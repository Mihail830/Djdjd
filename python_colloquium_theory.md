Конспект охватывает **все 72 вопроса занятий 2–6**. Нумерация соответствует программе коллоквиума. В каждом пункте разобраны определения, механизм работы, примеры с результатами и характерные ошибки. Для устного ответа полезно сначала сформулировать определение своими словами, затем объяснить ход выполнения примера и только после этого переходить к ограничениям и особым случаям.

**Версия языка:** примеры используют возможности Python 3.10 и новее; именно в 3.10 появилась конструкция `match`–`case`. Примеры выполнялись на CPython 3.12.3. **Как запускать примеры:** каждый блок `python` — самостоятельная программа. Его можно сохранить в отдельном `.py`-файле или запустить в редакторе. ## 1. Python как компилируемый и интерпретируемый язык

**Компиляция** — перевод программы в другое представление до его выполнения. **Интерпретация** — выполнение программы с помощью другой программы, интерпретатора. Эти понятия не являются взаимоисключающими характеристиками языка: конкретная реализация может сочетать оба подхода. Поэтому утверждение «Python только интерпретируется и никогда не компилируется» неточно.

В наиболее распространённой реализации **CPython** исходный текст сначала разбирается и компилируется в объект кода, содержащий байт-код. Затем этот код исполняет виртуальная машина интерпретатора. Байт-код — не машинные инструкции процессора; это внутренние инструкции конкретной реализации Python. Детали байт-кода могут меняться между версиями. Другие реализации Python вправе выполнять программу иначе, например применять JIT-компиляцию.

Обычная последовательность работы: сохранить текст в файле с расширением `.py`, затем передать файл интерпретатору. Команды оболочки, а не код внутри Python-файла:

```text
python hello.py
python3 hello.py
```

Какое имя команды доступно, зависит от установки. В интерактивном режиме введённые выражения могут автоматически показывать результат. В файле для вывода обычно нужен `print()`: отдельное выражение `2 + 3` вычисляется, но само ничего не печатает.

Встроенная функция `compile()` позволяет наглядно разделить этапы компиляции и выполнения:

```python
source = 'print("Привет, Python!")'
program = compile(source, "example.py", "exec")
print(type(program).__name__)
exec(program)
# Вывод:
# code
# Привет, Python!
```

Сначала создаётся объект кода. В этот момент строка «Привет» ещё не печатается. Вызов `exec()` выполняет подготовленную программу. Здесь исходный текст задан нами; выполнять через `exec()` произвольные недоверенные строки нельзя.

**Синтаксическая ошибка** мешает подготовить весь соответствующий блок к выполнению. **Ошибка времени выполнения** появляется при исполнении конкретной операции: синтаксически допустимое деление на ноль всё равно невозможно.

```python
try:
    compile("if True print(1)", "bad.py", "exec")
except SyntaxError as error:
    print(type(error).__name__)

try:
    exec(compile("print(10 / 0)", "division.py", "exec"))
except ZeroDivisionError as error:
    print(type(error).__name__)
# Вывод:
# SyntaxError
# ZeroDivisionError
```

При импорте модулей CPython может сохранять скомпилированный код в файлах `.pyc` в каталоге `__pycache__`. Это кеш, а не обязательный результат запуска каждого `.py`-файла; главный исполняемый файл обычно таким способом не кешируется. Пригодность кеша проверяется интерпретатором. `.pyc` не следует считать универсальным исполняемым файлом, независимым от версии Python.

**На коллоквиуме.** Хороший ответ описывает оба этапа CPython и отличает язык от его реализации. Типичная ошибка — называть байт-код машинным кодом процессора либо считать, что каждая строка большого файла разбирается только непосредственно перед её выполнением.

## 2. Физические и логические строки

**Физическая строка** — строка исходного текста, заканчивающаяся переводом строки. **Логическая строка** — единица исходного кода, воспринимаемая синтаксическим анализатором как завершённая строка программы. Одна логическая строка может занимать несколько физических. И наоборот: в одной физической строке можно записать несколько простых инструкций, разделённых точкой с запятой.

Рекомендуемый способ продолжения — **неявное объединение** внутри круглых, квадратных или фигурных скобок. Пока скобка не закрыта, перевод строки не завершает конструкцию. Это удобно для длинных вычислений, вызовов функций и литералов коллекций. Внутри таких скобок можно оставлять комментарии.

```python
total = (
    10
    + 20  # промежуточное слагаемое
    + 30
)
values = [
    1,
    2,
    3,
]
print(total, values)
# Вывод:
# 60 [1, 2, 3]
```

Присваивание `total` записано на пяти физических строках, но составляет одну логическую строку. Дополнительный отступ внутри скобок делает код читаемым; сам по себе он не создаёт тело `if` или цикла. Завершающая запятая в многострочном списке допустима и упрощает добавление новых элементов.

**Явное продолжение** записывается обратной косой чертой непосредственно перед переводом строки. После неё нельзя дописывать комментарий или пробелы: символ должен действительно соединять строки. Скобки обычно удобнее и надёжнее.

```python
total = 10 + \
    20
x = 2; y = 3; result = x + y
print(total)
print(result)
# Вывод:
# 30
# 5
```

Вторая физическая строка с присваиваниями содержит три простые инструкции в одной логической строке. Точка с запятой разрешена, но в обычном стиле каждую инструкцию размещают отдельно: так легче читать программу и искать ошибки. Составную инструкцию вроде нового `if` нельзя произвольно поставить после точки с запятой.

Тройные кавычки позволяют одному **строковому литералу** содержать переводы строк. Это не то же самое, что разбить арифметическое выражение на несколько физических строк: в первом случае переводы могут входить в значение строки, во втором они нужны только для оформления исходника. Подробности строковых литералов рассматриваются в занятии 5.

**На коллоквиуме.** Нужно объяснить не просто «строка — это текст до Enter», а разницу между текстовой строкой файла и синтаксически завершённой конструкцией. Типичная ошибка — переносить длинное выражение после `+` без скобок или обратной косой черты.

## 3. Выражения, инструкции, простые и составные инструкции. Отступы

**Выражение** вычисляется и даёт значение: `2 + 3`, `name.upper()`, `x > 0`. **Инструкция** задаёт действие программы: присваивание, условие, цикл, импорт, возврат из функции. Выражение может использоваться внутри инструкции. Вызов функции является выражением даже тогда, когда его основное назначение — побочный эффект, например печать. Значение `print()` — `None`.

**Простая инструкция** не содержит собственного набора вложенных инструкций: например, присваивание, `break`, `continue`, `pass`. **Составная инструкция** организует выполнение блоков: `if`, `while`, `for`, а также рассматриваемые позднее `def`, `try`, `match`. Она обычно имеет заголовок, завершающийся двоеточием, и тело.

```python
x = 2 + 3
result = print(x)
print(result)
if x > 0:
    print("положительное")
    print(x * 2)
print("конец")
# Вывод:
# 5
# None
# положительное
# 10
# конец
```

Справа от `=` сначала вычисляется выражение, затем имя связывается с его результатом. В строке `result = print(x)` сначала печатается `5`, затем имя `result` получает `None`. В условии `if` вычисляется `x > 0`. Две следующие строки принадлежат телу благодаря одинаковому увеличенному отступу. Последняя строка уже находится вне условия.

**Отступы в Python имеют синтаксическое значение.** Они определяют вложенность, а не просто украшают текст. Рекомендованный отступ — четыре пробела на уровень. Нельзя бессистемно смешивать табуляцию и пробелы. Возврат к меньшему отступу должен соответствовать ранее открытому уровню. У ветвей одного `if` заголовки `if`, `elif`, `else` выравниваются друг под другом.

```python
for number in [1, 2]:
    if number == 1:
        print("внутри if")
    print("внутри for", number)
print("вне for")
# Вывод:
# внутри if
# внутри for 1
# внутри for 2
# вне for
```

Первый `print` вложен и в цикл, и в условие. Второй — только в цикл, поэтому выполняется дважды. Третий выполняется один раз после завершения цикла. Чтобы разобраться в программе, полезно сначала выделить уровни вложенности и только потом вычислять значения.

Иногда тело пока нечем заполнить. Тогда используют `pass` — инструкцию, которая ничего не делает. Просто оставить заголовок с двоеточием без тела нельзя. Однострочная форма `if x: print(x)` допустима для простых тел, но многострочная запись лучше показывает структуру.

**Типичные ошибки:** забытое двоеточие, одинаковый отступ у заголовка и тела, случайное помещение завершающего действия внутрь цикла. Важно различать `IndentationError` как синтаксическую проблему и логически неверный, но синтаксически допустимый отступ: во втором случае программа запускается и делает не то, что задумано.

<a id="topic-4"></a>

## 4. Токены и правила именования идентификаторов

**Токены** — значимые единицы, на которые разбивается исходный текст перед синтаксическим анализом. Основные группы: идентификаторы, ключевые слова, литералы, операторы и разделители. Например, в `total = price + 10` имена `total` и `price` — идентификаторы, `10` — числовой литерал, `+` — арифметический оператор, `=` — знак присваивания. В формальном лексическом описании Python `=` относится к разделителям, хотя в учебном объяснении его часто называют оператором присваивания.

**Идентификатор** — имя переменной, функции, класса или другого именованного объекта. Допускаются буквы Unicode, знак подчёркивания и цифры, но цифра не может быть первым символом. Имена чувствительны к регистру: `count` и `Count` различны. Пробелы и дефис внутрь имени не входят: `total-price` читается как вычитание двух выражений. Для начинающего безопасное соглашение — латинские буквы, цифры и `_`.

```python
count = 3
Count = 8
student_name = "Анна"
номер = 5
print(count, Count)
print(student_name, номер)
print("student_name".isidentifier())
print("2students".isidentifier())
# Вывод:
# 3 8
# Анна 5
# True
# False
```

`isidentifier()` проверяет форму строки как идентификатора, но не запрещённость ключевого слова. Ключевые слова вроде `if`, `for`, `while`, `True`, `None` зарезервированы грамматикой и не могут служить обычными именами. Есть и **мягкие ключевые слова**, специальное значение которых зависит от контекста: например, `match` и `case` в конструкции сопоставления с образцом.

```python
import keyword
print("for".isidentifier())
print(keyword.iskeyword("for"))
print(keyword.iskeyword("list"))
print(keyword.issoftkeyword("match"))
print(keyword.iskeyword("match"))
# Вывод:
# True
# True
# False
# True
# False
```

**Литерал** задаёт значение непосредственно в исходнике: `12`, `2.5`, `"текст"`. В учебной речи `True`, `False`, `None` тоже часто называют литеральными значениями, но лексически это ключевые слова. Записи списков и словарей в квадратных/фигурных скобках также часто называют литералами коллекций; формально они являются конструкциями создания контейнеров.

**Операторы** задают действия: `+`, `*`, `==`, `and`. **Разделители** оформляют синтаксис: скобки, запятые, двоеточия, точки. Символ `#` начинает комментарий вне строки. Содержимое комментария не исполняется.

**Соглашения об именах:** переменные и функции — `snake_case`, классы — `CapWords`, константы — `UPPER_SNAKE_CASE`. Константа в данном случае является договорённостью: Python не запрещает переприсвоить такое имя. Не стоит называть переменные `list`, `str`, `sum`, `int`: это не синтаксическая ошибка, но так можно скрыть нужный встроенный объект. Осмысленное `student_count` обычно лучше неопределённого `a`, кроме коротких математических примеров.

**На коллоквиуме.** Нужно различать «имя допустимо синтаксически» и «имя хорошо выбрано». `a1` допустимо, но `final_exam_score` лучше объясняет назначение. Встроенное имя не обязательно является ключевым словом.

## 5. Характеристики объекта. `type()`, `id()`, `==` и `is`

Каждый объект имеет **тип**, **значение** и **идентичность**. Тип определяет поддерживаемые операции и способ интерпретации данных. Значение описывает содержимое. Идентичность отличает данный объект от других объектов, в том числе с равным содержимым.

`type(obj)` возвращает тип объекта. `id(obj)` возвращает целое число, представляющее его идентичность: оно постоянно во время жизни объекта и различается у одновременно существующих разных объектов. В CPython это обычно адрес в памяти, но язык не требует такого устройства. После уничтожения объекта число может быть повторно использовано. Конкретные значения `id()` между запусками не предсказывают.

```python
first = [1, 2]
second = [1, 2]
alias = first
print(type(first).__name__)
print(first == second)
print(first is second)
print(first is alias)
print(id(first) == id(alias))
# Вывод:
# list
# True
# False
# True
# True
```

Оператор `==` проверяет **равенство значений по правилам типов**, а `is` — **один ли это объект**. Два списка содержат одинаковые элементы, но созданы отдельно. `alias` не создаёт третий список: это ещё одно имя первого. Значение объекта получают, обращаясь к нему и выполняя подходящие операции; универсальной функции `value()` для «извлечения значения любого объекта» нет.

`isinstance(obj, Type)` полезна для проверки принадлежности типу с учётом наследования. В отличие от неё, `type(obj) is Type` проверяет точное совпадение типа. Размер через `sys.getsizeof()` — отдельная характеристика реализации, а не «значение» объекта; для контейнера он не равен размеру всех вложенных объектов.

```python
value = True
print(type(value) is bool)
print(type(value) is int)
print(isinstance(value, int))
missing = None
print(missing is None)
print([] == [])
print([] is [])
# Вывод:
# True
# False
# True
# True
# True
# False
```

`bool` является подтипом `int`, поэтому третья проверка истинна. Для сравнения с `None` обычный стиль — `is None` и `is not None`: нас интересует специальный единственный объект. Для чисел и строк нужен `==`, а не `is`.

**Типичная ловушка:** небольшие числа и некоторые строки реализация может повторно использовать. Случайное `a is b == True` для равных чисел не делает `is` заменой `==`. Кеширование — деталь реализации, не правило сравнения значений. На вопрос «равны ли два списка?» и «один ли это список?» могут быть разные ответы.

## 6. Изменяемые и неизменяемые типы

**Изменяемый объект** позволяет изменить собственное содержимое, сохранив идентичность. **Неизменяемый объект** после создания не допускает изменения своего значения. К изменяемым встроенным типам относятся `list`, `dict`, `set`, `bytearray`. К неизменяемым — `int`, `float`, `bool`, `complex`, `str`, `tuple`, `bytes`, `frozenset`, `range`, а также объект `None`.

Изменяемость относится к **объекту**, а не к имени. Имя можно перепривязать и к другому числу, и к другому списку. Это самостоятельная операция, не доказывающая изменяемости прежнего объекта.

```python
numbers = [1, 2]
alias = numbers
numbers.append(3)
print(numbers)
print(alias)
print(numbers is alias)

number = 10
old_number = number
number = number + 1
print(number, old_number)
print(number == old_number)
# Вывод:
# [1, 2, 3]
# [1, 2, 3]
# True
# 11 10
# False
```

`append()` изменяет уже существующий список, и оба имени видят новое содержимое. Сложение чисел вычисляет значение `11`, затем `number` связывается с результатом. Прежнее число `10` не превратилось в `11`: оно по-прежнему доступно через `old_number`.

Неизменяемость контейнера не обязательно означает неизменяемость всех достижимых через него объектов. Кортеж фиксирует набор ссылок, но среди его элементов может быть изменяемый список.

```python
record = ([1, 2], "данные")
record[0].append(3)
print(record)
try:
    record[1] = "новые данные"
except TypeError as error:
    print(type(error).__name__)
# Вывод:
# ([1, 2, 3], 'данные')
# TypeError
```

В первом действии не заменяется элемент кортежа: изменяется список, на который этот элемент ссылается. Во втором предпринимается запрещённая замена ссылки внутри кортежа.

**Почему это важно:** изменяемые объекты могут быть общими для нескольких имён или контейнеров. Ошибка часто возникает, когда программист считает присваивание копированием. Неизменяемость также связана с хешируемостью, но не равна ей: кортеж с вложенным списком неизменяем как контейнер, однако нехешируем. Для собственных классов правила ещё гибче, поэтому универсальное утверждение «любой изменяемый объект нехешируем» неверно.

**На коллоквиуме.** Определение должно говорить об изменении содержимого при сохранении идентичности. Фраза «неизменяемую переменную нельзя переприсвоить» неверна для обычных имён Python.

## 7. Присваивание: привязка имени и перепривязка

В инструкции `name = expression` сначала вычисляется правая часть, после чего имя слева связывается с полученным объектом. Если имя уже существовало, возникает новая привязка. Нельзя представлять присваивание как обязательное копирование всех данных в отдельную «коробку переменной».

Имя не имеет навсегда закреплённого типа. Тип имеет объект, на который оно в данный момент ссылается. Поэтому одно имя может сначала обозначать число, затем строку. Такая динамичность разрешена, хотя беспричинная смена смысла имени ухудшает читаемость.

```python
value = 10
print(type(value).__name__, value)
value = "десять"
print(type(value).__name__, value)

first = [1]
second = first
second.append(2)
second = [9]
print(first)
print(second)
# Вывод:
# int 10
# str десять
# [1, 2]
# [9]
```

Сначала `second` — ещё одна ссылка на список `first`, поэтому добавление видно через оба имени. После `second = [9]` создаётся другой список и перепривязывается только имя `second`. Список `[1, 2]` не меняется и остаётся доступным через `first`.

Присваивание не является уравнением и не требует предварительного объявления переменной. Запись `x = x + 1` использует старое значение справа и затем меняет привязку слева. Если имя справа ещё не определено, возникает `NameError`.

```python
x = 4
x = x + 1
print(x)
a = [10]
b = a
del a
print(b)
try:
    print(a)
except NameError as error:
    print(type(error).__name__)
# Вывод:
# 5
# [10]
# NameError
```

`del a` удаляет имя в данном пространстве имён, а не обязательно уничтожает объект. Пока существует `b`, список достижим. Когда ненужный объект перестаёт быть достижимым, его память может быть освобождена механизмами реализации; полагаться на точный момент освобождения в общем случае нельзя.

В простой форме слева стоит имя. В расширенных формах возможны элементы контейнеров, атрибуты и распаковка. При `items[0] = value` меняется элемент существующего контейнера, а не привязка имени `items`. Различие особенно важно для понимания списков и кортежей.

**Типичная ошибка:** ожидать, что после `b = a` последующие изменения списка `b` не затронут `a`. Если нужна независимость, выбирают подходящий вид копирования. Поверхностное и глубокое копирование подробно рассматриваются в пункте 36.

## 8. Ветвление `if` / `elif` / `else`

Условная инструкция выбирает блок по истинности выражений. Сначала проверяется условие `if`. Если оно истинно, выполняется его тело, а остальные ветви этой конструкции пропускаются. Иначе последовательно проверяются `elif`. Если ни одно условие не истинно, выполняется `else`, если он есть.

В одной конструкции выполняется **не более одной ветви**. `elif` может быть несколько, `else` — не более одного, в конце. У `else` нет собственного условия. Если `else` отсутствует и все условия ложны, вся конструкция ничего не делает.

```python
score = 75
if score >= 90:
    grade = "отлично"
elif score >= 70:
    grade = "хорошо"
elif score >= 50:
    grade = "удовлетворительно"
else:
    grade = "не зачтено"
print(grade)
# Вывод:
# хорошо
```

Порядок проверок важен. Если первым поставить `score >= 50`, оценка `75` попадёт в эту ветвь и более строгие проверки уже не выполнятся. Отдельные инструкции `if` отличаются от цепочки `if`–`elif`: в нескольких независимых `if` могут выполниться сразу несколько тел.

В условии допустим не только объект `bool`. Python проверяет истинность значения. Ложными считаются `False`, `None`, числовой ноль, пустые строки и пустые контейнеры. Непустая строка `"False"` истинна: её текст не превращается автоматически в логическое значение.

```python
values = [0, "", [], "False", [0]]
for value in values:
    if value:
        print(repr(value), "истинно")
    else:
        print(repr(value), "ложно")
# Вывод:
# 0 ложно
# '' ложно
# [] ложно
# 'False' истинно
# [0] истинно
```

У списка `[0]` один элемент, поэтому список непустой и истинный, хотя сам элемент `0` ложен. Это различие полезно при проверке наличия данных. Для проверки именно отсутствия значения используйте `value is None`, если `0` и пустая строка допустимы как реальные данные.

Условное выражение `a if condition else b` тоже существует, но это **выражение**, возвращающее значение, а не полная замена многострочного ветвления. Например, `label = "да" if enabled else "нет"`. Использовать его удобно для короткого выбора значения, а не для сложной логики с побочными действиями.

**Типичные ошибки:** `=` вместо `==`, пропущенное двоеточие, неверная последовательность перекрывающихся условий, использование `if x == True` вместо содержательного `if x`. Последнее проверяет равенство конкретному значению, а не общую истинность и может менять смысл для объектов других типов.

## 9. Цикл `while`. Бесконечный цикл

Цикл `while` повторяет тело, пока условие истинно. Условие проверяется **до каждого выполнения тела**, поэтому цикл может не выполниться ни разу. Если тело изменяет данные, используемые условием, при следующей проверке учитываются уже новые значения.

Для понимания цикла удобно выделять три части: начальное состояние, условие продолжения и изменение состояния. Если последнее не обеспечивает продвижения к завершению, легко получить бесконечное повторение.

```python
number = 1
total = 0
while number <= 4:
    total += number
    number += 1
print(total)
print(number)
# Вывод:
# 10
# 5
```

Первый проход добавляет `1`, затем число становится `2`; следующие проходы добавляют `2`, `3` и `4`. После последнего увеличения `number` равно `5`, условие ложно, цикл завершается. Текущее значение счётчика после цикла — первое значение, на котором проверка не прошла, а не последнее обработанное число.

Бесконечный цикл намеренно задают через `while True`, если выход определяется не исходным условием, а событием внутри тела. Обычно выход осуществляют через `break`, возврат из функции или исключение. Следующий пример безопасно заканчивается благодаря `break`:

```python
attempt = 0
while True:
    attempt += 1
    print("попытка", attempt)
    if attempt == 3:
        break
print("завершено")
# Вывод:
# попытка 1
# попытка 2
# попытка 3
# завершено
```

В реальной программе так может работать обработка команд или повторение запроса до успеха. Но бесконечное повторение без ожидания и полезной работы может загрузить процессор. В учебных примерах с `input()` нужно отдельно предусматривать команду выхода и обработку неверного ввода.

**Частые ошибки:** забытое увеличение счётчика, увеличение в неправильной ветви, неверный знак сравнения, случайное изменение другой переменной. Особенно опасно поставить изменение счётчика после `continue`: при некоторых состояниях выполнение до него больше не дойдёт.

**Вопрос коллоквиума:** сколько раз выполнится `while False`? Ноль. Выполнится ли тело `while True` обязательно хотя бы раз? Если программа действительно дошла до заголовка и проверка не прервана внешними событиями, да. Сам цикл не имеет встроенного обязательного конечного числа повторений.

## 10. Цикл `for`, объект `range`, различия `for` и `while`

Цикл `for` последовательно получает элементы из **итерируемого объекта**. Это не обязательно числа: можно перебирать символы строки, элементы списка, ключи словаря. На каждой итерации очередной элемент присваивается переменной цикла. Когда источник исчерпан, цикл завершается.

В отличие от ряда других языков, `for` в Python не означает инструкцию вида «начальное значение; условие; изменение». Если нужен числовой ряд, источником служит объект `range`.

`range(stop)` задаёт целые числа от нуля до `stop`, не включая `stop`. `range(start, stop)` задаёт начало явно. `range(start, stop, step)` добавляет шаг; по умолчанию он равен `1`. Шаг может быть отрицательным, но не нулевым. Аргументы должны поддерживать целочисленную интерпретацию, обычный `float` не подходит.

```python
print(list(range(4)))
print(list(range(2, 7)))
print(list(range(7, 1, -2)))
print(list(range(3, 1)))
for letter in "кот":
    print(letter)
# Вывод:
# [0, 1, 2, 3]
# [2, 3, 4, 5, 6]
# [7, 5, 3]
# []
# к
# о
# т
```

Правая граница всегда исключена, включая отрицательный шаг. Диапазон `range(3, 1)` пуст: шаг положительный, а начальная точка уже правее конечной. Направление не выбирается автоматически.

**`range` не является готовым списком всех чисел.** Это неизменяемая последовательность, которая компактно хранит параметры арифметической прогрессии и предоставляет элементы при обращении. Объём памяти не растёт пропорционально числу описанных элементов. Вызов `list(range(...))`, напротив, материализует список, что на большом диапазоне требует памяти.

```python
total = 0
for number in range(1, 5):
    total += number
print(total)

number = 1
other_total = 0
while number < 5:
    other_total += number
    number += 1
print(other_total)

for number in range(3):
    number = 100
    print(number)
# Вывод:
# 10
# 10
# 100
# 100
# 100
```

Первые два фрагмента вычисляют одинаковую сумму. В `for` получение следующего элемента организовано самим циклом; в `while` программист вручную поддерживает счётчик. Последний цикл показывает, что присваивание `number = 100` не меняет источник `range(3)`: на следующем проходе переменная снова получает следующий элемент источника, после чего тело снова связывает её со `100`.

**Когда что выбирать:** `for` естественен для обхода элементов и известной последовательности повторений; `while` — для повторения до достижения условия, число шагов которого заранее не определяется. Это рекомендация по ясности, а не запрет выражать одну задачу разными способами.

**Типичные ошибки:** ожидать включения `stop`, передавать `range(0, 1, 0.1)`, менять коллекцию при обходе без понимания последствий, предполагать, что переменная цикла обязательно существует после пустого цикла. Если до цикла имя не было связано и итераций не было, обращаться к нему нельзя.

<a id="topic-11"></a>

## 11. `break`, `continue`, `else` в циклах и вложенные циклы

**`break`** немедленно завершает ближайший охватывающий цикл. **`continue`** прекращает текущую итерацию ближайшего цикла и переходит к следующей: у `while` заново проверяется условие, у `for` запрашивается следующий элемент. Эти инструкции не завершают все вложенные циклы автоматически.

У циклов может быть блок **`else`**. Он выполняется при нормальном завершении цикла: источник `for` исчерпан либо условие `while` стало ложным. Если цикл был завершён через `break`, его `else` пропускается. Если выполнение ушло через `return` или исключение, это тоже не обычное завершение с переходом в `else`.

```python
numbers = [1, 3, 5]
for number in numbers:
    if number % 2 == 0:
        print("найдено", number)
        break
else:
    print("чётных нет")

for number in range(6):
    if number % 2 == 0:
        continue
    if number > 3:
        break
    print(number)
else:
    print("нормальное завершение")
# Вывод:
# чётных нет
# 1
# 3
```

Первый цикл не встречает чётного числа, не выполняет `break` и доходит до `else`. Во втором пропускаются `0`, `2`, `4`, печатаются `1`, `3`, а на `5` срабатывает `break`. Поэтому строка «нормальное завершение» не появляется. `continue` сам по себе не запрещает будущий `else`.

Блок `else` относится к циклу, если выровнен с его заголовком, а не с вложенным `if`. Он выполняется даже при нуле итераций, поскольку раннего выхода `break` не произошло.

```python
for outer in range(2):
    for inner in range(3):
        if inner == 1:
            break
        print(outer, inner)
    else:
        print("внутренний цикл без break")
else:
    print("внешний цикл завершён")

counter = 0
while counter < 0:
    counter += 1
else:
    print("while: ноль итераций")
# Вывод:
# 0 0
# 1 0
# внешний цикл завершён
# while: ноль итераций
```

Внутренний `break` дважды останавливает только внутренний цикл. Внешний продолжает работу, завершается обычным образом и выполняет собственный `else`. У внутреннего цикла его `else` не выполняется ни разу.

Если нужно выйти из нескольких уровней, можно использовать дополнительный флаг с проверкой во внешнем цикле, вынести поиск в функцию и применить `return` либо изменить структуру алгоритма. Просто поставить `break` во внутреннее тело недостаточно.

**Типичная ловушка `while`:** если счётчик увеличивается в конце тела, а до увеличения выполняется `continue`, одно и то же состояние может повторяться бесконечно. Исправление — обеспечить продвижение до возможного `continue` или иначе перестроить условие.

**На коллоквиуме.** Для прогнозирования вывода отдельно проследите, какой цикл завершает каждый `break`, к какому заголовку относится каждый `else` и какие действия пропускает `continue`. Фраза «`else` выполняется, если цикл не запускался» неполна: он также выполняется после любого нормального завершения без `break`.

# Занятие 3. Числовые типы данных

## 12. Целые числа: литералы, `int()`, системы счисления, диапазон

Тип **`int`** представляет целые числа: отрицательные, ноль и положительные. Целочисленные литералы можно записывать в десятичной системе без префикса, в двоичной с `0b`, восьмеричной с `0o`, шестнадцатеричной с `0x`. Подчёркивания внутри корректной записи помогают группировать разряды и не меняют значение. Знак минус формально является отдельным унарным оператором, применяемым к числовому литералу.

Число не «хранится как шестнадцатеричное» только потому, что создано через `0x`. Система записи исходника и математическое значение — разные вещи. Обычный `print()` показывает целое десятичной записью; `bin()`, `oct()`, `hex()` возвращают строки в других системах.

```python
print(42, 0b101010, 0o52, 0x2A)
print(1_000_000)
print(bin(42), oct(42), hex(42))
print(type(0x2A).__name__)
# Вывод:
# 42 42 42 42
# 1000000
# 0b101010 0o52 0x2a
# int
```

**`int` — встроенный тип**, а его вызов создаёт или получает целочисленное значение. `int()` без аргумента даёт `0`. Строки, байтовые строки и `bytearray` с допустимой записью числа можно преобразовать с указанием основания. По умолчанию основание равно `10`; допустимы основания от `2` до `36` и специальное `0`, означающее определение основания по префиксу. При явном основании требуется текстовая/байтовая запись, а не произвольное число.

```python
print(int(), int(True), int(False))
print(int("  -42  "))
print(int("1010", 2), int("ff", 16), int("z", 36))
print(int("0xff", 0))
print(int(3.9), int(-3.9))
for text in ["3.9", "12x"]:
    try:
        print(int(text))
    except ValueError as error:
        print(type(error).__name__)
# Вывод:
# 0 1 0
# -42
# 10 255 35
# 255
# 3 -3
# ValueError
# ValueError
```

При преобразовании конечного `float` функция `int()` **отбрасывает дробную часть к нулю**, а не округляет к ближайшему и не выполняет округление вниз для отрицательных чисел. Строка `"3.9"` не является целочисленной записью; при необходимости сначала разбирают число другим способом, понимая последствия точности. Числа `inf` и `nan` в `int` не преобразуются обычным образом: возникают исключения.

У `int` нет фиксированного математического диапазона вроде «только от −2³¹ до 2³¹−1». Разрядность растёт по мере необходимости, ограничиваясь ресурсами памяти и вычислительным временем. Например, `2 ** 100` — обычное целое. Это не означает, что можно без затрат создать число любого размера. В некоторых версиях и настройках CPython существуют дополнительные защитные ограничения на преобразование очень длинных десятичных строк в целые и обратно; они не превращают `int` в 32- или 64-битный тип.

**Типичные ошибки:** путать `int("11", 2)` и `int(11)`, считать `int(-3.9)` равным `-4`, писать десятичные литералы с лишним ведущим нулём вроде `012`. Для восьмеричной записи нужен префикс `0o`.

<a id="topic-13"></a>

## 13. Числа с плавающей точкой: `float`, диапазон и точность

Тип **`float`** предназначен для приближённого представления вещественных чисел. Литералы содержат точку или экспоненциальную запись: `3.14`, `.5`, `5.`, `1e3`, `2.5e-4`. Буква `e` означает умножение на степень десяти, а не математическую константу e. Десятичный разделитель в программе — точка, не запятая.

В обычной современной CPython `float` соответствует IEEE 754 binary64: 64 бита хранения, 53 значащих двоичных разряда, примерно 15–17 значащих десятичных цифр. Эти цифры относятся к **общей значащей точности**, а не к числу знаков после точки. Для числа огромного порядка шаг между соседними значениями тоже велик.

```python
print(3.14, .5, 5., 1e3, 2.5e-4)
print(float(), float(7), float("  -2.5e2  "))
print(type(1e3).__name__)
print(float(2**53) == float(2**53 + 1))
# Вывод:
# 3.14 0.5 5.0 1000.0 0.00025
# 0.0 7.0 -250.0
# float
# True
```

Последняя строка показывает потерю различимости соседних целых: оба значения преобразуются в один и тот же `float`. При этом исходные объекты `int` различны по значению. Утверждение «все целые точно представляются во `float`» неверно.

`float()` принимает числа и корректные строковые/байтовые записи, в том числе формы бесконечности и NaN. Строка `"1,5"` не преобразуется: запятая не признаётся десятичным разделителем. Конкретные характеристики платформы доступны через `sys.float_info`.

```python
import sys
print(sys.float_info.mant_dig)
print(sys.float_info.max > 1e308)
print(float("1e309"))
print(float("1e-4000"))
try:
    float("1,5")
except ValueError as error:
    print(type(error).__name__)
# Вывод в стандартной binary64-среде:
# 53
# True
# inf
# 0.0
# ValueError
```

Максимальное конечное значение binary64 приблизительно `1.7976931348623157 × 10³⁰⁸`. Минимальное положительное **нормализованное** — около `2.2250738585072014 × 10⁻³⁰⁸`. Есть ещё меньшие положительные субнормальные значения, вплоть до приблизительно `4.94 × 10⁻³²⁴`, но с уменьшенной относительной точностью. Слишком малые по модулю величины могут округлиться до нуля. При переполнении в зависимости от операции возникает `inf` или исключение: нельзя обещать один вариант для всех операций.

**На коллоквиуме.** Важно назвать ограниченность диапазона и точности отдельно. Два близких числа могут не различаться задолго до переполнения. Форматирование до двух знаков делает вывод короче, но не превращает внутреннее двоичное значение в точную десятичную дробь.

<a id="topic-14"></a>

## 14. Специальные значения `+inf`, `-inf`, `nan`

**`inf`** и **`-inf`** представляют положительную и отрицательную бесконечность. **`nan`** — «не число», специальный результат, обозначающий неопределённое или недопустимое числовое значение. Это значения типа `float`, а не отдельные встроенные типы. Их можно получить через `float("inf")`, `float("-inf")`, `float("nan")`, а также через константы модуля `math`.

Бесконечность больше любого конечного числа соответствующего направления. Однако арифметику с ней нельзя понимать как обычную арифметику с огромным конечным числом. Например, `inf - inf` не равно нулю: это неопределённость, представленная `nan`.

```python
import math
positive = float("inf")
negative = float("-inf")
not_a_number = float("nan")
print(positive > 10**1000)
print(negative < -10**1000)
print(positive + 10)
print(positive - positive)
print(math.isinf(positive), math.isnan(not_a_number))
print(math.isfinite(3.5), math.isfinite(positive))
# Вывод:
# True
# True
# inf
# nan
# True True
# True False
```

`math.isfinite(x)` проверяет, что число не бесконечно и не NaN. Эта проверка полезна перед обработкой результатов численного алгоритма. Текст `"inf"` сам по себе — строка, а `float("inf")` — числовое значение.

Главная особенность NaN: **он не равен даже самому себе**. Сравнения `<`, `<=`, `>`, `>=` с NaN тоже ложны, а `!=` истинно. Для проверки используют `math.isnan()`, а не `x == float("nan")`.

```python
import math
value = float("nan")
print(value == value)
print(value != value)
print(value < 0, value >= 0)
print(math.isnan(value))
print(bool(value), bool(float("inf")))
try:
    print(1.0 / 0.0)
except ZeroDivisionError as error:
    print(type(error).__name__)
# Вывод:
# False
# True
# False False
# True
# True True
# ZeroDivisionError
```

И NaN, и бесконечность логически истинны: они не являются числовым нулём. Деление обычного Python `float` на ноль вызывает исключение, а не автоматически возвращает бесконечность. Поведение библиотек для массивов может отличаться, но это не правило встроенных числовых операций Python.

**Типичные ошибки:** искать NaN обычным равенством, считать `nan` ложным, использовать бесконечность как «очень большое число» без учёта неопределённых операций. В сортировках и поиске экстремумов присутствие NaN также требует отдельной политики: обычный порядок вещественных чисел на него не распространяется.

## 15. Погрешности `float`, `math.isclose()`, `decimal.Decimal`

Дробь `0.1` не имеет конечного двоичного представления — подобно тому, как `1/3` не имеет конечной десятичной записи. При ограниченном количестве разрядов сохраняется ближайшее представимое значение. После вычисления результат снова может округляться. Поэтому запись знакомых десятичных дробей ещё не гарантирует точность арифметики с ними.

```python
value = 0.1 + 0.2
print(value)
print(value == 0.3)
print(format(0.1, ".17f"))
print(format(value, ".2f"))
# Вывод:
# 0.30000000000000004
# False
# 0.10000000000000001
# 0.30
```

Строка `"0.30"` — красивое отображение, а не исправление объекта `value`. Это фундаментальная особенность двоичной арифметики, не случайный дефект конкретного сложения.

**`math.isclose(a, b)`** проверяет близость чисел с относительным и абсолютным допусками. Для конечных значений используется критерий:

```text
|a − b| ≤ max(rel_tol × max(|a|, |b|), abs_tol)
```

`rel_tol` задаёт допуск относительно масштаба чисел, `abs_tol` — допустимую абсолютную разницу. По умолчанию они равны `1e-9` и `0.0`. Около нуля часто необходим именно ненулевой `abs_tol`: относительный допуск сам по себе не решает эту задачу. Допуск выбирают по смыслу задачи, точности исходных данных и накоплению ошибок, а не просто увеличивают до получения желаемого ответа.

```python
import math
print(math.isclose(0.1 + 0.2, 0.3))
print(math.isclose(1e-12, 0.0))
print(math.isclose(1e-12, 0.0, abs_tol=1e-10))
print(math.isclose(1000.0, 1000.5, rel_tol=0.001))
print(math.isclose(float("nan"), float("nan")))
# Вывод:
# True
# False
# True
# True
# False
```

Бесконечности близки только самим себе с тем же знаком, а NaN не близок ничему, включая другой NaN. Приближённое равенство также не следует бездумно использовать как обычное математическое отношение равенства: близость с допуском в общем случае не транзитивна.

**`decimal.Decimal`** предоставляет десятичную арифметику с настраиваемой точностью и правилами округления. Для точного ввода десятичных данных создавайте числа из строк, а не из предварительно созданных `float`.

```python
from decimal import Decimal, localcontext, ROUND_HALF_UP
print(Decimal("0.1") + Decimal("0.2") == Decimal("0.3"))
print(Decimal(0.1) == Decimal("0.1"))
print(Decimal("2.675").quantize(Decimal("0.01"), rounding=ROUND_HALF_UP))
with localcontext() as context:
    context.prec = 6
    print(Decimal(1) / Decimal(3))
# Вывод:
# True
# False
# 2.68
# 0.333333
```

`Decimal(0.1)` точно переносит уже имеющееся двоичное приближение, поэтому не совпадает с точной десятичной `Decimal("0.1")`. Контекст задаёт число значащих цифр арифметических результатов, а `quantize()` — нужный десятичный разряд округления. Даже `Decimal` не делает всякое деление точным: `1/3` остаётся бесконечной дробью. Денежные правила также нужно задать явно; сам выбор типа не определяет бухгалтерскую политику.

**На коллоквиуме.** Объясните причину погрешности, подход сравнения по допуску и отличие точного десятичного ввода от конвертации `float`. Фраза «нужно всегда применять `round()`» не является универсальным решением.

<a id="topic-16"></a>

## 16. `bool` как подтип `int`. Синглтоны. Хороший стиль

Тип **`bool`** имеет два значения: `True` и `False`. Это **синглтоны**: каждое значение представлено своим единственным объектом. В обычной работе логические результаты не нужно вручную конструировать или сравнивать по идентичности: условные выражения и сравнения уже возвращают нужное значение.

`bool` является подтипом `int`: `True` ведёт себя в арифметическом контексте как `1`, `False` — как `0`. Это позволяет, например, суммировать результаты проверок. Но логическое назначение типа сохраняется: использовать его как замаскированное обычное число без необходимости не стоит.

```python
print(isinstance(True, int))
print(type(True) is int)
print(True == 1, False == 0)
print(True + True, False * 100)
print(bool(5) is True)
print(bool(0) is False)
print(sum(number > 0 for number in [-2, 0, 3, 7]))
# Вывод:
# True
# False
# True True
# 2 0
# True
# True
# 2
```

`True + True` даёт целое `2`, а не третье логическое значение. Выражение-генератор в `sum()` создаёт последовательность проверок: две из них истинны, поэтому сумма равна двум.

`bool(value)` проверяет истинность объекта. Для чисел ложен ноль, для контейнеров — пустота. Непустой текст `"False"`, `"0"` или `"нет"` всё равно истинен. Если строка содержит пользовательский ответ, его нужно явно разобрать по правилам приложения.

```python
print(bool("False"), bool("0"), bool(""))
print(bool([]), bool([False]))
value = 2
print(bool(value))
print(value == True)
if value:
    print("значение истинно")
# Вывод:
# True True False
# False True
# True
# False
# значение истинно
```

Пример показывает, почему `if value == True` не равно `if value`: число `2` истинно, но не равно `1`. Хороший стиль для логической переменной — `if ready:` и `if not ready:`. Если требуется именно проверка объекта `None`, используйте `is None`, а не общую проверку ложности. Если API принципиально различает буквальное `True` и прочие значения, `value is True` может быть обоснован, но это отдельная задача, а не стандартная запись любого условия.

**Типичная ошибка:** считать `bool("False")` способом разбора текстового логического значения. Ещё одна — писать сравнение с `True`, когда требуется обычная проверка истинности. На коллоквиуме важно назвать и наследование от `int`, и различие точного типа `bool` с точным типом `int`.

## 17. Арифметические операции, `/`, `//`, `%`, отрицательные числа и типы

Для чисел доступны `+`, `-`, `*`, `/`, `//`, `%`, `**`, а также унарные `+` и `-`. Возведение в степень `**` имеет высокий приоритет и группируется справа: `2 ** 3 ** 2` означает `2 ** (3 ** 2)`. Скобки помогают явно задавать порядок.

**Истинное деление `/`** двух целых возвращает `float`, даже если остатка нет. **Деление с округлением вниз `//`** вычисляет частное, округлённое к минус бесконечности; для двух целых результат имеет тип `int`. Это не то же самое, что отбросить дробную часть к нулю. **Остаток `%`** связан с этим частным.

Для целых `a`, `b`, где `b ≠ 0`, выполняется:

```text
a = (a // b) × b + (a % b)
```

Остаток либо нулевой, либо имеет знак делителя; его модуль меньше модуля делителя.

```python
for a, b in [(7, 3), (-7, 3), (7, -3), (-7, -3)]:
    q = a // b
    r = a % b
    print(a, b, q, r, a == q * b + r)
print(6 / 3, type(6 / 3).__name__)
print(-7 // 3, int(-7 / 3))
# Вывод:
# 7 3 2 1 True
# -7 3 -3 2 True
# 7 -3 -3 -2 True
# -7 -3 2 -1 True
# 2.0 float
# -3 -2
```

Для `-7 // 3` точное частное около `-2.333`, поэтому округление вниз даёт `-3`. Чтобы восстановить `-7`, нужен остаток `2`: `(-3) × 3 + 2 = -7`. Запоминать правило «остаток всегда положительный» нельзя: при отрицательном делителе он отрицателен или равен нулю.

При смешивании обычных `int` и `float` арифметический результат обычно приводится к `float`; при участии `complex` базовая арифметика может перейти к комплексным числам. Но это не означает существования единого неявного преобразования любых типов: `"2" + 3` запрещено, как и обычное сложение `Decimal` с `float`.

```python
print(2 + 0.5, type(2 + 0.5).__name__)
print(7.0 // 2, type(7.0 // 2).__name__)
print(7.0 % 2)
print(2 ** 3 ** 2)
print(-2 ** 2, (-2) ** 2)
print(2 ** -1)
print(divmod(-7, 3))
# Вывод:
# 2.5 float
# 3.0 float
# 1.0
# 512
# -4 4
# 0.5
# (-3, 2)
```

`//` с участием `float` возвращает `float` с целочисленным значением, а не обязательно объект `int`. Для плавающей арифметики действуют погрешности, поэтому целочисленные тождества нельзя применять к ней без учёта округлений. `divmod(a, b)` возвращает пару из частного и остатка.

**Типичные ошибки:** заменять `//` выражением `int(a / b)` для отрицательных чисел, ожидать `int` от `/`, писать `^` для степени. В Python `^` означает побитовое исключающее ИЛИ, а не возведение в степень. Делитель `0` в `/`, `//` и `%` вызывает `ZeroDivisionError`.

## 18. Составное присваивание и неизменяемость чисел

**Составное, или расширенное, присваивание** объединяет операцию и присваивание: `+=`, `-=`, `*=`, `/=`, `//=`, `%=`, `**=` и другие формы. Для обычной числовой переменной `x += y` удобно читать как «вычислить сумму текущего `x` и `y`, затем связать `x` с результатом».

Числовые объекты неизменяемы. Поэтому `x += 1` не меняет значение уже существующего объекта числа. Имена, которые ссылались на прежнее число, продолжают обозначать прежнее значение. При этом реализация может переиспользовать уже существующие неизменяемые объекты; нельзя обещать, что любая операция физически выделяет новый участок памяти.

```python
x = 10
other = x
x += 5
print(x, other)
print(x is other)
x /= 3
print(x, type(x).__name__)
# Вывод:
# 15 10
# False
# 5.0 float
```

После `x /= 3` тип результата — `float`, поскольку `/` выполняет истинное деление. Составное присваивание не обязано сохранять прежний тип. Если в алгоритме важны целые числа, вид операции выбирают по математическому смыслу, а не по краткости записи.

У изменяемых типов расширенное присваивание может изменить исходный объект **на месте**. Поэтому в общем случае `x += y` не следует считать полностью равнозначным переписыванию `x = x + y`: возможны специальные методы и различие в числе вычислений левой части.

```python
numbers = [1]
alias = numbers
numbers += [2]
print(numbers, alias, numbers is alias)

numbers = [1]
alias = numbers
numbers = numbers + [2]
print(numbers, alias, numbers is alias)
# Вывод:
# [1, 2] [1, 2] True
# [1, 2] [1] False
```

Первый фрагмент расширяет список, второй создаёт результат конкатенации и перепривязывает имя. Это различие объясняется типом объекта, а не другим смыслом символа `=`. Для индексируемой или атрибутной левой части расширенное присваивание также вычисляет целевой объект только один раз; механическое разворачивание может изменить побочные эффекты.

**На коллоквиуме.** Если спрашивают про числа, подчеркните неизменяемость и перепривязку. Если предлагают сравнить поведение со списком, учитывайте изменение на месте. Утверждение «`+=` всегда изменяет объект» неверно, как и «`+=` всегда создаёт независимую копию».

## 19. Сравнения и цепочки сравнений

Основные операции сравнения: `==`, `!=`, `<`, `<=`, `>`, `>=`. Они проверяют равенство, неравенство и порядок. Для обычных встроенных числовых типов результат — `bool`. Сравнения `is`, `is not`, `in`, `not in` тоже относятся к проверкам, но решают другие задачи: идентичность и принадлежность.

Встроенные вещественные числа обычно сравниваются по математическому значению, поэтому `3 == 3.0` истинно. Однако близкие приближённые результаты `float` могут быть не равны; для численной близости нужен обоснованный допуск. NaN нарушает привычные ожидания об упорядоченности.

```python
print(3 == 3.0)
print(3 != 4, 3 <= 3)
x = 7
print(0 < x < 10)
print(0 < x and x < 10)
print(1 < 2 > 0)
print("3" == 3)
try:
    print("3" < 3)
except TypeError as error:
    print(type(error).__name__)
# Вывод:
# True
# True True
# True
# True
# True
# False
# TypeError
```

Число и строка не становятся равными только потому, что строка содержит цифру. Упорядочивающее сравнение таких типов запрещено. Комплексные числа допускают равенство, но не обычные `<` и `>`.

**Цепочка сравнений** `a < b <= c` означает совместную проверку соседних пар, а не последовательное сравнение логического результата с `c`. Среднее выражение вычисляется один раз. Если раннее сравнение ложно, последующие выражения могут вовсе не вычисляться.

```python
def middle():
    print("вызван middle")
    return 5

print(0 < middle() < 10)
print(10 < 5 < 1 / 0)
# Вывод:
# вызван middle
# True
# False
```

Во втором выражении `10 < 5` ложно. Поэтому `1 / 0` не вычисляется и исключение не возникает. В первом выражении функция вызывается один раз, хотя её результат участвует в двух соседних сравнениях.

Цепочка `a < b > c` допустима и означает `a < b` и `b > c`, а не монотонное возрастание всех трёх чисел. Для математического интервала `0 < x < 10` такая запись особенно естественна. Смешанные цепочки с `is` и `in` тоже синтаксически возможны, но могут быть сложны для чтения, поэтому без необходимости их лучше не использовать.

**Типичная ошибка:** считать `a < b < c` эквивалентом `(a < b) < c`. Это разные выражения. На уточняющий вопрос о побочных эффектах важно упомянуть однократное вычисление средних операндов и короткое замыкание.

<a id="topic-20"></a>

## 20. `not`, `and`, `or` и ленивое вычисление

**`not x`** возвращает логическое отрицание истинности `x` и всегда даёт `bool`. **`x and y`** возвращает `x`, если оно ложно, иначе вычисляет и возвращает `y`. **`x or y`** возвращает `x`, если оно истинно, иначе вычисляет и возвращает `y`.

Таким образом, `and` и `or` возвращают **один из операндов**, а не обязательно `True` или `False`. Значение операнда и его истинность — не одно и то же. Это свойство позволяет выбирать резервные значения, но требует внимательности.

```python
print(not "", not "False")
print(0 and 100)
print(5 and "готово")
print("" or "по умолчанию")
print("текст" or "резерв")
print([] or [1, 2])
# Вывод:
# True False
# 0
# готово
# по умолчанию
# текст
# [1, 2]
```

В `5 and "готово"` первый операнд истинен, поэтому результатом становится второй. В `"текст" or "резерв"` уже первый операнд истинен, поэтому второй не нужен.

**Ленивое вычисление, или короткое замыкание:** правый операнд вычисляется только тогда, когда он необходим для результата. Это используют для безопасной предварительной проверки.

```python
value = 0
print(value != 0 and 10 / value > 2)
text = ""
print(bool(text and text[0] == "A"))

def marker():
    print("правая часть вычислена")
    return 7

print(False and marker())
print(True or marker())
print(False or marker())
# Вывод:
# False
# False
# False
# True
# правая часть вычислена
# 7
```

Первая проверка не делит на ноль, потому что левый операнд `and` ложен. Во второй не происходит обращения по индексу пустой строки. Три вызова в конце показывают, когда функция действительно запускается: только в последнем случае.

Приоритет среди этих операторов: сначала `not`, затем `and`, затем `or`; сравнения обычно выполняются раньше логических связок. Поэтому `not a == b` читается как `not (a == b)`. Для сложного условия скобки полезны даже там, где формально не обязательны.

Выражение `user_value or default` подставляет значение по умолчанию при **любом** ложном `user_value`: не только при `None`, но и при `0`, `""`, пустом списке. Если ноль — допустимые данные, такой выбор может оказаться ошибкой; лучше `default if user_value is None else user_value`.

**Типичная ошибка:** `if x == 1 or 2:`. Это условие означает `(x == 1) or 2`, а число `2` истинно, поэтому условие всегда истинно. Нужно `x == 1 or x == 2` либо `x in (1, 2)`. Также нельзя механически заменять `and`/`or` побитовыми `&`/`|`: у них другой смысл и другое поведение вычисления.

## 21. `abs()`, `round()` и банковское округление

**`abs(x)`** возвращает модуль числа: расстояние до нуля. Для обычных целых и вещественных чисел результат неотрицателен. Для комплексного числа возвращается его модуль — длина соответствующего вектора, то есть `float`.

**`round(number, ndigits)`** округляет число до заданного десятичного разряда. Без `ndigits` для обычных `int` и `float` возвращает целое. Для `float` с явно заданным `ndigits`, в том числе нулём, результат остаётся `float`. Отрицательный `ndigits` означает округление до десятков, сотен и так далее, а не «удаление цифр слева».

```python
print(abs(-7), abs(2.5), abs(3 + 4j))
print(round(3.14159, 2))
print(round(1234, -2))
print(round(2.5), round(3.5), round(4.5))
print(round(-2.5), round(-3.5))
print(round(2.5, 0), type(round(2.5, 0)).__name__)
# Вывод:
# 7 2.5 5.0
# 3.14
# 1200
# 2 4 4
# -2 -4
# 2.0 float
```

**Банковское округление, или ties to even**, при точном попадании посередине выбирает вариант с чётной последней сохраняемой цифрой. Поэтому `2.5` округляется до `2`, а `3.5` до `4`. Это не правило «всегда вниз» и не «для положительных вверх, для отрицательных вниз». Оно уменьшает систематическое смещение при большом числе округлений.

Важная оговорка: правило применяется к реально представленному значению. Десятичная запись, заканчивающаяся на `5`, может храниться как число чуть меньше или чуть больше середины.

```python
from decimal import Decimal, ROUND_HALF_UP
print(round(2.675, 2))
print(format(2.675, ".2f"))
print(Decimal("2.675").quantize(Decimal("0.01")))
print(Decimal("2.5").quantize(Decimal("1"), rounding=ROUND_HALF_UP))
print(round(1.2), type(round(1.2)).__name__)
# Вывод:
# 2.67
# 2.67
# 2.68
# 3
# 1 int
```

`round(2.675, 2)` даёт `2.67` из-за двоичного приближения исходного `float`, а не потому, что банковское округление должно всегда уменьшать последнюю цифру. Точное `Decimal("2.675")` находится на середине между `2.67` и `2.68`; вариант с чётной последней цифрой — `2.68`. Для другого правила используется явно заданный режим, например `ROUND_HALF_UP`.

Округление числа и форматирование — разные операции. `round(1.2, 2)` не хранит «два знака после точки» и не обязано отображаться как `1.20`. Если нужно именно такое представление, используйте `f"{value:.2f}"`, получая строку. Если нужны точные десятичные расчёты с оговорённой политикой, применяйте `Decimal` и задавайте режим явно.

**На коллоквиуме.** Объясните три различия: округление к ближайшему против отбрасывания дробной части; правило точной середины против ошибки представления; изменение числового результата против подготовки строки для вывода. Простой лозунг «пять округляется вверх» для встроенного `round()` неверен.

# Занятие 4. Последовательности: списки и кортежи

Список и кортеж позволяют хранить несколько объектов в определённом порядке. Они поддерживают многие общие операции, но по-разному ведут себя при изменении данных. Чтобы уверенно пользоваться ими, важно различать сам контейнер, находящиеся в нём объекты и имена, которые ссылаются на контейнер. Все примеры рассчитаны на Python 3.10 и новее. Каждый блок представляет отдельную программу; комментарий «Вывод» содержит точный результат её выполнения.

<a id="topic-22"></a>

## 22. Список: определение, характеристики, области применения

**Список** — изменяемая упорядоченная последовательность объектов. Встроенный тип списка называется `list`. Упорядоченность означает, что у элементов есть позиции: первый, второй и так далее. Она не означает автоматическую сортировку: список сохраняет заданное расположение элементов, даже если числа идут не по возрастанию. Изменяемость означает возможность заменить элемент, добавить новые элементы или удалить существующие без обязательного создания другого списка.

В одном списке разрешено хранить объекты разных типов. Например, строка может обозначать название товара, целое число — количество, а логическое значение — наличие на складе. Однако в практических программах однотипные данные обычно удобнее: к ним легче применять общие операции. Повторяющиеся значения разрешены и занимают самостоятельные позиции. Пустой список тоже является полноценным списком и содержит ноль элементов.

```python
items = ["карандаш", 3, True, "карандаш"]
print(items)
print(type(items).__name__)
print(items[0], items[3])
# Вывод:
# ['карандаш', 3, True, 'карандаш']
# list
# карандаш карандаш
```

В этом примере четыре позиции, хотя различных по значению объектов меньше. Два одинаковых слова не сливаются в один элемент. Квадратные скобки обозначают литерал списка, а запятые разделяют элементы. При печати всего списка строки показываются в кавычках, чтобы их было легче отличить от чисел и других значений. При отдельной печати строк внешние кавычки не выводятся.

Список хранит ссылки на объекты, а не независимые копии всего содержимого. Поэтому присваивание списка другому имени не копирует его. Оба имени могут обозначать один изменяемый контейнер.

```python
orders = ["чай", "кофе"]
alias = orders
alias.append("сок")
print(orders)
print(alias is orders)
# Вывод:
# ['чай', 'кофе', 'сок']
# True
```

Метод `append()` добавляет элемент в конец. Изменение видно через оба имени, поскольку список один. Оператор `is` здесь проверяет именно общность объекта, а не равенство записанных значений.

**Где применяют.** Списки подходят для результатов вычислений, очереди заданий, набора строк файла, изменяемой таблицы и промежуточной обработки данных. Если количество элементов меняется во время работы, список часто оказывается естественным выбором.

При выборе структуры сначала полезно сформулировать, какие действия потребуются программе. Если нужно пройти по всем оценкам, добавить новую оценку и заменить ошибочно введённую, список удовлетворяет этим требованиям напрямую. Если требуется постоянно проверять только уникальность значений, другие контейнеры могут быть удобнее. Сам по себе список не проверяет смысл данных: он разрешит смешать оценки с названиями предметов. Согласованность содержимого остаётся ответственностью автора программы.

**Типовая ошибка и вопрос коллоквиума.** Нельзя считать, что список автоматически упорядочивает данные по величине или что присваивание создаёт копию. На вопрос «Какие свойства делают объект списком?» следует назвать тип `list`, сохранение порядка, доступ по позиции, допустимость повторов и возможность изменения содержимого.

## 23. Создание списков: литерал, `list()`, списковые включения с `if` и вложенными циклами

Для заранее известных элементов используют **литерал списка**: выражения записывают между квадратными скобками. Выражение `[]` создаёт пустой список. Вызов `list()` без аргумента тоже создаёт пустой список, а с итерируемым объектом собирает его элементы в новый список. Итерируемым называется объект, из которого можно последовательно получать элементы: например, строка, диапазон или другой список.

```python
empty = []
letters = list("кот")
numbers = list(range(2, 7, 2))
original = [10, 20]
copy = list(original)
print(empty)
print(letters)
print(numbers)
print(copy == original, copy is original)
# Вывод:
# []
# ['к', 'о', 'т']
# [2, 4, 6]
# True False
```

Строка превращается в список отдельных символов, а не в список из одной строки. Диапазон `range(2, 7, 2)` даёт числа 2, 4 и 6: правая граница не включается. Вызов `list(original)` создаёт другой внешний контейнер с теми же элементами. Это поверхностное копирование: вложенные изменяемые объекты автоматически не дублируются.

**Списковое включение** строит список по правилу. Общая форма: `[выражение for переменная in источник if условие]`. Сначала берётся очередной элемент источника, затем проверяется условие, а при его истинности вычисляется выражение для результата. Часть с `if` необязательна. Несколько частей `for` обозначают вложенные циклы и читаются слева направо.

```python
squares = [n * n for n in range(6) if n % 2 == 0]
pairs = [(letter, n) for letter in "ab" for n in range(1, 3)]
print(squares)
print(pairs)
# Вывод:
# [0, 4, 16]
# [('a', 1), ('a', 2), ('b', 1), ('b', 2)]
```

В первом включении проходят фильтр числа 0, 2 и 4, после чего вычисляются их квадраты. Во втором сначала фиксируется буква `a`, для неё перебираются оба числа, затем то же происходит для `b`. Результат содержит четыре пары. Каждый элемент включения может сам быть кортежем, списком или другим объектом.

Списковое включение полезно понимать как сокращённую запись накопления результата. Воображаемая программа сначала создаёт пустой список, затем выполняет циклы, проверяет условие и добавляет вычисленное значение. Такой мысленный перевод помогает разобрать даже незнакомый пример. Включение не изменяет источник автоматически: оно строит отдельный результат. Если внутри выражения возвращаются уже существующие вложенные списки, новый внешний контейнер по-прежнему может содержать ссылки на прежние объекты.

**Типовые ошибки.** `list(5)` не означает «список из пяти элементов»: число не является итерируемым объектом. Для одного элемента нужен литерал `[5]`. Не следует путать фильтрующий `if` после цикла с условным выражением перед ним: `[x if x > 0 else 0 for x in data]` сохраняет число элементов, а фильтр способен его уменьшить. Слишком сложное включение лучше заменить обычными циклами.

**Вопрос коллоквиума.** В каком порядке появятся пары при двух частях `for`? Ответ нужно объяснять через внешний и внутренний циклы, а не через догадку по готовому результату.

## 24. Длина списка, положительные и отрицательные индексы, выход за диапазон

Функция `len()` возвращает **длину списка**, то есть количество его элементов. Вложенный список на внешнем уровне считается одним элементом независимо от собственной длины. Например, длина `[[1, 2], [3, 4, 5]]` равна двум. Индексация позволяет получить один элемент по его позиции. Положительные индексы начинаются с нуля: первый элемент имеет индекс `0`, второй — `1`, последний — `len(items) - 1`.

Отрицательные индексы отсчитываются от конца. Индекс `-1` обозначает последний элемент, `-2` — предпоследний. Для списка длины `n` допустимы целые индексы от `-n` до `n - 1` включительно. Ноль не бывает «отрицательным нулём»: выражения `0` и `-0` задают одну позицию.

```python
colors = ["красный", "зелёный", "синий"]
print(len(colors))
print(colors[0], colors[2])
print(colors[-1], colors[-3])
print(colors[-0])
# Вывод:
# 3
# красный синий
# синий красный
# красный
```

Доступ по индексу не удаляет элемент и не меняет список. Он возвращает объект, находящийся на указанной позиции. Если таким объектом является изменяемый контейнер, последующее изменение полученного объекта может быть видно и через исходный список.

Индекс, которому не соответствует позиция, вызывает `IndexError`. Особенно часто это происходит при обращении к индексу, равному длине списка: отсчёт ведь начинается с нуля. Для пустого списка недопустим любой одиночный индекс, включая `0` и `-1`. Неподходящий тип индекса, например дробное число, вызывает `TypeError`.

```python
values = [10, 20]
for index in (2, -3):
    try:
        print(values[index])
    except IndexError as error:
        print(type(error).__name__)

try:
    print(values[1.0])
except TypeError as error:
    print(type(error).__name__)
print(len([]))
# Вывод:
# IndexError
# IndexError
# TypeError
# 0
```

Исключения перехватываются, поэтому программа продолжает работу после каждой неудачной попытки. При отрицательной индексации можно мысленно прибавить длину: для двух элементов индекс `-3` превращается в `-1` относительно начала и остаётся за левой границей.

Чтобы разобраться с индексами, полезно нарисовать элементы в ряд и подписать над ними положительные позиции, а под ними отрицательные. У списка из четырёх элементов сверху будут числа от нуля до трёх, снизу — от минус четырёх до минус одного. Каждая пара подписей указывает на один элемент. Отрицательная индексация особенно удобна, когда длина заранее неизвестна, но нужен последний или предпоследний результат.

**Типовая ошибка и вопрос коллоквиума.** Цикл по индексам обычно записывают как `range(len(values))`, а не `range(len(values) + 1)`. На вопрос о последнем элементе полезно дать два варианта: `values[-1]` и `values[len(values) - 1]`, обязательно оговорив, что список должен быть непустым.

## 25. Срезы `[start:stop:step]` и значения по умолчанию

**Срез** выбирает из последовательности несколько элементов и для списка создаёт новый список. В записи `items[start:stop:step]` параметр `start` задаёт начальную позицию, `stop` — границу остановки, а `step` — шаг. Начальная позиция включается, конечная граница не включается. При положительном шаге движение идёт вправо, при отрицательном — влево. Можно выбрать пустую последовательность, если направление и границы не позволяют получить ни одного элемента.

Если шаг пропущен, он равен `1`. Для положительного шага пропущенное начало соответствует началу списка, а пропущенный конец — его концу. Поэтому `items[:]` выбирает все элементы, `items[:3]` — первые три, `items[3:]` — элементы начиная с четвёртого. Границы среза могут выходить за длину: они корректируются, а не вызывают `IndexError`.

```python
values = [0, 1, 2, 3, 4, 5]
print(values[1:5:2])
print(values[:3])
print(values[3:])
print(values[20:30])
print(values[-3:])
# Вывод:
# [1, 3]
# [0, 1, 2]
# [3, 4, 5]
# []
# [3, 4, 5]
```

В первом срезе выбираются позиции 1 и 3; позиция 5 уже является исключённой границей. Срез за правым краем даёт пустой список. Отрицательные границы, как и отрицательные индексы, отсчитываются от конца, но срез описывает диапазон, а не доступ к одной позиции.

При отрицательном шаге значения по умолчанию меняются: движение начинается у правого конца и идёт за левый край. Поэтому `items[::-1]` разворачивает последовательность. Важно не заменять пропущенную левую границу остановки явным `-1`: явное значение сначала интерпретируется как индекс последнего элемента.

```python
values = [0, 1, 2, 3, 4, 5]
print(values[::-1])
print(values[4:1:-1])
print(values[:-1:-1])
print(values[-1::-1])
try:
    print(values[::0])
except ValueError as error:
    print(type(error).__name__)
# Вывод:
# [5, 4, 3, 2, 1, 0]
# [4, 3, 2]
# []
# [5, 4, 3, 2, 1, 0]
# ValueError
```

Шаг `0` недопустим: он не определяет продвижения. Обратный срез создаёт новую последовательность, а не переставляет элементы исходного списка.

Двоеточие принципиально меняет смысл квадратных скобок: вместо требования одной существующей позиции получается описание выборки. Даже срез из одного элемента возвращает контейнер, а одиночный индекс — сам элемент. Поэтому результат `values[0:1]` и результат `values[0]` могут иметь разные типы. Полный срез списка создаёт поверхностную копию: внешние контейнеры различаются, но вложенные изменяемые элементы могут оставаться общими. Эту особенность важно учитывать при работе с таблицами.

**Типовая ошибка и вопрос коллоквиума.** Нельзя считать, что `stop` включается или что срез с большими границами обязательно ошибочен. Объясните различие между `values[100]` и `values[100:200]`: первая операция требует существующей позиции, вторая безопасно выбирает доступную часть диапазона, которая может оказаться пустой.

## 26. Изменение элементов списка по индексу и срезами: замена, вставка, удаление

Присваивание по индексу меняет объект на одной существующей позиции: `items[index] = value`. Длина списка при этом сохраняется. Правая часть может быть любым объектом, включая другой список: такой объект станет одним элементом, а не автоматически распределится по нескольким позициям. Индекс должен быть допустимым; присваивание на позицию `len(items)` не добавляет элемент и приводит к `IndexError`.

Присваивание **срезу** заменяет выбранную часть элементами итерируемого объекта справа. Для обычного среза с шагом `1` число новых элементов не обязано совпадать с числом удаляемых. Поэтому одна операция может увеличить или уменьшить список. Присваивание пустому срезу вставляет элементы, а присваивание пустой последовательности удаляет выбранную часть.

```python
values = [10, 20, 30, 40]
values[1] = 99
print(values)
values[1:3] = [7, 8, 9]
print(values)
values[2:2] = [100, 200]
print(values)
values[1:4] = []
print(values)
# Вывод:
# [10, 99, 30, 40]
# [10, 7, 8, 9, 40]
# [10, 7, 100, 200, 8, 9, 40]
# [10, 8, 9, 40]
```

Сначала заменяется только число 20. Затем две позиции заменяются тремя числами. Срез `[2:2]` пустой: перед прежним элементом на позиции 2 вставляются два значения. Последнее присваивание удаляет три позиции. Все изменения происходят в одном внешнем списке, поэтому другие имена этого списка тоже увидят результат.

Для **расширенного среза**, у которого шаг не равен `1`, действует другое правило: количество передаваемых элементов должно точно совпадать с количеством выбранных позиций. Такие позиции могут быть разнесены по списку, и изменение длины через это присваивание не допускается.

```python
values = [0, 1, 2, 3, 4, 5]
values[::2] = [10, 20, 30]
print(values)
try:
    values[::2] = [7]
except ValueError as error:
    print(type(error).__name__)
del values[1::2]
print(values)
# Вывод:
# [10, 1, 20, 3, 30, 5]
# ValueError
# [10, 20, 30]
```

Позиции 0, 2 и 4 получают три новых значения. Попытка передать одно значение вместо трёх завершается ошибкой. При этом оператор `del` разрешает удаление элементов расширенного среза: ограничение на совпадение количества относится именно к присваиванию.

Перед сложной заменой полезно отдельно определить три вещи: какие позиции выбираются, сколько элементов исчезает и сколько приходит справа. Для обычного среза новая длина равна прежней длине минус число удалённых элементов плюс число добавленных. При замене по индексу этот расчёт всегда сохраняет длину. Такой подход помогает не спутать вставку с заменой и заранее понять, какие индексы получат элементы после операции.

**Типовые ошибки.** `items[1:2] = 5` неверно, потому что справа требуется итерируемый объект; подходит `[5]`. Важно различать `items = new_items`, которое связывает имя с другим объектом, и `items[:] = new_items`, которое меняет уже существующий список.

**Вопрос коллоквиума.** Каким присваиванием вставить несколько элементов без удаления? Ответ: заменить пустой срез, например `items[2:2] = [7, 8]`.

## 27. Методы добавления элементов: `append()`, `extend()`, `insert()`

Методы добавления изменяют существующий список. `append(value)` помещает **один объект** в конец. Если передать список, он станет вложенным элементом. `extend(iterable)` перебирает источник и добавляет **каждый его элемент** в конец. Эта разница определяет не только длину результата, но и его структуру: вложенный список и несколько чисел на внешнем уровне — разные данные.

Оба метода возвращают `None`, а не изменённый список. Такой интерфейс подчёркивает, что операция выполнена на месте. Если написать `values = values.append(5)`, имя `values` начнёт обозначать `None`, хотя прежний список действительно изменился. Обычно вызов изменяющего метода записывают отдельной строкой.

```python
nested = [1, 2]
result = nested.append([3, 4])
flat = [1, 2]
flat.extend([3, 4])
letters = []
letters.extend("кот")
print(nested)
print(flat)
print(letters)
print(result)
# Вывод:
# [1, 2, [3, 4]]
# [1, 2, 3, 4]
# ['к', 'о', 'т']
# None
```

В первой операции длина увеличивается с двух до трёх. Во второй — с двух до четырёх. Строка является итерируемым объектом, поэтому `extend("кот")` добавляет три символа. Для добавления слова одним элементом требовался бы `append("кот")`. Источником `extend()` может быть также диапазон или выражение-генератор.

Метод `insert(index, value)` вставляет один объект **перед** указанной позицией. Элементы начиная с этой позиции сдвигаются вправо. При слишком большом индексе вставка происходит в конце, при слишком маленьком отрицательном — в начале. В отличие от присваивания по индексу, здесь граничное значение не обязано соответствовать существующему элементу.

```python
values = [20, 30]
values.insert(0, 10)
print(values)
values.insert(2, 25)
print(values)
values.insert(100, 40)
values.insert(-100, 0)
print(values)
# Вывод:
# [10, 20, 30]
# [10, 20, 25, 30]
# [0, 10, 20, 25, 30, 40]
```

После каждой вставки позиции могут измениться, поэтому последующие индексы нужно понимать относительно текущего списка. Отрицательный индекс также относится к текущей длине: `insert(-1, x)` вставляет перед последним элементом, а не после него.

Содержимое аргумента не определяет метод автоматически: выбор делает программист. Даже пустой список при добавлении через `append()` становится полноценным одним элементом, тогда как `extend()` тем же пустым источником ничего не добавит. Метод `insert()` также всегда помещает один объект, независимо от его внутреннего размера. Если требуется вставить сразу несколько элементов в середину, удобнее использовать присваивание пустому срезу, а не строить серию отдельных вставок.

**Типовая ошибка и вопрос коллоквиума.** Вопрос «Как добавить список в список?» неоднозначен без уточнения структуры. Для одного вложенного элемента нужен `append()`, для добавления его содержимого — `extend()`. Вставка в середину большого списка требует сдвига последующих ссылок; поэтому для последовательного накопления результатов обычно выбирают добавление в конец, а не многократную вставку в начало.

<a id="topic-28"></a>

## 28. Удаление элементов: `del`, `pop()`, `remove()`, `clear()`

Способ удаления выбирают по тому, **что известно об элементе** и **нужно ли сохранить удалённое значение**. Оператор `del` удаляет элемент по индексу или сразу несколько элементов по срезу. Он не возвращает значение. Метод `pop(index)` удаляет один элемент по позиции и возвращает его; если индекс не задан, удаляется последний элемент. Одиночный недопустимый индекс вызывает `IndexError`, а удаление пустого среза безопасно.

```python
values = [10, 20, 30, 40, 50]
del values[1]
print(values)
last = values.pop()
first = values.pop(0)
print(last, first)
print(values)
del values[:]
print(values)
# Вывод:
# [10, 30, 40, 50]
# 50 10
# [30, 40]
# []
```

После удаления числа 20 позиции оставшихся элементов изменились. Поэтому `pop(0)` позднее удаляет первый элемент уже укороченного списка. Значения 50 и 10 сохранены в переменных и могут использоваться в дальнейших вычислениях. Выражение `del values[:]` очищает содержимое, но само имя `values` продолжает обозначать существующий список.

Метод `remove(value)` ищет элемент **по равенству значению** и удаляет только первое совпадение. Если совпадений нет, возникает `ValueError`. Метод `clear()` удаляет все элементы и оставляет пустой список. Как и большинство изменяющих методов, `remove()` и `clear()` возвращают `None`.

```python
values = [2, 5, 2, 7]
values.remove(2)
print(values)
try:
    values.remove(99)
except ValueError as error:
    print(type(error).__name__)
alias = values
values.clear()
print(values, alias)
try:
    values.pop()
except IndexError as error:
    print(type(error).__name__)
# Вывод:
# [5, 2, 7]
# ValueError
# [] []
# IndexError
```

Второе число 2 остаётся, потому что `remove()` останавливается на первом найденном совпадении. Оба имени после `clear()` показывают пустой список: операция изменила общий объект. Напротив, `values = []` связало бы только имя `values` с новым контейнером и не очистило бы объект, доступный через `alias`.

Если значение может отсутствовать, стратегия зависит от задачи. Иногда отсутствие является обычной ситуацией, и его обрабатывают условием или перехватом исключения. Иногда оно свидетельствует о нарушении логики, которое нужно обнаружить. Проверка принадлежности перед удалением понятна начинающему, но выполняет отдельный поиск, после которого метод снова ищет значение. Для небольших учебных списков это обычно несущественно; важнее ясно определить ожидаемое поведение при отсутствии элемента.

**Типовые ошибки.** Нельзя путать `remove(0)` и `pop(0)`: первое удаляет значение ноль, второе — элемент на первой позиции. Удалять элементы во время прямого перебора того же списка опасно: сдвиги позиций могут приводить к пропускам. Для фильтрации часто безопаснее создать новый список включением.

**Вопрос коллоквиума.** Чем `del values` отличается от `values.clear()`? В первом случае удаляется привязка имени; сам объект может остаться доступен через другие имена. Во втором очищается контейнер, а имя сохраняется.

## 29. Итерируемость списка и функции `sum()`, `max()`, `min()`, `sorted()`

Список является **итерируемым объектом**: его элементы можно последовательно получать в порядке расположения. Цикл `for` не требует вручную вычислять индексы. Каждый проход связывает переменную цикла с очередным элементом. Когда элементы заканчиваются, цикл завершается. Сам список можно перебирать повторно: новый цикл снова начинает с первого элемента, если содержимое не было изменено.

Функции обработки итерируемых объектов используют тот же общий принцип получения элементов. `sum()` суммирует числа, `max()` выбирает наибольший элемент, `min()` — наименьший. Функция `sorted()` возвращает новый отсортированный список. Для сравнения и сортировки элементы должны поддерживать нужные отношения порядка; произвольная смесь строк и чисел обычно не подходит.

```python
values = [7, 2, 5]
for value in values:
    print(value * 2)
print(sum(values))
print(min(values), max(values))
print(sorted(values))
print(values)
# Вывод:
# 14
# 4
# 10
# 14
# 2 7
# [2, 5, 7]
# [7, 2, 5]
```

Цикл выводит удвоенные элементы, но не присваивает их обратно в список. Поэтому исходные значения сохраняются. Аналогично `sorted()` создаёт отдельный результат, а не переставляет элементы `values`. Это важное различие между вычислением нового значения и изменением контейнера.

У пустого списка нет наибольшего и наименьшего элемента. Для `max()` и `min()` с одним итерируемым аргументом можно передать именованный параметр `default`: он определяет результат при отсутствии элементов. У `sum()` есть начальное значение `start`, по умолчанию равное нулю. Оно участвует и при непустом источнике, то есть добавляется к сумме.

```python
print(sum([]))
print(sum([2, 3], start=10))
print(max([], default="нет данных"))
print(min([], default=0))
print(sorted([]))
try:
    print(max([]))
except ValueError as error:
    print(type(error).__name__)
# Вывод:
# 0
# 15
# нет данных
# 0
# []
# ValueError
```

Параметр `default` не становится участником сравнения при непустом источнике. Если список содержит числа, `max(values, default=100)` не означает, что результат будет не меньше ста: запасное значение применяется только при пустоте. Для объединения строк вместо `sum()` используют строковый метод `join()`.

При переборе переменная цикла получает очередной объект, а не специальную связь с позицией списка. Поэтому присваивание этой переменной другого числа не заменяет элемент контейнера. Если же переменная обозначает вложенный список и вызывается его изменяющий метод, состояние вложенного объекта изменится. Для доступа одновременно к позиции и значению часто используют `enumerate()`: это избавляет от ручного счётчика и делает намерение программы более очевидным.

**Типовая ошибка и вопрос коллоквиума.** Не следует считать все итерируемые объекты многократно используемыми: список допускает повторный обход, а итератор постепенно исчерпывается. На вопрос «Нужен ли объекту индекс, чтобы работать с `sum()`?» ответ отрицательный: функции достаточно возможности последовательно получать подходящие элементы.

## 30. Кортеж: определение, отличия от списка, области применения

**Кортеж** — упорядоченная неизменяемая последовательность объектов; его встроенный тип называется `tuple`. Как и список, он сохраняет порядок, допускает повторяющиеся значения и может содержать объекты разных типов. Кортеж поддерживает длину, индексацию, срезы и перебор. Главное отличие состоит в невозможности заменить, добавить или удалить отдельную позицию существующего кортежа.

Неизменяемость относится к устройству самого контейнера. Она не означает, что каждый объект внутри обязательно неизменяем. Кортеж может содержать список, а содержимое такого списка разрешено менять. Поэтому утверждение «в кортеже вообще ничего не может измениться» слишком сильное. Точнее сказать: набор ссылок на элементы кортежа и их порядок после создания не меняются.

```python
point = (3, 8)
print(type(point).__name__)
print(len(point))
print(point[0], point[-1])
print(point[:1])
print(point + (10,))
print(point)
# Вывод:
# tuple
# 2
# 3 8
# (3,)
# (3, 8, 10)
# (3, 8)
```

Срез кортежа снова даёт кортеж. При объединении создаётся результат из трёх элементов, но исходная точка остаётся прежней. Запятая в записи `(3,)` существенна: так обозначается кортеж из одного элемента, а не число в скобках.

Кортеж удобен для небольшой записи с фиксированной структурой: координат точки, размера изображения, пары «название — количество». Он также естественен для возврата нескольких связанных результатов функции. По соглашению список чаще обозначает изменяемый набор однотипных элементов, а кортеж — фиксированную группу значений с разным смыслом. Это рекомендация проектирования, а не запрет языка.

```python
record = ("Анна", 19, "Python")
name, age, course = record
print(name)
print(age, course)
try:
    record[1] = 20
except TypeError as error:
    print(type(error).__name__)
# Вывод:
# Анна
# 19 Python
# TypeError
```

Распаковка назначает смысловые имена позициям, после чего работать с записью удобнее, чем постоянно помнить номера индексов. Попытка заменить возраст непосредственно в кортеже запрещена. При необходимости можно создать новую запись с другим возрастом.

Неизменяемый внешний контейнер помогает выразить намерение автора: полученную пару координат следует рассматривать как готовое значение, а не как рабочую область для добавления новых координат. Если точка перемещается, можно связать переменную с новым кортежем. Это не противоречит неизменяемости старого объекта. Нужно различать возможность переназначить имя и возможность изменить объект: имя не является частью кортежа и не обязано навсегда обозначать одно значение.

**Типовая ошибка и вопрос коллоквиума.** Нельзя обосновывать выбор кортежа только тем, что он «всегда быстрее списка»: производительность зависит от операции и реализации. Более надёжные основания — фиксированная структура и запрет изменения контейнера. Кортеж допустим как ключ словаря только тогда, когда все его элементы хешируемы; наличие внутри списка делает такой кортеж непригодным ключом.

## 31. Создание кортежей: литерал, `tuple()`, выражение-генератор вместо «кортежного включения»

Кортеж обычно записывают как элементы, разделённые запятыми, в круглых скобках. Однако для непустого кортежа решающую роль играет **запятая**, а не сами скобки. Запись `(5)` является числом в группирующих скобках; запись `(5,)` — кортежем из одного числа. Скобки часто нужны для ясности или из-за окружающего синтаксиса. Пустой кортеж записывается как `()`.

Функция `tuple()` без аргумента возвращает пустой кортеж, а с итерируемым объектом собирает его элементы. Как и `list()`, она перебирает строку по символам. Если нужно положить строку внутрь как один элемент, используют литерал с запятой, например `("кот",)`.

```python
single = (5,)
number = (5)
without_parentheses = 10, 20
print(type(single).__name__, type(number).__name__)
print(without_parentheses)
print(tuple("кот"))
print(tuple([1, 2, 3]))
print(tuple())
# Вывод:
# tuple int
# (10, 20)
# ('к', 'о', 'т')
# (1, 2, 3)
# ()
```

В Python **не существует отдельного синтаксиса кортежного включения**. Выражение `(x * x for x in range(3))` создаёт генератор, а не кортеж. Оно называется **выражением-генератором**. Генератор выдаёт значения по запросу и постепенно исчерпывается. Чтобы получить готовый кортеж результатов, генератор передают функции `tuple()`.

```python
generator = (n * n for n in range(3))
print(type(generator).__name__)
print(next(generator))
print(tuple(generator))
print(tuple(generator))
squares = tuple(n * n for n in range(4) if n % 2 == 0)
print(squares)
# Вывод:
# generator
# 0
# (1, 4)
# ()
# (0, 4)
```

Первый вызов `next()` забирает квадрат нуля. Затем `tuple(generator)` получает только оставшиеся квадраты: 1 и 4. Повторное преобразование того же генератора даёт пустой кортеж, поскольку значения уже закончились. Последняя строка создаёт новый генератор и сразу полностью собирает его результат. Дополнительные скобки вокруг генератора здесь не нужны: он является единственным аргументом вызова.

Практическая разница заметна при больших источниках данных. Готовый кортеж хранит все полученные элементы и допускает многократную индексацию. Генератор хранит состояние вычисления и выдаёт следующий результат по запросу, но не предоставляет обычного доступа к произвольной позиции. Преобразование генератора в кортеж завершает вычисление оставшейся последовательности. Поэтому такое преобразование разумно, когда действительно нужны повторный обход, известная длина или обращение к отдельным позициям.

**Типовые ошибки.** Замена квадратных скобок включения круглыми не создаёт аналогичный готовый контейнер другого типа. Разница затрагивает и время вычисления: список строится сразу, а значения генератора обычно вычисляются при запросе. При этом самый внешний источник выражения-генератора подготавливается при его создании, поэтому слово «ленивый» не означает полного отсутствия работы до первого запроса.

**Вопрос коллоквиума.** Как получить кортеж квадратов чётных чисел? Следует назвать `tuple()` с выражением-генератором, а не «кортежное включение», и пояснить отличие готовой последовательности от одноразового источника значений.

## 32. Неизменяемость кортежа и изменяемые элементы внутри него

Неизменяемый контейнер не позволяет менять свои позиции, но может ссылаться на изменяемые объекты. Для кортежа это означает следующее: нельзя выполнить `record[0] = new_value`, но можно вызвать изменяющий метод объекта `record[0]`, если этот объект поддерживает такую операцию. Кортеж при этом продолжает ссылаться на тот же объект; меняется внутреннее состояние элемента, а не структура кортежа.

Полезная модель — представить кортеж как неизменяемый набор ячеек со ссылками. Закреплены именно ссылки в ячейках. Свойства объектов, на которые они указывают, определяются их собственными типами. Если элемент — число или строка, его нельзя изменить на месте; если список, его содержимое изменяется обычными методами.

```python
record = ("покупки", ["хлеб"])
record[1].append("молоко")
print(record)
try:
    record[1] = ["чай"]
except TypeError as error:
    print(type(error).__name__)
print(record)
# Вывод:
# ('покупки', ['хлеб', 'молоко'])
# TypeError
# ('покупки', ['хлеб', 'молоко'])
```

Метод `append()` получает вложенный список и меняет его. Последующее присваивание пытается уже заменить сам элемент кортежа, поэтому запрещено. Эти операции могут выглядеть похожими по расположению квадратных скобок, но обращаются к разным уровням структуры.

Особенно тонкая ситуация возникает с расширенным присваиванием. Для списка операция `+=` сначала дополняет существующий список, а затем пытается записать результат в цель присваивания. Если целью является позиция кортежа, второй этап невозможен. Исключение не откатывает уже выполненное изменение вложенного списка.

```python
container = ([1, 2],)
try:
    container[0] += [3]
except TypeError as error:
    print(type(error).__name__)
print(container)
container[0].extend([4])
print(container)
# Вывод:
# TypeError
# ([1, 2, 3],)
# ([1, 2, 3, 4],)
```

После ошибки число 3 уже находится внутри. Следующий вызов `extend()` не требует присваивания позиции кортежа и поэтому проходит без ошибки. Такой пример показывает, что возникновение исключения не гарантирует отсутствия побочных эффектов. В реальном коде лучше не использовать заведомо запрещённую форму, а явно менять вложенный объект методом.

Чтобы определить допустимость операции, полезно назвать её непосредственную цель. В записи `record[1].append(value)` цель метода — список, полученный из второй позиции. В записи `record[1] = value` цель присваивания — сама позиция кортежа. Одинаковый префикс выражения не делает эти действия эквивалентными. Такой разбор по уровням работает и для более сложных структур, например кортежа со словарём, внутри которого хранятся списки значений.

**Типовые ошибки.** Кортеж со списком внутри не становится глубоко неизменяемым и не подходит как ключ словаря. Нельзя также считать, что исключение автоматически возвращает программу к прежнему состоянию.

**Вопрос коллоквиума.** Изменился ли кортеж после `container[0].append(5)`? Точный ответ: состав его позиций и ссылки на элементы остались прежними, но состояние вложенного изменяемого объекта изменилось, поэтому изменилось и наблюдаемое содержимое всей структуры.

## 33. Сравнение списков и кортежей: лексикографический порядок и нюансы

Списки сравниваются со списками, а кортежи — с кортежами **лексикографически**. Этот порядок похож на словарное сравнение слов: элементы сопоставляются слева направо. Первая различающаяся пара определяет результат. Если все элементы более короткой последовательности равны соответствующему началу длинной, короткая последовательность считается меньшей.

При сравнении длины не являются первым критерием. Например, список из трёх небольших чисел может быть меньше списка из одного большого числа, потому что решение принимается уже по первым элементам. До последующих позиций дело тогда не доходит. Для равенства требуются совпадение длины и равенство соответствующих элементов.

```python
print([1, 9] < [2, 0])
print([1, 2] < [1, 2, 0])
print([9] > [1, 100, 1000])
print((3, 4) == (3, 4))
print([3, 4] == (3, 4))
# Вывод:
# True
# True
# True
# True
# False
```

В первой строке сравнение заканчивается на 1 и 2. Во второй общая часть полностью совпадает, поэтому решает длина. Третья строка подчёркивает, что короткая последовательность не обязательно меньше. Последняя строка показывает различие типов контейнеров: список и кортеж с одинаковыми значениями не равны.

Упорядочивающее сравнение списка с кортежем, например `[1] < (2,)`, не поддерживается и вызывает `TypeError`. Ошибка возможна и для двух списков одного типа, если в решающей позиции окажутся несравнимые элементы, например число и строка. Однако такие элементы не помешают сравнению, если результат уже определён более ранними позициями.

```python
print([0, "текст"] < [1, 100])
try:
    print([1, "текст"] < [1, 100])
except TypeError as error:
    print(type(error).__name__)
try:
    print([1] < (2,))
except TypeError as error:
    print(type(error).__name__)
print([1, 2] == [1.0, 2.0])
# Вывод:
# True
# TypeError
# TypeError
# True
```

В первой строке значения 0 и 1 сразу дают ответ, поэтому разные типы второй пары не рассматриваются. Во второй первые элементы равны, приходится сравнивать строку с числом, и возникает исключение. Последняя строка напоминает, что сравнение элементов использует их собственные правила: соответствующие целые и вещественные числа могут быть равны.

Сравнение последовательностей часто используют при упорядочивании записей с несколькими полями. Если первым полем является номер группы, а вторым фамилия, сначала будут сопоставляться группы, и только внутри одинаковых групп — фамилии. Поэтому расположение полей влияет на смысл сравнения. Если естественный порядок полей не совпадает с нужным порядком сортировки, лучше явно сформировать ключ, а не перестраивать сами записи только ради одного вычисления.

**Типовые ошибки.** Лексикографическое сравнение не сравнивает суммы и не ищет максимальные элементы. Не следует также смешивать `==` и `is`: равные последовательности могут быть разными объектами.

**Вопрос коллоквиума.** Почему `[2, 1000] < [3]` истинно? Потому что первая различающаяся пара — 2 и 3; длины и второе значение уже не влияют на ответ.

<a id="topic-34"></a>

## 34. Общие операции последовательностей и операторы `+=`, `*=`

Списки и кортежи относятся к последовательностям и поддерживают общий набор операций. `len()` сообщает количество элементов; `in` и `not in` проверяют наличие значения; `+` объединяет последовательности совместимых типов; `*` повторяет их содержимое заданное целое число раз. Индексация выбирает один элемент, срез — подпоследовательность, а цикл `for` перебирает элементы по порядку.

Проверка принадлежности для списка или кортежа ищет отдельный элемент, а не произвольную подпоследовательность. Например, наличие числа 2 и наличие списка `[2]` — разные вопросы. При сложении обычный список объединяют со списком, а кортеж — с кортежем. Нулевое или отрицательное число повторений даёт пустую последовательность соответствующего типа.

```python
values = [1, 2, 3]
print(len(values), 2 in values, 9 not in values)
print([2] in values)
print(values + [4])
print(("а", "б") * 2)
print(values * 0)
print(values[1], values[:2])
for value in (7, 8):
    print(value)
# Вывод:
# 3 True True
# False
# [1, 2, 3, 4]
# ('а', 'б', 'а', 'б')
# []
# 2 [1, 2]
# 7
# 8
```

Повторение не создаёт глубоких копий элементов. Если повторяется список с вложенным списком, несколько позиций будут ссылаться на один вложенный объект. Для независимых строк таблицы обычно используют включение: `[[0] * 3 for _ in range(2)]`, а не `[[0] * 3] * 2`.

Расширенные присваивания особенно важны при наличии нескольких имён. Для списка `+=` дополняет существующий объект элементами итерируемого источника, а `*=` повторяет его содержимое на месте. Для кортежа изменить объект нельзя, поэтому имя связывается с результатом операции, а другие имена продолжают обозначать прежний кортеж.

```python
values = [1]
alias = values
values += [2]
values *= 2
print(values, alias)
record = (1,)
old_record = record
record += (2,)
record *= 2
print(record, old_record)
rows = [[]] * 2
rows[0].append(9)
print(rows)
# Вывод:
# [1, 2, 1, 2] [1, 2, 1, 2]
# (1, 2, 1, 2) (1,)
# [[9], [9]]
```

Оба имени списка видят изменения. У кортежа старое имя сохраняет прежнее значение. В последнем примере строк фактически не две независимые: две позиции указывают на один список.

Для операции повторения следует мысленно выписать ссылки на элементы, а не рисовать новые независимые объекты. Если исходный элемент неизменяемый, например число, общность ссылок обычно не создаёт трудностей: изменить такое число на месте всё равно нельзя. Если элемент изменяемый, общий доступ становится наблюдаемым. Поэтому одинаковая внешняя запись прямоугольной таблицы ещё не доказывает независимость её строк; важно понять, как именно таблица была создана.

**Типовая ошибка и вопрос коллоквиума.** `a = a + b` и `a += b` для списка не всегда взаимозаменяемы: первая форма создаёт новый внешний список, вторая меняет прежний. Кроме того, список в `+=` принимает произвольный итерируемый источник, тогда как обычное `+` со строкой или кортежем не выполняет такое расширение.

<a id="topic-35"></a>

## 35. Цепное присваивание, распаковка коллекций, распаковка с `*`, обмен значений

При **цепном присваивании** правая часть вычисляется один раз, после чего полученный объект связывается с несколькими целями: `a = b = expression`. Если результат изменяемый, имена обозначают общий объект. Поэтому `a = b = []` не создаёт два независимых списка. Для отдельных контейнеров нужны отдельные вычисления литералов, например `a, b = [], []`.

**Распаковка** распределяет элементы итерируемого объекта между целями. Без звёздочки число элементов должно точно совпадать с количеством целей. Источником может быть не только кортеж: подходят список, строка, диапазон и другие итерируемые объекты. При несовпадении количества возникает `ValueError`. Вложенная распаковка повторяет структуру вложенных данных.

```python
a = b = []
a.append(1)
print(a, b)
x, y = [10, 20]
print(x, y)
x, y = y, x
print(x, y)
name, (width, height) = ("экран", (80, 25))
print(name, width, height)
# Вывод:
# [1] [1]
# 10 20
# 20 10
# экран 80 25
```

Обмен значений работает потому, что правая часть вычисляется с прежними значениями переменных до присваивания левой части. Временная переменная в исходном коде не нужна. Вложенная форма сначала выделяет название и пару размеров, затем разбирает пару на ширину и высоту. Скобки группируют цели и делают структуру понятной.

В присваивании со звёздочкой одна цель собирает все элементы, не назначенные другим целям. Такая цель получает **список**, даже если источник был кортежем или строкой. Она может оказаться пустой. На одном уровне распаковки допускается только одна цель со звёздочкой, иначе распределение остатка было бы неоднозначным.

```python
first, *middle, last = (10, 20, 30, 40)
print(first, middle, last)
head, *tail = [7]
print(head, tail)
combined = [0, *range(1, 4), 4]
print(combined)
try:
    left, right = [1, 2, 3]
except ValueError as error:
    print(type(error).__name__)
# Вывод:
# 10 [20, 30] 40
# 7 []
# [0, 1, 2, 3, 4]
# ValueError
```

В первой строке крайние цели забирают первый и последний элементы, а середина собирается в список. В литерале `combined` звёздочка выполняет другую, связанную по смыслу операцию: раскрывает элементы источника внутрь нового контейнера. Здесь она ничего не собирает в переменную. Аналогично можно раскрывать итерируемые объекты в литералах кортежей.

Распаковка делает код выразительным, когда форма данных заранее известна. Имена `width` и `height` объясняют смысл лучше, чем постоянные обращения к нулевой и первой позициям. Однако слишком глубокая вложенная форма затрудняет чтение. В таком случае полезно разобрать данные за несколько понятных шагов. При использовании звёздочки нужно помнить о накоплении остатка в список: распаковка очень большого источника может потребовать значительного объёма памяти.

**Типовые ошибки.** При `a, b = b, a` не происходит последовательного затирания прежнего `a`. Напротив, при двух отдельных присваиваниях `a = b; b = a` прежнее значение `a` будет потеряно. Звёздочка не отменяет минимальных требований: в форме `first, *middle, last` источник должен содержать хотя бы два элемента.

**Вопрос коллоквиума.** Какой тип получит `middle` при распаковке кортежа? Всегда список, а не кортеж.

## 36. Поверхностное и глубокое копирование

Простое присваивание не копирует объект: оно создаёт ещё одну привязку к нему. **Поверхностная копия** создаёт новый внешний контейнер, но сохраняет ссылки на прежние элементы. Для списка её получают через `copy()`, полный срез `[:]`, `list(original)` или `copy.copy()`. Изменение внешней структуры копии не затрагивает оригинал. Однако изменение общего вложенного списка заметно через оба контейнера.

Эту разницу удобно рассматривать по уровням. Внешний уровень содержит ссылки на строки таблицы. При поверхностном копировании создаётся новый список этих ссылок, но сами строки таблицы остаются прежними. Замена одной строки в копии и изменение содержимого прежней строки поэтому ведут себя по-разному.

```python
original = [[1, 2], [3, 4]]
shallow = original.copy()
print(shallow is original, shallow[0] is original[0])
shallow[0].append(9)
shallow[1] = [100]
print(original)
print(shallow)
# Вывод:
# False True
# [[1, 2, 9], [3, 4]]
# [[1, 2, 9], [100]]
```

Первый вложенный список общий, поэтому добавленная девятка видна в оригинале. Замена второй позиции меняет только внешний контейнер `shallow`: оригинал продолжает ссылаться на `[3, 4]`. Оператор `is` позволяет показать связь объектов без обращения к зависящим от запуска числовым адресам.

**Глубокое копирование**, выполняемое `copy.deepcopy()`, рекурсивно копирует вложенные объекты, для которых это предусмотрено. В обычной структуре из списков получается независимый набор изменяемых контейнеров. При этом глубокое копирование не обязано создавать новые экземпляры неизменяемых объектов: смысл операции состоит не в новом адресе каждого числа, а в корректном воспроизведении структуры и отделении изменяемых частей.

```python
import copy

shared = [1]
original = [shared, shared]
deep = copy.deepcopy(original)
deep[0].append(2)
print(original)
print(deep)
print(deep[0] is deep[1])
print(deep[0] is original[0])
# Вывод:
# [[1], [1]]
# [[1, 2], [1, 2]]
# True
# False
```

Две позиции оригинала ссылались на один объект. `deepcopy()` сохраняет это внутреннее отношение: в копии обе позиции указывают на один новый список, а не на два разных. Для этого функция запоминает уже обработанные объекты. Такой механизм также позволяет обрабатывать многие циклические структуры без бесконечного рекурсивного копирования.

Выбор глубины копирования определяется тем, какие изменения должны быть независимыми. Для списка чисел поверхностной копии обычно достаточно, потому что сами числа не изменяются на месте. Для таблицы списков поверхностная копия отделяет только набор строк, но не их содержимое. Если требуется независимость всех вложенных изменяемых частей, выбирают глубокую копию либо явно создают нужные уровни заново. Более глубокое копирование не всегда полезнее: оно требует дополнительной работы.

**Типовые ошибки.** Полный срез не делает независимыми все вложенные уровни. Глубокая копия тоже не является универсальным способом клонирования любых ресурсов: открытые файлы, сетевые подключения и пользовательские классы требуют отдельного понимания. Для простой таблицы из независимых строк может хватить явного копирования каждой строки.

**Вопрос коллоквиума.** Почему `copied[0].append(5)` иногда меняет исходные данные, а `copied[0] = [5]` — нет? Первая операция меняет общий вложенный объект, вторая заменяет ссылку только в новом внешнем контейнере.

## 37. `sorted()`: параметры `key`, `reverse`, устойчивость сортировки

Функция `sorted(iterable, *, key=None, reverse=False)` получает элементы итерируемого объекта и возвращает **новый список** в отсортированном порядке. Исходная последовательность не переставляется. Даже если передать кортеж или строку, результатом будет список. По умолчанию элементы сравниваются напрямую и располагаются по возрастанию. Параметр `reverse=True` задаёт убывающий порядок.

Параметр `key` принимает функцию, которая вычисляет **ключ сравнения** для каждого элемента. Сортируются исходные элементы, но порядок определяется этими ключами. Например, `key=len` сравнивает длины строк. Важно передавать саму функцию, а не результат её преждевременного вызова. Для одного запуска сортировки ключ вычисляется один раз на каждый элемент, поэтому сложную подготовку обычно удобнее сосредоточить именно в нём.

```python
words = ["кот", "а", "дом", "река", "я"]
print(sorted(words, key=len))
print(sorted(words, key=len, reverse=True))
print(words)
numbers = (-4, 2, -1, 3)
print(sorted(numbers, key=abs))
# Вывод:
# ['а', 'я', 'кот', 'дом', 'река']
# ['река', 'кот', 'дом', 'а', 'я']
# ['кот', 'а', 'дом', 'река', 'я']
# [-1, 2, 3, -4]
```

Слова «кот» и «дом» имеют одинаковую длину. Их взаимное расположение сохраняется, как и порядок односимвольных слов. Это проявление **устойчивости сортировки**: элементы с равными ключами остаются в том же относительном порядке, в каком находились в источнике. Устойчивость сохраняется и при `reverse=True`; этот параметр не означает простого разворота уже отсортированного списка с переворачиванием равных групп.

Для нескольких критериев удобно возвращать кортеж ключей. Он сравнивается лексикографически: сначала учитывается первый критерий, затем при равенстве второй и так далее. Другой способ — несколько устойчивых сортировок, начиная с менее важного критерия и заканчивая главным.

```python
students = [("Борис", 2), ("Анна", 1), ("Вера", 2), ("Глеб", 1)]
print(sorted(students, key=lambda item: (item[1], item[0])))
by_name = sorted(students, key=lambda item: item[0])
by_group = sorted(by_name, key=lambda item: item[1])
print(by_group)
values = [3, 1, 2]
result = values.sort()
print(values, result)
# Вывод:
# [('Анна', 1), ('Глеб', 1), ('Борис', 2), ('Вера', 2)]
# [('Анна', 1), ('Глеб', 1), ('Борис', 2), ('Вера', 2)]
# [1, 2, 3] None
```

Первый вариант сортирует по номеру группы, затем по имени. Во втором сначала формируется порядок имён, который сохраняется внутри каждой группы при следующем проходе. Метод `list.sort()` отличается от `sorted()`: он переставляет элементы существующего списка и возвращает `None`. Оба способа поддерживают `key`, `reverse` и устойчивость.

Устойчивость особенно полезна для записей, в которых порядок поступления уже имеет значение. Если заявки сортируются по приоритету, заявки с одинаковым приоритетом сохранят очередность источника. При этом функция не придумывает новый порядок для равных ключей. Если нужен дополнительный критерий, например время или имя, его следует явно включить в ключ. Устойчивость и наличие второго критерия — разные механизмы, хотя оба помогают получать предсказуемое расположение данных.

**Типовые ошибки и вопрос коллоквиума.** `key=len()` неверно: нужен объект функции `len`. Нельзя рассчитывать на сравнение несовместимых ключей, например чисел со строками. Почему второстепенную сортировку выполняют первой? Потому что последующий устойчивый проход по главному критерию сохраняет уже полученный порядок внутри групп с одинаковым главным ключом.

# Занятие 5. Строки

Строки нужны не только для вывода сообщений. С их помощью представляют имена, команды, пути, содержимое файлов и данные, полученные по сети. Чтобы уверенно работать со строками, полезно различать три вещи: текст программы, созданное во время выполнения строковое значение и способ показа этого значения человеку. Например, запись `"\n"` занимает несколько знаков в исходном коде, но создаёт строку из одного символа перевода строки.

Примеры рассчитаны на Python 3.10 и более новые версии. Каждый блок выполняется отдельно: все необходимые переменные определены внутри него. Комментарии после пометки «Вывод» показывают точный стандартный вывод; внешние кавычки в этих комментариях присутствуют только там, где их действительно печатает программа.

<a id="topic-38"></a>

## 38. Строка: определение, характеристики, области применения

**Строка** — объект типа `str`, представляющий неизменяемую последовательность кодовых точек Unicode. Практически это означает, что в строке можно хранить русский и английский текст, цифры, знаки препинания, управляющие символы и множество других знаков. Слово «неизменяемая» означает, что после создания объекта нельзя заменить отдельный его элемент. Однако переменной можно присвоить другую строку: переменная и объект — не одно и то же.

Строка имеет длину, её элементы расположены в определённом порядке и доступны по индексам. Даже один элемент строки является строкой: отдельного встроенного типа «символ» в Python нет. Пустая строка тоже полноценный объект `str`; её длина равна нулю. Она часто обозначает отсутствие текста, но не равна ни `None`, ни числу `0`.

```python
text = "Кот"
print(type(text).__name__)
print(len(text))
print(text[0], type(text[0]).__name__)
print(len(""), "" == None)
# Вывод:
# str
# 3
# К str
# 0 False
```

В примере `len()` считает элементы строки, а индекс `0` обозначает первый элемент. Важно не путать длину строки с размером её записи в файле. Например, одна русская буква при кодировании UTF-8 занимает несколько байтов. Кроме того, один видимый знак иногда состоит из нескольких кодовых точек: буква и отдельный комбинируемый знак ударения будут двумя элементами строки. Для обычных учебных примеров достаточно считать элементы символами, помня об этом уточнении.

```python
word = "кот"
try:
    word[0] = "р"
except TypeError as error:
    print(type(error).__name__)
word = "р" + word[1:]
print(word)
print("код".encode("utf-8"))
# Вывод:
# TypeError
# рот
# b'\xd0\xba\xd0\xbe\xd0\xb4'
```

Первое действие запрещено, потому что пытается изменить существующий объект. Второе создаёт новую строку из новой первой буквы и оставшейся части старой. Метод `encode()` отдельно превращает текст в байты; результат уже относится к типу `bytes`, а не `str`.

Строки применяют для интерфейсов, журналов событий, поиска, обработки документов и обмена данными. Но число, записанное текстом, ещё не становится числом для вычислений: `"12" + "3"` даёт `"123"`. **Типичная ошибка** — ожидать числовой арифметики от текстовых данных. **Вопрос коллоквиума:** почему присваивание новой строки переменной разрешено, если сами строки неизменяемы? Ответ должен различать изменение объекта и переназначение имени.

## 39. Встроенный объект `str` и функция `repr()`: назначение и различия

`str` — встроенный тип строк. Вызов `str(value)` обычно создаёт текстовое представление значения, ориентированное на чтение человеком. Если аргумент уже является строкой, её содержимое сохраняется. Вызов `str()` без аргументов создаёт пустую строку. При этом `str()` не является универсальным декодировщиком: для превращения байтов в текст нужно указать кодировку, например через `data.decode("utf-8")`.

Функция `repr(value)` возвращает другую строку — представление объекта, удобное для диагностики. Для строк оно обычно содержит внешние кавычки и escape-последовательности вместо невидимых управляющих символов. Именно поэтому `repr()` помогает увидеть пробелы, переводы строк и обратные косые черты. Возвращаемое значение остаётся обычной строкой, а не специальным «отладочным объектом».

```python
text = "первая\nвторая"
print(str(text))
print(repr(text))
print(type(repr(text)).__name__)
print(repr(str()))
# Вывод:
# первая
# вторая
# 'первая\nвторая'
# str
# ''
```

Первый `print()` получает строку с настоящим переводом строки, поэтому занимает две строки вывода. Второй получает результат `repr()`: в нём перевод строки показан двумя видимыми знаками `\n`. Кавычки тоже входят в возвращённое представление и потому печатаются. Это объясняет различие между интерактивным показом значения и выводом через `print()`: интерактивная оболочка обычно использует представление, близкое к `repr()`.

```python
number = 42
text = "42"
print(str(number), str(text))
print(repr(number), repr(text))
print(str(b"abc"))
print(b"abc".decode("ascii"))
# Вывод:
# 42 42
# 42 '42'
# b'abc'
# abc
```

По человекочитаемому представлению числа и строки иногда невозможно различить исходные типы. Отладочное представление помогает: у строки появляются кавычки. Вызов `str(b"abc")` показывает представление байтов, включая `b` и кавычки, а декодирование возвращает сам текст `abc`.

Для многих простых встроенных значений `repr()` похож на корректный Python-код, восстанавливающий значение. Но это не универсальная гарантия: некоторые объекты показываются описанием с типом и адресом. Превращать произвольный `repr()` обратно через `eval()` небезопасно и обычно не нужно. Для обмена данными применяют предусмотренные форматы, а не случайные отладочные представления.

**Типичная ошибка** — принимать кавычки, показанные оболочкой, за часть самой строки. **Вопрос коллоквиума:** чем отличаются содержимое строки, результат `repr()` и вывод `print()`? Полный ответ объясняет, что `repr()` и `str()` возвращают строки, а `print()` отправляет полученный текст в поток вывода.

## 40. Строковые литералы: одинарные, двойные и тройные кавычки, пустая строка, неявная конкатенация соседних литералов, отступы в многострочных литералах

**Литерал** — запись значения непосредственно в программе. Строку можно заключить в одинарные или двойные кавычки: выбор сам по себе не меняет тип и содержимое. Удобно выбирать ограничители так, чтобы внутри пришлось меньше экранировать кавычки. Для пустой строки подходят `''` и `""`: между открывающим и закрывающим ограничителями нет ни одного символа.

Тройные одинарные или двойные кавычки позволяют включить в литерал настоящие переводы строк. Они не создают особого многострочного типа: результат по-прежнему `str`. Начальный и конечный переводы строк сохраняются, если находятся внутри ограничителей. Сохраняются и пробелы, которыми текст выровнен в исходном коде.

```python
first = 'Она сказала: "да"'
second = "Это 'пример'"
empty = ""
combined = ("добрый "
            "день")
print(first)
print(second)
print(len(empty))
print(combined)
# Вывод:
# Она сказала: "да"
# Это 'пример'
# 0
# добрый день
```

В круглых скобках соседние литералы автоматически объединяются. Оператор `+` здесь не нужен: соединение выполняется при обработке программы. Этот приём удобен, когда длинное сообщение требуется разнести на несколько строк исходного кода без добавления переводов строк в результат. Пробел между словами нужно записать внутри одного из литералов: пробелы и переносы между самими литералами содержимым не становятся.

```python
from textwrap import dedent

text = """
    первая
    вторая
"""
print(repr(text))
clean = dedent(text).strip("\n")
print(repr(clean))
print("ab" "cd" == "abcd")
# Вывод:
# '\n    первая\n    вторая\n'
# 'первая\nвторая'
# True
```

Вначале вывод видимого представления обнаруживает и отступы, и крайние переводы строк. `dedent()` убирает общий отступ непустых строк, а `strip("\n")` удаляет переводы строк только по краям. Эти операции нужны не всегда: если отступ является частью форматируемого документа, его следует сохранить.

Неявная конкатенация работает с литералами, но не с соседними переменными. Если `a` и `b` — переменные, запись `a b` синтаксически неверна; требуется `a + b` либо другой подход. **Типичная ошибка** — забыть запятую в списке строк: `["один" "два"]` содержит один объединённый элемент. **Вопрос коллоквиума:** чем отличаются перевод строки в исходном коде между соседними литералами и перевод строки внутри тройных кавычек? Первый организует программу, второй становится частью значения.

<a id="topic-41"></a>

## 41. Escape-последовательности: `\n`, `\t`, `\'`, `\"`, `\\`, `\r`, `\b`

**Escape-последовательность** начинается с обратной косой черты и задаёт специальный символ либо способ записать ограничитель. В обычном строковом литерале Python распознаёт её при создании строки. Например, `\n` обозначает перевод строки, `\t` — горизонтальную табуляцию, `\\` — одну обратную косую черту. Последовательности `\'` и `\"` позволяют включить соответствующие кавычки без преждевременного завершения литерала.

Нужно различать запись и результат: `"\n"` содержит один символ, а `"\\n"` — обратную косую черту и букву `n`. Когда требуется понять содержимое без влияния терминала, полезно применять `repr()`. Это особенно важно для управляющих символов: они не обязаны выглядеть как печатные знаки.

```python
text = "А\nБ\tВ"
print(text)
print(repr(text))
print(len("\n"), len("\\n"))
print('Он сказал: \'да\'')
print("Путь: C:\\tmp")
# Вывод:
# А
# Б	В
# 'А\nБ\tВ'
# 1 2
# Он сказал: 'да'
# Путь: C:\tmp
```

Во второй строке фактического вывода между буквами `Б` и `В` находится символ табуляции, а не заданное количество пробелов. Табуляция переводит позицию к следующей табуляционной границе; ширина отображения зависит от средства просмотра. Поэтому она неудобна для строго выровненных таблиц: для них лучше задавать ширину и выравнивание явно.

```python
carriage = "abc\rXY"
backspace = "abc\bX"
print(repr(carriage))
print(repr(backspace))
print([ord(char) for char in "\r\b"])
print("Она сказала: \"да\"")
# Вывод:
# 'abc\rXY'
# 'abc\x08X'
# [13, 8]
# Она сказала: "да"
```

Символ `\r` — возврат каретки: в обычном терминале он возвращает позицию к началу текущей строки. Символ `\b` — возврат на одну позицию назад. Ни один из них не удаляет предшествующие элементы из объекта `str`. Терминал может визуально перезаписать часть текста после перемещения позиции, но длина и содержимое строки от этого не меняются. Во втором примере они показаны через `repr()`, поэтому результат не зависит от поведения курсора.

Не следует рассчитывать на неизвестные escape-последовательности вроде случайного `\q`: такие записи не являются хорошим способом хранить обратную косую черту и могут сопровождаться предупреждениями. Нужно писать `\\` либо осознанно использовать raw-литерал. **Типичная ошибка** — указать путь `"C:\new"` и неожиданно получить перевод строки. **Вопрос коллоквиума:** почему `\b` не равнозначен удалению последней буквы строки? Он задаёт управляющий символ, а не операцию изменения объекта.

## 42. r-строки

**Raw-строка** создаётся литералом с префиксом `r` или `R`. Слово raw означает, что обратные косые черты в основном сохраняются буквально, а не запускают обычное преобразование escape-последовательностей. Это удобно для регулярных выражений, фрагментов документации и некоторых путей. После создания никакого отдельного типа raw-строки нет: результат является обычным `str`, и методы работают с ним точно так же, как с другими строками.

Сравним перевод строки и два печатных знака. В обычном литерале `"\n"` Python создаёт символ перевода строки. В raw-литерале `r"\n"` сохраняются обратная косая черта и `n`. Запись `repr()` дополнительно экранирует косую черту, чтобы показать её без неоднозначности; это не означает, что количество черт в исходном объекте внезапно удвоилось.

```python
ordinary = "\n"
raw = r"\n"
print(len(ordinary), len(raw))
print(repr(ordinary))
print(repr(raw))
print(r"C:\new\test")
# Вывод:
# 1 2
# '\n'
# '\\n'
# C:\new\test
```

У raw-литералов есть синтаксические ограничения. Главная ловушка: литерал не может завершаться нечётным количеством обратных косых черт перед закрывающей кавычкой. Последняя черта мешает распознать кавычку как завершение. Поэтому запись `r"C:\temp\"` некорректна ещё на этапе разбора программы. В учебном коде ниже ошибка проверяется через `compile()`, чтобы её можно было перехватить, не ломая весь блок.

```python
bad_source = 'path = r"C:\\temp\\"'
try:
    compile(bad_source, "<example>", "exec")
except SyntaxError as error:
    print(type(error).__name__)

path = r"C:\temp" + "\\"
print(path)
print(repr(path))
quoted = r'\"'
print(quoted, len(quoted))
# Вывод:
# SyntaxError
# C:\temp\
# 'C:\\temp\\'
# \" 2
```

Для завершающей черты можно объединить raw-литерал без неё с обычным литералом `"\\"`. Другой вариант — использовать обычную строку и экранировать все обратные косые черты. Обратите внимание на пример с кавычкой: raw-запись позволяет экранировать ограничитель при разборе, но сама обратная косая черта при этом остаётся в содержимом. Следовательно, «raw» не означает «полностью игнорировать правила кавычек».

**Типичная ошибка** — считать префикс `r` средством обработки уже существующей переменной. Это часть синтаксиса литерала, а не функция. **Вопрос коллоквиума:** почему у `r"\n"` длина два, а raw-литерал с одной конечной обратной косой чертой не разбирается? Нужно отдельно объяснить содержимое строки и правила определения её границ.

## 43. f-строки

**F-строка** — строковый литерал с префиксом `f` или `F`, в котором выражения в фигурных скобках вычисляются при выполнении программы. Результаты преобразуются в текст и вставляются в соответствующие места. Это удобный способ сформировать сообщение из постоянных фрагментов и значений переменных. Обычная строка без префикса `f` не подставляет значения: фигурные скобки остаются обычными символами.

Внутри поля допустимо выражение: имя, арифметическая операция, обращение по индексу, вызов функции. Двоеточие вводит спецификацию формата, например число знаков после десятичной точки. Чтобы вывести буквальные фигурные скобки, их удваивают: `{{` и `}}`. Это относится к внешнему тексту f-строки, а не к созданию словаря внутри выражения.

```python
name = "Анна"
count = 3
price = 12.5
print(f"{name}: {count} книги")
print(f"Сумма: {count * price:.2f}")
print(f"{{name}} = {name}")
print("{name}")
# Вывод:
# Анна: 3 книги
# Сумма: 37.50
# {name} = Анна
# {name}
```

Число `37.5` отображается как `37.50`, потому что формат `.2f` требует две цифры после точки. Само числовое значение не меняется: форматирование производит строку. Согласование слова «книги» здесь задано вручную; f-строка не выполняет грамматическое склонение и не переводит текст автоматически.

```python
text = "А\nБ"
value = 7
print(f"{text!r}")
print(f"{value=}")
print(f"{value:04d}")
value = 9
print(f"Теперь {value}")
# Вывод:
# 'А\nБ'
# value=7
# 0007
# Теперь 9
```

Преобразование `!r` вызывает `repr()`, что удобно для диагностики скрытых символов. Отладочная запись `{value=}` показывает и текст выражения, и значение; она доступна в Python 3.10. Формат `04d` выводит целое десятичное число в поле шириной не менее четырёх позиций, заполняя свободное место нулями.

Подстановка выполняется в момент создания строки. Если сохранить `message = f"{value}"`, а затем изменить `value`, сохранённый текст не обновится сам. Нельзя рассматривать f-строку как постоянно связанный с переменной шаблон.

Для совместимости с Python 3.10 выражения внутри полей не должны содержать обратные косые черты; сложные фрагменты лучше заранее вычислять в переменных. Также удобно использовать разные кавычки для внешнего литерала и строк внутри выражения. **Типичная ошибка** — забыть префикс `f`. **Вопрос коллоквиума:** чем `!r` отличается от `.2f`? Первое выбирает представление объекта, второе задаёт формат отображения подходящего значения.

## 44. Строки как последовательности

Строка является **последовательностью**: её элементы упорядочены, их можно получать по индексам, перебирать и выделять срезами. Нумерация начинается с нуля. Отрицательный индекс отсчитывается с конца: `-1` обозначает последний элемент. Индекс должен попадать в существующий диапазон, иначе возникает `IndexError`.

Срез записывается как `text[start:stop:step]`. Начальная граница включается, конечная не включается. Пропущенные границы выбираются с учётом направления обхода. Для положительного шага простая запись `text[a:b]` означает элементы от индекса `a` до индекса перед `b`. В отличие от одиночного индекса, слишком далёкая граница среза обычно не вызывает исключения: она ограничивается длиной строки.

```python
text = "Python"
print(text[0], text[-1])
print(text[1:4])
print(text[:2], text[2:])
print(text[::2])
print(text[::-1])
print(repr(text[20:30]))
# Вывод:
# P n
# yth
# Py thon
# Pto
# nohtyP
# ''
```

Срез `1:4` выбирает индексы `1`, `2`, `3`, а не четыре элемента. В `::2` выбирается каждый второй элемент, начиная с первого. Шаг `-1` даёт обратный порядок. Значение шага не может быть нулём, поскольку тогда нельзя перейти к следующему элементу.

```python
text = "кот"
for index, char in enumerate(text):
    print(index, char)
print("от" in text, "ток" in text)
print("ха" * 3)
try:
    print(text[10])
except IndexError as error:
    print(type(error).__name__)
try:
    print(text[::0])
except ValueError as error:
    print(type(error).__name__)
# Вывод:
# 0 к
# 1 о
# 2 т
# True False
# хахаха
# IndexError
# ValueError
```

Оператор `in` проверяет наличие подстроки, то есть непрерывного фрагмента, а не произвольного набора букв. `enumerate()` выдаёт пары «индекс, элемент» и избавляет от ручного управления счётчиком. Повторение `*` создаёт строку из нескольких копий, а `+` соединяет строки. Срезы и соединение не меняют исходный объект: строки остаются неизменяемыми.

Понятие элемента связано с Unicode-кодовой точкой, а не обязательно с целым визуальным знаком. Поэтому разворот с помощью `[::-1]` может нарушить сложный знак с комбинируемой отметкой. Для обычного слова из отдельных букв пример работает ожидаемо, но не является универсальным алгоритмом зеркального отображения любого текста.

**Типичная ошибка** — обратиться к индексу `len(text)`: последний допустимый неотрицательный индекс равен `len(text) - 1`. **Вопрос коллоквиума:** почему `text[100]` может завершиться исключением, а `text[:100]` возвращает строку? Индекс требует конкретный существующий элемент, а срез описывает диапазон, который Python ограничивает доступными позициями.

## 45. Сравнение строк: `==`, `!=`, `<`, `>`, истинность строк

Равенство `==` проверяет одинаковую последовательность элементов, а `!=` — её различие. Регистр и пробелы учитываются: `"Кот"` и `"кот"` различны, как и `"кот"` и `"кот "`. Для сравнения содержимого используют именно `==`, а не `is`: последний проверяет тождественность объектов и не подходит для обычной задачи сравнения текста.

Операторы `<` и `>` задают лексикографическое сравнение. Python последовательно сравнивает соответствующие Unicode-кодовые точки до первого различия. Если одна строка полностью совпадает с началом другой, более короткая считается меньшей. Это технический порядок, а не полноценная словарная сортировка конкретного языка: регистр, диакритика и национальные правила автоматически не учитываются.

```python
print("кот" == "кот", "Кот" != "кот")
print("abc" < "abd")
print("ab" < "abc")
print("Z" < "a")
print("10" < "2")
print(10 < 2)
# Вывод:
# True True
# True
# True
# True
# True
# False
```

Сравнение `"10" < "2"` истинно, потому что уже первая цифра `1` располагается раньше `2` по коду. Длина и числовой смысл всей записи здесь не анализируются. Если задача числовая, данные нужно сначала корректно преобразовать, например через `int()`, предусмотрев обработку некорректного ввода. Сравнивать строку и число через `<` в Python 3 нельзя: такие объекты не имеют общего встроенного порядка.

```python
for text in ("", " ", "0", "False"):
    print(repr(text), bool(text))

try:
    print("2" < 10)
except TypeError as error:
    print(type(error).__name__)
print(bool("   ".strip()))
# Вывод:
# '' False
# ' ' True
# '0' True
# 'False' True
# TypeError
# False
```

**Истинность строки** определяется только её пустотой. Пустая строка ложна, любая непустая истинна, даже если содержит пробел, текст `False` или цифру `0`. Поэтому условие `if text:` отвечает на вопрос «есть ли хотя бы один элемент», а не «есть ли содержательный текст». Для проверки непустого текста после удаления крайних пробельных символов часто используют `if text.strip():`.

Визуально одинаковые Unicode-записи тоже могут различаться: готовая буква с диакритикой и комбинация базовой буквы с отдельным знаком не обязательно равны как последовательности. При необходимости текст предварительно нормализуют, но обычное сравнение само этого не делает.

**Типичная ошибка** — считать, что `"False"` ведёт себя как логическое `False`. **Вопрос коллоквиума:** как связаны лексикографический порядок и истинность? Никак: первый сравнивает содержимое двух строк, вторая проверяет пустоту одного объекта.

## 46. Способы форматирования строк: f-строки, `str.format()`, оператор `%`

**Форматирование** превращает значения в текст по шаблону. В Python часто встречаются три способа: f-строки, метод `str.format()` и оператор `%`. Для нового простого кода обычно удобны f-строки: рядом видны и текст, и выражения. Метод `format()` полезен, когда шаблон хранится отдельно от значений. Форматирование через `%` важно уметь читать в существующих программах.

У f-строк поля содержат выражения. У `format()` фигурные скобки обозначают позиции или имена аргументов, переданных методу. В обоих способах после двоеточия используется близкая мини-система описания формата. Но обычная строка-шаблон сама не вычисляет произвольные выражения как f-строка: заполнение происходит только при явном вызове метода.

```python
name = "Ира"
score = 8.25
print(f"{name}: {score:.1f}")
print("{}: {:.1f}".format(name, score))
print("%s: %.1f" % (name, score))
print("{who}: {points:.1f}".format(who=name, points=score))
# Вывод:
# Ира: 8.2
# Ира: 8.2
# Ира: 8.2
# Ира: 8.2
```

Все варианты создают одинаковый текст. Число `8.25` при выводе с одним знаком округляется до `8.2`: в этом примере половинный случай приводит к чётной последней цифре. В общем случае особенности двоичного представления `float` тоже влияют на результат, поэтому форматирование нельзя описывать как «просто отрезать хвост».

```python
template = "{0} + {0} = {1}"
print(template.format(3, 6))
print("{{{}}}".format("текст"))
print("%s: %03d; %%" % ("номер", 7))
try:
    print("{missing}".format(name="Ира"))
except KeyError as error:
    print(type(error).__name__)
# Вывод:
# 3 + 3 = 6
# {текст}
# номер: 007; %
# KeyError
```

Позиция `{0}` может использоваться несколько раз. В шаблоне `format()` удвоенные фигурные скобки дают буквальные скобки. У оператора `%` буквальный знак процента записывается как `%%`, `%s` отвечает за строковое представление, а `%03d` — за десятичное целое шириной не менее трёх позиций с нулевым заполнением.

Число и типы переданных значений должны соответствовать шаблону. Неизвестное имя поля вызывает исключение, а неверный числовой формат может привести к `ValueError` или `TypeError`. Шаблоны форматирования не заменяют безопасную параметризацию SQL-запросов и другие специализированные механизмы: красивый текст ещё не означает безопасную команду.

**Типичная ошибка** — смешать синтаксис способов, например передать `%s` в `format()` и ожидать подстановку. **Вопрос коллоквиума:** когда f-строка вычисляет поля, а когда работает `format()`? Первая — при выполнении литерала, второй — при явном вызове метода с аргументами.

## 47. Форматирование чисел: тип `f` и точность, проценты, разделители разрядов, ширина, нули слева, округление

Числовая спецификация управляет тем, **как значение показывается**, а не изменяет исходное число. Тип `f` задаёт запись с фиксированной десятичной точкой. Точность `.2f` означает ровно две цифры после точки; при необходимости добавляются нули или выполняется округление. В русском тексте обычно ожидается запятая, однако обычный формат `f` использует точку и не выбирает национальные правила автоматически.

Тип `%` в мини-языке форматирования умножает значение на сто для представления и добавляет знак процента. Например, доля `0.125` превращается в `12.5%` при точности один знак. Здесь процент — именно тип формата после двоеточия, а не старый оператор форматирования строк.

```python
number = 12345.678
share = 0.125
print(f"{number:.2f}")
print(f"{share:.1%}")
print(f"{number:,.2f}")
print(f"{number:_.2f}")
print(f"|{7:5d}|")
print(f"{7:05d}")
# Вывод:
# 12345.68
# 12.5%
# 12,345.68
# 12_345.68
# |    7|
# 00007
```

Запятая и подчёркивание группируют разряды. Ширина `5` обозначает минимальную общую ширину результата, а не количество цифр и не точность. Если значение длиннее, оно не обрезается. Формат `05d` задаёт нулевое заполнение целого; для отрицательного числа нули размещаются после знака, что отличается от простого добавления нулей слева ко всей строке.

```python
from decimal import Decimal, ROUND_HALF_UP

value = 2.675
print(f"{value:.2f}")
print(round(2.5), round(3.5))
print(f"{-7:05d}")
print(f"|{123456:3d}|")
money = Decimal("2.675").quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)
print(money)
print(value)
# Вывод:
# 2.67
# 2 4
# -0007
# |123456|
# 2.68
# 2.675
```

Значение `float` хранится в двоичной системе и часто лишь приближённо соответствует десятичной записи. Поэтому `2.675` при форматировании до сотых даёт `2.67`. Функция `round()` для точно представимых половинных случаев использует округление к ближайшему чётному результату: `2.5` даёт `2`, а `3.5` — `4`. Это не ошибка и не правило «всегда вниз».

Если требуется конкретное правило десятичного округления, используют `Decimal`, создавая его из строки, и явно задают режим. В примере `ROUND_HALF_UP` округляет половинный случай в сторону увеличения абсолютного значения. Исходная переменная `value` не меняется ни от форматирования, ни от отдельного вычисления `money`.

**Типичная ошибка** — путать `.2f` с двумя значащими цифрами или ожидать, что ширина отрежет длинное число. **Вопрос коллоквиума:** почему визуальное округление не заменяет выбор корректного числового типа для денежных расчётов? Формат отвечает за представление, а ошибки накопления и правила арифметики определяются типом и алгоритмом вычислений.

## 48. Выравнивание строк: `ljust()`, `rjust()`, `center()`

Методы `ljust(width)`, `rjust(width)` и `center(width)` создают строку не короче указанной ширины. Первый прижимает исходный текст к левому краю, второй — к правому, третий размещает по центру. Свободные позиции по умолчанию заполняются пробелами. Вторым аргументом можно передать другой символ заполнения.

Это операции над текстом, а не команды терминалу. Они не перемещают уже напечатанный курсор и не знают ширину окна. Метод возвращает результат, который следует сохранить или передать в `print()`. Исходная строка не меняется. Чтобы увидеть крайние пробелы в учебном примере, полезно окружить результат вертикальными чертами.

```python
text = "кот"
print("|" + text.ljust(7) + "|")
print("|" + text.rjust(7) + "|")
print("|" + text.center(7) + "|")
print(text.ljust(7, "."))
print(text.rjust(7, "0"))
# Вывод:
# |кот    |
# |    кот|
# |  кот  |
# кот....
# 0000кот
```

Ширина означает размер результата в элементах строки. Для слова длиной три и поля шириной семь нужно четыре заполнителя. При центрировании в этом примере они распределяются поровну. Если свободных мест нечётное количество, абсолютно симметричный результат невозможен: одна сторона получает на один заполнитель больше. Не стоит строить алгоритм на визуальном предположении о том, какая именно сторона будет длиннее; если это важно по условию, количество заполнителей лучше вычислять явно.

```python
text = "длинное"
print(text.ljust(3, "."))
print("-7".rjust(5, "0"))
print(f"{-7:05d}")
try:
    print("кот".center(8, "--"))
except TypeError as error:
    print(type(error).__name__)
print(len("кот".center(9, ".")))
# Вывод:
# длинное
# 000-7
# -0007
# TypeError
# 9
```

Если исходный текст длиннее заданного поля, методы возвращают его без обрезания. Для ограничения длины нужен отдельный срез или специально выбранная спецификация формата. Заполнитель обязан быть строкой ровно из одного символа; `"--"` не подходит. Сравнение отрицательного числа показывает важную границу применения: `rjust()` не распознаёт знак числа, а числовое форматирование распознаёт.

Методы считают кодовые точки, а не экранные колонки. Табуляция, комбинируемые знаки, некоторые иероглифы и эмодзи могут отображаться с иной визуальной шириной. Поэтому для простых учебных таблиц методы подходят, но для произвольного Unicode-текста в терминале может понадобиться специальный подсчёт экранной ширины.

**Типичная ошибка** — написать `text.ljust(10)` без присваивания и ожидать изменения переменной. **Вопрос коллоквиума:** в чём различие между минимальной шириной поля и обрезанием? Выравнивание только добавляет заполнители при недостаточной длине, но не удаляет существующий текст.

## 49. Методы изменения регистра: `lower()`, `upper()`

Метод `lower()` создаёт строку, в которой регистровые буквы приведены к нижнему регистру. Метод `upper()` приводит их к верхнему. Цифры, пробелы и знаки без регистра обычно сохраняются. Эти методы учитывают Unicode, поэтому работают не только с латинскими буквами: русский текст тоже преобразуется.

Поскольку строки неизменяемы, метод возвращает результат, а не исправляет объект на месте. Если результат нужен дальше, следует написать `text = text.lower()` или сохранить его под другим именем. Вызов без сохранения полезен только тогда, когда результат сразу используется, например передаётся в `print()` или сравнивается с другой строкой.

```python
text = "ПрИвЕт, Python 3!"
print(text.lower())
print(text.upper())
print(text)
normalized = text.lower()
print(normalized.startswith("привет"))
# Вывод:
# привет, python 3!
# ПРИВЕТ, PYTHON 3!
# ПрИвЕт, Python 3!
# True
```

Такое преобразование удобно при проверке команд, когда регистр не имеет значения по условию задачи. Например, команды `ДА`, `Да` и `да` можно заранее привести к одному виду. Однако это осознанное правило программы: не всякий текст допустимо менять. Пароли, идентификаторы во внешних системах и пользовательские данные могут быть регистрозависимыми.

```python
text = "Straße"
upper = text.upper()
print(upper)
print(len(text), len(upper))
print(upper.lower())
print(text.lower() == "STRASSE".lower())
print(text.casefold() == "STRASSE".casefold())
# Вывод:
# STRASSE
# 6 7
# strasse
# False
# True
```

Преобразование регистра не обязательно сохраняет длину: немецкая буква `ß` в верхнем регистре превращается в `SS`. Следовательно, цепочка `upper().lower()` не обязана восстанавливать исходный текст. Нельзя также предполагать, что индекс символа до преобразования всегда указывает на соответствующую букву после него.

Для более полного безрегистрового сопоставления Unicode-текста существует `casefold()`. Он показан как уточнение: обычный `lower()` и операция, специально предназначенная для безрегистрового сравнения, решают близкие, но не одинаковые задачи. Даже `casefold()` не является полным механизмом учёта всех национальных правил поиска и сортировки; требования конкретной задачи всё равно нужно определить заранее.

Вызов методов не меняет кодировку файла, не переводит слова на другой язык и не исправляет орфографию. Это именно преобразование регистра символов. **Типичная ошибка** — ожидать, что после `name.upper()` переменная `name` уже содержит верхний регистр. **Вопрос коллоквиума:** почему `upper()` может изменить длину строки и почему операция не обязана быть обратимой? Unicode-преобразование может сопоставлять одному исходному знаку несколько результирующих.

## 50. Методы проверки строк: `islower()`, `isupper()`, `isalpha()`, `isdigit()`, `isalnum()`, `isspace()`

Эти методы проверяют свойство строки и возвращают `bool`. `isalpha()` означает, что строка непуста и состоит из букв. `isdigit()` проверяет цифровые символы Unicode, а не только ASCII-цифры от `0` до `9`. `isalnum()` допускает буквенные и числовые символы Unicode. `isspace()` проверяет, что непустая строка целиком состоит из пробельных символов, включая не только обычный пробел, но, например, табуляцию и перевод строки.

`islower()` и `isupper()` устроены иначе, чем «каждый символ обязан быть строчной или прописной буквой». Они требуют наличия хотя бы одного регистрового символа и проверяют регистр всех таких символов. Цифры и знаки препинания не мешают проверке, поскольку регистра у них нет. Но строка только из цифр не проходит ни одну из двух проверок.

```python
print("кот".isalpha(), "кот2".isalpha())
print("кот2".isalnum(), "кот-2".isalnum())
print("abc123!".islower(), "ABC123!".isupper())
print("123".islower(), "123".isupper())
print(" \t\n".isspace(), "".isspace())
print("".isalpha(), "".isdigit(), "".isalnum())
# Вывод:
# True False
# True False
# True True
# False False
# True False
# False False False
```

Пустая строка для всех перечисленных методов даёт `False`. В частности, неверно рассуждать, что пустая строка «не содержит ничего недопустимого» и потому должна считаться числом или словом: встроенные проверки дополнительно требуют соответствующего содержимого.

```python
for text in ("123", "١٢", "²", "-12", "1.5"):
    print(repr(text), text.isdigit())
    try:
        print(int(text))
    except ValueError as error:
        print(type(error).__name__)
print("123".isascii() and "123".isdigit())
print("١٢".isascii() and "١٢".isdigit())
# Вывод:
# '123' True
# 123
# '١٢' True
# 12
# '²' True
# ValueError
# '-12' False
# -12
# '1.5' False
# ValueError
# True
# False
```

Главный нюанс: `isdigit()` не эквивалентен успешности `int()`. Арабско-индийские десятичные цифры принимаются обеими операциями. Надстрочная двойка считается цифровым символом, но `int("²")` её не принимает. Наоборот, строка со знаком минуса может быть допустима для `int()`, хотя `isdigit()` вернёт `False`. Для проверки возможности преобразования надёжнее пробовать преобразование и обрабатывать `ValueError`, одновременно учитывая допустимый синтаксис задачи.

Если нужны строго непустые ASCII-цифры, удобно сочетание `text.isascii() and text.isdigit()`. Для идентификаторов с буквами и цифрами следует отдельно решить, допустимы ли подчёркивания: `isalnum()` их не допускает. Проверка принадлежности символов и проверка допустимого значения также различаются. Даже успешно преобразованное целое может оказаться отрицательным, слишком большим или не входить в разрешённый диапазон. Например, для возраста обычно нужны и преобразование, и отдельное сравнение с границами. Один строковый метод не способен заменить все правила предметной области.

Полезно строить обработку по этапам: сначала определить, разрешены ли крайние пробелы, затем выполнить нужное преобразование, после него проверить диапазон. В таком порядке каждое действие имеет понятную цель. Если вместо этого подряд применять много методов без сформулированного правила, можно случайно принять недопустимые данные или отвергнуть корректные. В частности, предварительное удаление знака минуса только ради успешного `isdigit()` меняет смысл записи и потому не является универсальной проверкой числа.

**Типичная ошибка** — использовать `isdigit()` как универсальную проверку любого числа, включая отрицательные и дробные. **Вопрос коллоквиума:** приведите строку, у которой `isdigit()` истинно, но `int()` вызывает исключение, и объясните, почему противоречия здесь нет.

## 51. Методы очистки строк: `strip()`, `lstrip()`, `rstrip()`, `replace()`, `removeprefix()`, `removesuffix()`

Очистка текста включает разные операции, которые нельзя смешивать. `strip()` удаляет подходящие символы с обоих краёв, `lstrip()` — только слева, `rstrip()` — только справа. Без аргумента удаляются пробельные символы Unicode. Внутренние пробелы эти методы не затрагивают. Все они возвращают строку и не изменяют исходный объект.

Если передан аргумент `chars`, он задаёт **набор отдельных удаляемых символов**, а не цельный префикс или суффикс. Метод последовательно движется от края, пока встречает любой символ из набора. Как только встречен неподходящий символ, удаление с этого края прекращается. Порядок символов в аргументе не задаёт порядок удаления.

```python
text = " \tкот  пёс\n"
print(repr(text.strip()))
print(repr(text.lstrip()))
print(repr(text.rstrip()))
print("cabbaXYab".strip("abc"))
print("abacus".lstrip("ab"))
print("abacus".removeprefix("ab"))
# Вывод:
# 'кот  пёс'
# 'кот  пёс\n'
# ' \tкот  пёс'
# XY
# cus
# acus
```

В `abacus` метод `lstrip("ab")` удаляет `a`, затем `b`, затем ещё одно `a`: все три входят в набор. Метод `removeprefix("ab")` удаляет только один точный начальный фрагмент и оставляет следующую `a`. Это принципиально разные задачи. По той же причине `rstrip(".txt")` не является корректной заменой удаления расширения `.txt`.

```python
filename = "report.txt"
print(filename.removesuffix(".txt"))
print("text".rstrip(".txt"))
print("text".removesuffix(".txt"))
print("prefix_prefix_name".removeprefix("prefix_"))
print("a-b-a".replace("a", "X"))
print("a-b-a".replace("a", "X", 1))
print("имя".removeprefix("нет"))
# Вывод:
# report
# te
# text
# prefix_name
# X-b-X
# X-b-a
# имя
```

Методы `removeprefix()` и `removesuffix()` удаляют одно точное вхождение на соответствующем краю. Если совпадения нет, содержимое остаётся прежним; искать фрагмент в середине они не будут. Эти методы доступны в Python 3.10 и не требуют новых версий.

`replace(old, new)` заменяет все неперекрывающиеся вхождения подстроки, а необязательный третий аргумент ограничивает количество замен. Замена может происходить в любом месте, поэтому `replace()` опасно использовать для удаления только расширения или служебного префикса: одинаковый фрагмент внутри имени тоже изменится. Поиск и замена чувствительны к регистру.

**Типичная ошибка** — писать `path.strip("/home/")`, рассчитывая удалить только каталог `/home/`. На самом деле получится удаление любых перечисленных символов по краям. **Вопрос коллоквиума:** какой метод выбрать для удаления точно одного начального `https://` и почему `lstrip()` для этого не подходит? Правильный выбор — `removeprefix()`, поскольку нужен цельный фрагмент, а не набор допустимых символов.

## 52. Методы `split()` и `join()`

Метод `split()` разбивает строку на части и возвращает список строк. Без аргумента он использует серии пробельных символов как разделители: последовательные пробелы, табуляции и переводы строк объединяются, а пустые фрагменты по краям не создаются. Это удобно для выделения слов из простого текста.

При явном разделителе, например `split(",")`, правила другие: разделителем является точная подстрока, соседние разделители образуют пустые элементы, а разделитель на краю даёт пустой крайний элемент. Подстрока-разделитель может состоять из нескольких символов, но не может быть пустой. Такой разбор не равнозначен полноценному анализу CSV: кавычки и экранирование метод самостоятельно не понимает.

```python
text = "  кот\tпёс\nлиса  "
print(text.split())
print("a,,b,".split(","))
print("  a  b  ".split(" "))
print("".split())
print("".split(","))
print("a=b=c".split("=", 1))
# Вывод:
# ['кот', 'пёс', 'лиса']
# ['a', '', 'b', '']
# ['', '', 'a', '', 'b', '', '']
# []
# ['']
# ['a', 'b=c']
```

Аргумент `maxsplit` ограничивает число разбиений, а не число получаемых элементов: одно разбиение даёт максимум две части. Поэтому `split("=", 1)` удобно отделяет имя параметра от всего оставшегося значения, даже если дальше встречаются новые знаки равенства. Для полного разбиения ограничение можно не указывать. Перед выбором разделителя важно сформулировать структуру данных. Если строка представляет обычное предложение, пробельное разбиение часто достаточно. Если в строке записаны поля, пустой элемент может иметь смысл: отсутствующее отчество или незаполненная колонка. В таком случае удалять пустые элементы автоматически нельзя — вместе с ними потеряется положение последующих полей. По этой причине результат `split()` следует интерпретировать в контексте формата, а не считать любой полученный список готовыми правильными данными.

```python
words = ["кот", "пёс", "лиса"]
print(" | ".join(words))
print("".join(["П", "и", "т", "о", "н"]))
print("-".join("abc"))
print(",".join(str(number) for number in [1, 2, 3]))
try:
    print(",".join([1, 2]))
except TypeError as error:
    print(type(error).__name__)
try:
    print("abc".split(""))
except ValueError as error:
    print(type(error).__name__)
# Вывод:
# кот | пёс | лиса
# Питон
# a-b-c
# 1,2,3
# TypeError
# ValueError
```

Метод `join()` вызывается у **разделителя**, а не у списка. Он вставляет строку-разделитель между соседними элементами итерируемого объекта. Все элементы должны быть строками: автоматического вызова `str()` для чисел нет. Генератор в примере явно преобразует числа перед объединением.

Строка сама итерируема, поэтому `"-".join("abc")` вставляет разделитель между буквами. Для пустого набора элементов результатом будет пустая строка, а для одного элемента разделитель вообще не появляется. В отличие от постепенного наращивания результата в цикле, `join()` сразу выражает намерение собрать текст из готовых частей.

**Типичная ошибка** — ожидать, что `split()` и `split(" ")` всегда одинаковы. **Вопрос коллоквиума:** можно ли восстановить исходное количество пробелов после `" ".join(text.split())`? Нет: разбиение без явного разделителя потеряло информацию о пробельных сериях и крайних пробелах.

## 53. Методы поиска в строках: `startswith()`, `endswith()`, `find()`, `rfind()`, `index()`, `rindex()`

Поиск начинается с выбора требуемого результата. Если нужно узнать, начинается или заканчивается ли строка определённым фрагментом, используют `startswith()` и `endswith()`. Они возвращают `bool`, не удаляют найденный фрагмент и чувствительны к регистру. В качестве проверяемого значения можно передать кортеж строк: результат будет истинным при совпадении хотя бы с одной из них.

Если нужна позиция подстроки, подходят `find()` и `index()`. Оба ищут первое вхождение слева и возвращают индекс его начала. Разница проявляется при отсутствии совпадения: `find()` возвращает `-1`, а `index()` вызывает `ValueError`. Методы `rfind()` и `rindex()` выбирают последнее вхождение, но возвращают обычный индекс от начала строки, а не отрицательную позицию от конца.

```python
text = "abracadabra"
print(text.startswith("abra"), text.endswith("abra"))
print("photo.png".endswith((".jpg", ".png")))
print(text.find("abra"), text.rfind("abra"))
print(text.index("cad"), text.rindex("a"))
print(text.find("xyz"))
print(text.find("a", 1, 5))
# Вывод:
# True True
# True
# 0 7
# 4 10
# -1
# 3
```

Дополнительные аргументы `start` и `end` ограничивают область поиска; конечная граница не включается. Возвращаемая позиция всё равно относится к исходной строке. В последней строке поиск идёт в диапазоне индексов от `1` до `4`, и подходящая буква обнаруживается на исходной позиции `3`.

```python
text = "кот и пёс"
position = text.find("кот")
print(position)
print(bool(position), position != -1)
missing = text.find("лиса")
print(bool(missing), missing != -1)
try:
    print(text.index("лиса"))
except ValueError as error:
    print(type(error).__name__)
print("пёс" in text)
print(text.startswith("пёс", 6))
# Вывод:
# 0
# False True
# True False
# ValueError
# True
# True
```

Проверка `if text.find(part):` ошибочна сразу в двух направлениях. Успешное совпадение в позиции `0` считается ложным, а отсутствие с результатом `-1` — истинным. Поэтому результат сравнивают с `-1` либо, если позиция не нужна, используют `part in text`. Условие наличия подстроки и её позиция — разные виды информации.

Отрицательный результат нельзя без проверки применять как индекс: `text[-1]` является допустимым доступом к последнему символу, а не сообщением об отсутствии. Поиск также не выполняет нормализацию Unicode и не игнорирует регистр автоматически; если задача требует такого поведения, подготовка текста должна быть явной.

**Типичная ошибка** — ожидать от `rfind()` индекс вроде `-1`, `-2` при успешном поиске справа. **Вопрос коллоквиума:** когда предпочтительнее `index()`, а когда `find()`? Первый удобен, если отсутствие нарушает ожидаемое условие и обрабатывается исключением; второй — если отсутствие является обычным вариантом результата.

## 54. Моржовый оператор `:=`: отличие от `=`, области применения, приоритет и ограничения

**Выражение присваивания** `name := expression` вычисляет правую часть, связывает результат с именем и одновременно возвращает это значение как результат выражения. Обычное присваивание `name = expression` является инструкцией и само не используется в качестве значения внутри другого выражения. Моржовый оператор нужен не для сокращения любого присваивания, а там, где вычисленное значение требуется сразу проверить и затем повторно использовать.

Типичные применения — получение результата поиска, вычисление длины, чтение очередной порции данных. Если выражение дорогое или имеет побочный эффект, сохранение результата также позволяет избежать повторного выполнения. Но чрезмерно сложное условие хуже читается: отдельное присваивание часто яснее и остаётся полностью правильным решением.

```python
text = "  кот  "
if (clean := text.strip()):
    print(clean)
    print(len(clean))
print(clean)

if (size := len("Python")) > 3:
    print(size)
# Вывод:
# кот
# 3
# кот
# 6
```

Круглые скобки подчёркивают границы выражения. В первом условии в `clean` попадает строка, а уже затем проверяется её истинность. Имя доступно после `if`, потому что условный оператор не создаёт отдельную локальную область видимости. Во втором условии сначала сохраняется длина, затем она сравнивается с числом.

```python
text = "abc"
if size := len(text) > 2:
    print(size, type(size).__name__)
if (size := len(text)) > 2:
    print(size, type(size).__name__)

value = (number := 4) + 1
print(number, value)
# Вывод:
# True bool
# 3 int
# 4 5
```

Приоритет `:=` ниже, чем у сравнений и логических операторов `and` и `or`, поэтому без внутренних скобок в первом условии присваивается результат `len(text) > 2`, то есть `True`, а не длина. Приоритет выше, чем у запятой; для кортежей это тоже требует внимания к скобкам. Надёжный стиль — явно заключать присваивание в скобки, если его значение является частью более сложного выражения.

```python
sources = [
    "x := 1",
    "(items[0] := 1)",
    "(obj.attr := 1)",
    "(a, b := (1, 2))",
]
for source in sources:
    try:
        compile(source, "<example>", "exec")
    except SyntaxError as error:
        print(type(error).__name__)
    else:
        print("допустимо")

print((pair := (1, 2)))
# Вывод:
# SyntaxError
# SyntaxError
# SyntaxError
# допустимо
# (1, 2)
```

Цель `:=` — одно простое имя: нельзя присваивать атрибуту, элементу или распаковывать кортеж целей. Последняя проверяемая запись допустима синтаксически, но не означает распаковку: это кортеж из выражения `a` и выражения присваивания `b`. Его выполнение без определения `a` вызвало бы `NameError`; здесь проверяется только разбор, поэтому код не исполняется. Для сохранения всего кортежа подходит `(pair := (1, 2))`.

Отдельная тонкость относится к вызову функции. Запись `print(x=1)` передаёт именованный аргумент `x`, а не выполняет присваивание локальной переменной. Выражение `print(x := 1)` сохраняет значение в `x` и передаёт его как позиционный аргумент. Эти конструкции похожи внешне, но имеют совершенно разный смысл. Если нужно передать выражение присваивания именно как значение именованного аргумента, его заключают в скобки, например `sorted([3, 1], reverse=(flag := True))`. При изучении оператора полезнее сначала разобрать простые условия, а не объединять несколько новых правил в одной строке.

Без скобок оператор запрещён, например, как отдельная инструкция; в ряде других контекстов скобки также обязательны. Включения имеют дополнительные ограничения: нельзя переназначать через `:=` переменную их обхода или применять его в итерируемой части включения. **Типичная ошибка** — незаметно сохранить логический результат вместо исходного значения. **Вопрос коллоквиума:** почему скобки в `if (n := len(text)) > 0:` существенны для значения `n`, хотя условие может вести себя похоже и без них?

## 55. Конструкция `match`-`case`: отличие от `switch`, виды образцов

`match` выполняет **структурное сопоставление с образцом**. Сначала вычисляется сопоставляемое значение, затем ветви `case` проверяются сверху вниз. Выполняется первая подходящая ветвь, чей дополнительный guard, если он есть, истинен. Проваливания в следующую ветвь, характерного для некоторых реализаций `switch`, нет; `break` для завершения ветви не требуется. Если ничего не подошло, выполнение продолжается после всей конструкции.

В отличие от простого переключателя по равенству, `match` умеет проверять форму объекта и извлекать части. **Литеральный образец** `case "start":` сравнивает с указанным значением. **Захватывающий образец** `case name:` не сравнивает со старой переменной `name`, а связывает это имя с найденным значением. Поэтому одиночное имя без квалификации нельзя использовать как обозначение заранее заданной константы. Для именованной константы подходит квалифицированное имя, например `Commands.START`, либо проверка в guard.

```python
def describe(command):
    match command:
        case "start" | "run":
            return "запуск"
        case "stop":
            return "остановка"
        case other:
            return f"неизвестно: {other}"

for command in ("run", "stop", "help"):
    print(describe(command))
# Вывод:
# запуск
# остановка
# неизвестно: help
```

Образец с `|` — **OR pattern**: подходит любая из альтернатив. Если альтернативы захватывают имена, каждая должна связывать одинаковый набор имён; иначе возникает `SyntaxError`. Безусловный захват имени, как `case other`, должен завершать последовательность обычных ветвей, поскольку иначе следующие окажутся недостижимыми. Специальное имя `_` — подстановочный образец: совпадает с любым значением и ничего не связывает. При этом ранее существовавшая переменная `_` не удаляется.

```python
def describe(value):
    match value:
        case ["sum", left, right] if isinstance(left, int) and isinstance(right, int):
            return left + right
        case [head, *tail]:
            return f"голова={head}, хвост={tail}"
        case {"name": name, "age": age} if age >= 18:
            return f"взрослый: {name}"
        case _:
            return "не подошло"

print(describe(["sum", 2, 3]))
print(describe(("a", "b", "c")))
print(describe({"name": "Анна", "age": 20, "city": "Омск"}))
print(describe("abc"))
# Вывод:
# 5
# голова=a, хвост=['b', 'c']
# взрослый: Анна
# не подошло
```

**Sequence pattern** `[head, *tail]` разбирает подходящую последовательность; хвост собирается в список. Квадратные скобки образца не означают обязательный тип `list`: кортеж тоже подходит. Однако строки, `bytes` и `bytearray` не разбираются такими образцами как последовательности. **Mapping pattern** проверяет наличие указанных ключей: дополнительные ключи разрешены; их можно собрать через `**rest`. Ключи образца не являются обычными захватывающими переменными.

**Guard** после `if` проверяется только после структурного совпадения и получения нужных имён. Ложный guard разрешает перейти к следующей ветви. Исключения внутри guard не превращаются автоматически в несовпадение: условия должны учитывать допустимые типы. Здесь словари во входных примерах имеют числовой возраст.

```python
from dataclasses import dataclass

@dataclass
class Point:
    x: int
    y: int

def locate(value):
    match value:
        case Point(0, y):
            return f"ось Y: {y}"
        case Point(x=x, y=y) if x == y:
            return f"диагональ: {x}"
        case ("left", item) | ("right", item):
            return f"элемент: {item}"
        case _:
            return "другое"

for value in (Point(0, 5), Point(3, 3), ("right", 7), 0):
    print(locate(value))

_ = "сохранено"
match 123:
    case _:
        print(_)
# Вывод:
# ось Y: 5
# диагональ: 3
# элемент: 7
# другое
# сохранено
```

**Class pattern** проверяет принадлежность классу и сопоставляет атрибуты; он не создаёт новый объект. Именованные поля обращаются к атрибутам, а позиционные зависят от `__match_args__`, который для обычной `dataclass` формируется автоматически. Образец `Point(0, y)` поэтому проверяет `x` и захватывает `y`. Конструкция `pattern as name` дополнительно позволяет сохранить целиком значение, прошедшее вложенный образец.

Литеральные образцы включают также числа и значения `None`, `True`, `False`. Для последних трёх используется проверка тождественности соответствующему одиночному объекту, а не обычное числовое равенство. Это важно, потому что в обычном сравнении `True == 1` истинно, но `case True` предназначен именно для логического значения. Наборы и произвольные итераторы не становятся sequence-образцами только потому, что их можно перебирать: структурное сопоставление имеет свои правила допустимых объектов.

Сопоставление не создаёт отдельной области видимости для захваченных имён. После успешной ветви они могут оставаться доступны в окружающей функции. Но нельзя полагаться на состояние частично захваченных имён после неуспешного сопоставления: такие детали не следует использовать как механизм передачи данных. Лучше получать окончательный результат внутри выбранной ветви и возвращать его явно, как в примерах.

**Типичная ошибка** — написать `case expected:` для сравнения с переменной и случайно получить безусловный захват. **Вопрос коллоквиума:** чем различаются строковый литерал, захватывающее имя, `_` и квалифицированная константа в `case`? В ответе следует различить сравнение, связывание и игнорирование значения, а затем объяснить порядок ветвей и роль guard.

# Занятие 6. Словари и множества

Раздел рассчитан на Python 3.10 и новее. Словари и множества удобно изучать вместе: оба типа используют хеширование, но решают разные задачи. ## 56. Словарь: определение, характеристики, области применения

**Словарь**, или `dict`, — изменяемая коллекция пар «ключ — значение». Ключ играет роль адреса, по которому программа получает связанное значение. В списке адресом обычно служит целочисленный индекс, а в словаре ключ может иметь другой подходящий тип: например, имя человека, код товара или кортеж координат. Значения могут быть объектами любых типов. Один ключ связан ровно с одним значением, но разные ключи вправе иметь одинаковые значения.

Мысленно словарь удобно представить как справочник, а не как последовательность ячеек. Если требуется найти возраст по имени, естественна запись `ages["Анна"]`. Индексировать словарь «по позиции» такая запись не позволяет: число внутри квадратных скобок, если оно используется, тоже является ключом. Словарь изменяем: в него можно добавлять записи, заменять значения и удалять пары без создания нового объекта.

```python
person = {"имя": "Анна", "возраст": 20}
print(person["имя"])
person["возраст"] = 21
person["город"] = "Казань"
print(person["возраст"])
print(list(person))
# Ожидаемый вывод:
# Анна
# 21
# ['имя', 'возраст', 'город']
```

Первое обращение находит значение по строковому ключу. Присваивание по существующему ключу меняет только связанное значение, а присваивание по новому ключу добавляет запись. Начиная с Python 3.7 порядок вставки является гарантией языка. Поэтому ключ `город` оказывается в конце. Эта гарантия действует и в базовой для раздела версии Python 3.10. Однако порядок вставки не означает автоматической сортировки по ключам.

```python
stock = {"ручка": 5, "тетрадь": 5}
print(len(stock))
print(stock == {"тетрадь": 5, "ручка": 5})
print(list(stock.values()))
# Ожидаемый вывод:
# 2
# True
# [5, 5]
```

Длина словаря — количество пар, а не количество различных значений. Равенство обычных словарей проверяет соответствие ключей значениям, но не требует одинакового порядка вставки. Это важное различие: порядок влияет на обход, а равенство характеризует содержимое.

Типовые применения — настройки программы, карточка пользователя, частотный словарь, кеш вычислений, поиск записи по идентификатору. Словарь удобен, когда объект имеет устойчивое обозначение и по нему нужно быстро находить сведения. Для последовательности однотипных записей часто применяют список словарей, а для поиска каждой записи по идентификатору — словарь словарей.

**Типовая ошибка:** считать словарь автоматически отсортированным либо ожидать, что `d[0]` выдаст первую вставленную пару. **Вопрос коллоквиума:** почему два словаря с разным порядком ключей могут быть равны? Потому что порядок обхода и равенство содержимого — разные свойства.

## 57. Хеш-функции и функция `hash()`. Хешируемость: примеры хешируемых и нехешируемых объектов

**Хеш-функция** преобразует объект в целое число — хеш. В Python встроенная функция `hash(obj)` запрашивает хеш объекта. Хеш помогает словарю или множеству выбрать область поиска, после чего для различения подходящих объектов используется проверка равенства. Поэтому хеширование не заменяет сравнение и не превращает объект в уникальный номер.

Объект **хешируем**, если имеет хеш, который не меняется в течение его жизни, и согласованное с ним равенство. Обязательное направление правила: если два хешируемых объекта равны, их хеши тоже равны. Обратное неверно: одинаковые хеши могут принадлежать неравным объектам. Такое совпадение называется коллизией. Python умеет обрабатывать коллизии, поэтому они сами по себе не означают ошибку.

```python
print(hash(7) == hash(7))
print(1 == 1.0)
print(hash(1) == hash(1.0))
print(hash((2, "x")) == hash((2, "x")))
# Ожидаемый вывод:
# True
# True
# True
# True
```

Здесь намеренно не печатаются конкретные хеши строк и кортежей. Для некоторых типов значения хешей рандомизированы между запусками интерпретатора. Гарантия устойчивости относится к жизни объекта, а не к сохранению одного числа между разными процессами, версиями Python или платформами. `hash()` также не является криптографическим алгоритмом: его нельзя использовать вместо защищённого отпечатка файла или средства хранения паролей.

```python
objects = [42, "кот", (1, 2), [1, 2], (1, [2])]
for obj in objects:
    try:
        hash(obj)
        print(type(obj).__name__, "хешируем")
    except TypeError:
        print(type(obj).__name__, "нехешируем")
# Ожидаемый вывод:
# int хешируем
# str хешируем
# tuple хешируем
# list нехешируем
# tuple нехешируем
```

Обычные числа, строки и `frozenset` хешируемы; списки, словари и обычные множества — нет. Для кортежа важны все его компоненты: неизменяемость внешней оболочки недостаточна, если внутри находится нехешируемый список. И наоборот, лозунг «любой изменяемый объект нехешируем» слишком груб: пользовательские классы могут иметь собственные правила. Например, экземпляры обычного класса по умолчанию сравниваются по идентичности и могут быть хешируемыми.

При собственной реализации `__eq__` и `__hash__` необходимо сохранять их согласованность. Нельзя менять поля, участвующие в хеше ключа, пока объект используется в словаре: поиск может перестать работать ожидаемым образом. **Вопрос коллоквиума:** является ли хеш уникальным идентификатором? Нет: коллизии допустимы, а криптографические гарантии отсутствуют.

Практический смысл устойчивости хеша легко увидеть на аналогии с библиотечным каталогом. Если книга помещена в ячейку по некоторому вычисленному адресу, а её адрес затем неожиданно изменился, поиск начнёт смотреть не туда. Поэтому важна не только возможность однажды вызвать `hash()`, но и соблюдение договора на протяжении использования объекта. При этом адрес не обязан быть единственным: несколько кандидатов могут оказаться рядом, и окончательный выбор делается сравнением. Не следует смешивать хеш, идентичность объекта и его значение: это три разных понятия.

## 58. Ключи словаря: требования, повторяющиеся ключи в литерале

Ключ словаря должен быть **хешируемым**. Это позволяет искать запись через хеш-таблицу. Строка подходит, список не подходит, а кортеж подходит только тогда, когда хешируемы его элементы. Требование относится именно к ключу: значением вполне может быть список, словарь или другой изменяемый объект. При выборе ключа полезно спрашивать не только «разрешён ли такой тип», но и «однозначно ли он обозначает нужную сущность».

Если в литерале один ключ записан несколько раз, отдельные записи с ним не сохраняются: последующее значение заменяет предыдущее. Результатом является обычный словарь, а не журнал присваиваний. Это может незаметно уничтожить часть исходных данных, поэтому повторяющиеся ключи в больших литералах стоит рассматривать как подозрительное место.

```python
data = {"x": 10, "y": 20, "x": 30}
print(data)
print(list(data))
try:
    bad = {[1, 2]: "точка"}
except TypeError:
    print("Список не подходит для ключа")
# Ожидаемый вывод:
# {'x': 30, 'y': 20}
# ['x', 'y']
# Список не подходит для ключа
```

Замена значения `x` не перемещает этот ключ в конец: позиция определяется первым добавлением. Ошибка со списком возникает уже при попытке создать словарь, потому что Python не может получить подходящий хеш ключа. Для координат вместо списка можно использовать кортеж из чисел, если координаты должны служить устойчивым адресом.

```python
d = {True: "логическое", 1: "целое", 1.0: "вещественное"}
print(len(d))
print(d[True])
print(d[1])
print(d[1.0])
# Ожидаемый вывод:
# 1
# вещественное
# вещественное
# вещественное
```

`True`, `1` и `1.0` численно равны и имеют согласованные хеши. Поэтому они обозначают одну запись, несмотря на различие типов. Аналогичная ситуация возникает с `False`, `0` и `0.0`. Не следует представлять словарь как таблицу, различающую ключи исключительно по имени типа. Для ключей важна семантика равенства, поддержанная хешированием.

Если предметная область требует различать логический признак и число, можно включить категорию в ключ, например `("bool", True)` и `("int", 1)`. Внешние строки тогда различаются и делают кортежи разными ключами. Это уже сознательная модель данных, а не обход ограничения языка.

**Типовая ошибка:** ожидать три записи для ключей `True`, `1`, `1.0` или разрешать повторяющиеся имена в конфигурации, рассчитывая получить список значений. **Вопрос коллоквиума:** почему одинаковый хеш сам по себе не объединяет разные ключи? Потому что после выбора кандидатов учитывается равенство; коллизия не тождественна совпадению ключей.

## 59. Создание словарей: литерал, словарное включение, `dict()`, `dict.fromkeys()`

Словарь можно создать несколькими способами, и выбор зависит от происхождения данных. **Литерал** `{ключ: значение}` удобен для небольшого заранее известного набора пар. Пустой словарь записывают как `{}` или `dict()`. **Словарное включение** строит пары по правилу: слева от двоеточия вычисляется ключ, справа — значение, а после `for` задаётся источник. Условие `if` позволяет сразу отобрать нужные элементы.

Конструктор `dict()` принимает другой словарь, отображение либо итерируемый объект, выдающий пары из двух элементов. Его также можно вызвать с именованными аргументами: `dict(name="Анна")`. Тогда ключами будут строки с именами аргументов. Для произвольных строк, чисел и кортежей обычно удобнее литерал или последовательность пар.

```python
literal = {"a": 1, "b": 2}
pairs = dict([("a", 1), ("b", 2)])
keywords = dict(a=1, b=2)
squares = {n: n * n for n in range(5) if n % 2 == 0}
print(literal == pairs == keywords)
print(squares)
# Ожидаемый вывод:
# True
# {0: 0, 2: 4, 4: 16}
```

Включение перебирает числа от нуля до четырёх, оставляет чётные и связывает каждое с квадратом. Если правило несколько раз создаёт равные ключи, действует обычная замена значения: последняя обработанная пара побеждает. Поэтому число элементов результата может оказаться меньше числа обработанных элементов источника.

`dict.fromkeys(iterable, value)` создаёт ключи из итерируемого объекта и связывает каждый с одним и тем же значением. Если значение не передано, используется `None`. Важно различать «одно одинаковое значение» и «несколько независимо созданных объектов»: `fromkeys()` ничего не копирует для каждого ключа.

```python
shared = dict.fromkeys(["a", "b"], [])
shared["a"].append(7)
print(shared["b"])
print(shared["a"] is shared["b"])
independent = {key: [] for key in ["a", "b"]}
independent["a"].append(7)
print(independent["a"])
print(independent["b"])
# Ожидаемый вывод:
# [7]
# True
# [7]
# []
```

В первом случае обе записи ссылаются на один список: изменение через `a` видно через `b`. Во втором литерал `[]` вычисляется заново на каждой итерации включения, и списки независимы. При неизменяемом заполнителе, например `0` или `None`, общая ссылка обычно не создаёт такой проблемы: сам объект невозможно изменить на месте.

**Типовая ошибка:** создавать таблицу независимых накопителей через `dict.fromkeys(names, [])`. **Вопрос коллоквиума:** чем включение отличается от `fromkeys()`? Во включении выражение значения вычисляется для каждого элемента, а `fromkeys()` получает уже готовое одно значение и использует его для всех ключей.

При выборе способа создания полезно сначала определить, где находятся данные. Если пары уже перечислены человеком, литерал обычно наиболее прозрачен. Если готовая последовательность хранит пары, конструктор избавляет от ручного цикла. Если значения вычисляются по правилу, включение показывает правило непосредственно. Если требуется одинаковая неизменяемая начальная отметка для набора ключей, подходит `fromkeys()`. Читаемость здесь важнее попытки всегда использовать самый короткий синтаксис: подходящий способ должен объяснять происхождение ключей и значений следующему читателю программы.

## 60. Обход словаря: итерирование по ключам, методы `keys()`, `values()`, `items()`, объекты-представления (view objects)

При обычном обходе `for key in d` словарь выдаёт ключи в порядке вставки. Метод `keys()` предоставляет ключи явно, `values()` — значения, `items()` — пары `(ключ, значение)`. Последний вариант особенно удобен, когда нужны обе части записи: распаковка в заголовке цикла сразу даёт две переменные. Не требуется отдельно искать `d[key]` на каждой итерации, хотя такой код тоже возможен.

Результаты этих методов — **объекты-представления**, или views. Они не являются заранее скопированными списками. Представление связано с исходным словарём и показывает его актуальное состояние. Сам объект представления можно сохранить в переменную, а затем увидеть через него более поздние добавления или изменения словаря. Благодаря этому не нужно копировать все записи только ради доступа к ним.

```python
prices = {"хлеб": 40, "чай": 90}
print(list(prices))
print(list(prices.keys()))
print(list(prices.values()))
for name, price in prices.items():
    print(name, price)
# Ожидаемый вывод:
# ['хлеб', 'чай']
# ['хлеб', 'чай']
# [40, 90]
# хлеб 40
# чай 90
```

Все три вида обхода согласованы с порядком вставки. Значения при этом могут повторяться: `values()` не удаляет дубликаты. Пары в `items()` выдаются как двухэлементные кортежи, поэтому их удобно распаковывать. Представления не следует считать обычными последовательностями с индексированием: выражение `d.keys()[0]` не является способом получить первый ключ.

```python
d = {"a": 1}
live = d.items()
snapshot = list(d.items())
d["a"] = 9
d["b"] = 2
print(list(live))
print(snapshot)
print(sorted(d.keys() & {"b", "c"}))
# Ожидаемый вывод:
# [('a', 9), ('b', 2)]
# [('a', 1)]
# ['b']
```

`live` отражает новое состояние, а `snapshot` хранит ранее собранный список пар. Представление ключей поддерживает операции, похожие на операции множеств, поскольку ключи уникальны и хешируемы. Для представления элементов такие операции также имеют смысл, когда значения хешируемы; представление значений не становится множеством автоматически.

Снимок через `list()` является поверхностным: если значение — изменяемый список, в сохранённой паре остаётся ссылка на него, а не независимая глубокая копия. Поэтому снимок состава записей и полное копирование вложенных данных — разные задачи.

**Типовая ошибка:** считать view неизменным снимком или списком с индексами. **Вопрос коллоквиума:** почему сохранённое `keys()` видит новый ключ? Потому что это динамическое представление исходного словаря, а не копия его прежнего состояния.

## 61. Изменение размера словаря во время итерирования

Во время обхода словаря нельзя безопасно рассчитывать на произвольное добавление и удаление его ключей. Итератор хранит состояние прохода по внутренней структуре. Изменение состава записей может нарушить этот проход: возможен `RuntimeError`, а некоторые изменения могут приводить к пропуску элементов. Правильная практическая формулировка — **не менять набор ключей того же словаря, по которому идёт активная итерация**.

Нельзя сводить правило к совету «сохраните прежнюю длину, и всё будет безопасно». Удаление одного ключа и добавление другого сохраняет размер, но меняет структуру и состав словаря. Отсутствие исключения в одном опыте не превращает такой приём в надёжный алгоритм. Конкретные детали обнаружения изменений зависят от реализации и характера операций, поэтому учебный код не должен обещать универсальное поведение такого обхода.

```python
scores = {"Аня": 5, "Борис": 3}
for name in scores:
    scores[name] += 1
print(scores)
# Ожидаемый вывод:
# {'Аня': 6, 'Борис': 4}
```

Здесь меняются только значения существующих ключей. Набор ключей остаётся прежним, поэтому обычное последовательное обновление значений допустимо. Однако это не означает, что итератор создаёт снимок значений: при обходе `items()` значения берутся из текущего состояния словаря. Если алгоритму требуется именно старое состояние, его нужно сохранить отдельно до изменений.

```python
scores = {"Аня": 5, "Борис": 2, "Вера": 4}
for name in list(scores):
    if scores[name] < 3:
        del scores[name]
print(scores)
source = {"a": 1, "b": 0, "c": 2}
filtered = {key: value for key, value in source.items() if value > 0}
print(filtered)
print(len(source))
# Ожидаемый вывод:
# {'Аня': 5, 'Вера': 4}
# {'a': 1, 'c': 2}
# 3
```

Первый алгоритм обходит отдельный список ключей. Удаление из `scores` не меняет этот список, поэтому проход устойчив. Цена такого решения — дополнительная память для снимка. Второй алгоритм вообще не изменяет источник: он создаёт новый словарь, выбирая подходящие пары. Это часто понятнее, если задача сформулирована как фильтрация, а не как обязательное изменение существующего объекта.

Ещё один подход — сначала собрать ключи на удаление, затем выполнить отдельный цикл удаления. Он отделяет принятие решения от изменения структуры и хорошо читается при сложных условиях.

**Типовая ошибка:** удалять неподходящие элементы прямо из `for key in d` или чередовать удаление и добавление ради сохранения длины. **Вопрос коллоквиума:** почему обновление значения разрешено, а замена набора ключей опасна? Первое сохраняет структуру адресов обхода, второе вмешивается в сам объект, по которому движется итератор.

Отдельно различайте сам словарь и данные, которые он содержит. Например, добавление имени в список, лежащий под существующим ключом, меняет вложенный список, но не набор ключей внешнего словаря. Такой шаг не равнозначен вставке новой пары. Однако логика программы всё равно должна учитывать, какие значения уже прочитаны, а какие ещё будут обработаны. Отсутствие структурной ошибки не доказывает правильности алгоритма: если условие обработки зависит от изменяемых данных, результат может зависеть от порядка обхода. Снимок нужен именно тогда, когда требуется работать с прежним состоянием.

## 62. Чтение элементов словаря: оператор `[]`, `get()`, `setdefault()`

Оператор `d[key]` возвращает значение существующего ключа. Если ключ отсутствует, обычный словарь возбуждает `KeyError`. Такой способ уместен, когда наличие записи является обязательным условием корректной программы: исключение сигнализирует о нарушении ожидания. Метод `get(key, default)` тоже читает значение, но при отсутствии ключа возвращает заданный запасной результат; без второго аргумента это `None`.

Метод `setdefault(key, default)` сочетает чтение и возможную вставку. Если ключ уже существует, он возвращает прежнее значение и не заменяет его. Если ключа нет, метод добавляет его с переданным значением и возвращает это значение. Название не означает «всегда установить значение по умолчанию»: установка происходит только при отсутствии ключа.

```python
d = {"count": 0, "note": None}
print(d["count"])
print(d.get("missing", "нет записи"))
print(d.get("note", "запасное"))
print("missing" in d)
try:
    print(d["missing"])
except KeyError:
    print("Ключ отсутствует")
# Ожидаемый вывод:
# 0
# нет записи
# None
# False
# Ключ отсутствует
```

`get()` не изменяет словарь. Запасной результат применяется только к отсутствующему ключу: хранящееся значение `None` остаётся `None`. Поэтому `if d.get(key)` не является общей проверкой наличия записи. Оно проверяет истинность значения и не различает отсутствие, ноль, пустую строку и другие ложные результаты. Для проверки наличия служит `key in d`.

```python
groups = {}
groups.setdefault("A", []).append("Анна")
groups.setdefault("A", []).append("Артём")
print(groups)
print(groups.setdefault("A", ["другое"]))
print(groups.setdefault("B", []))
print(list(groups))
# Ожидаемый вывод:
# {'A': ['Анна', 'Артём']}
# ['Анна', 'Артём']
# []
# ['A', 'B']
```

При первом обращении создаётся список группы `A`, затем в него добавляется имя. При втором обращении возвращается уже существующий список, поэтому имена накапливаются вместе. Переданный позднее список `["другое"]` не заменяет накопленные данные. Создание `B` показывает, что `setdefault()` действительно может изменить словарь даже в выражении, внешне похожем на чтение.

Аргументы функции вычисляются до вызова. Поэтому выражение, создающее значение по умолчанию для `get()` или `setdefault()`, вычислится и при существующем ключе. Эти методы не обеспечивают ленивого вычисления дорогого результата.

**Типовая ошибка:** применять `setdefault()` как обычное присваивание или ждать от `get()` автоматического добавления пары. **Вопрос коллоквиума:** как отличить отсутствие ключа от сохранённого `None`? Проверить принадлежность ключа либо использовать отдельный уникальный объект-маркер как значение по умолчанию.

## 63. Добавление и изменение элементов: присваивание по ключу, `update()`, операторы `|` и `|=`

Присваивание `d[key] = value` добавляет новую пару либо заменяет значение существующего ключа. Одна операция охватывает оба случая, поэтому предварительно проверять наличие ключа обычно не нужно. Порядок вставки сохраняется: обновлённый ключ остаётся на прежнем месте, а новый помещается в конец. Если удалить ключ и затем вставить заново, он уже считается новой вставкой.

Метод `update()` переносит в словарь несколько пар. Он принимает отображение, итерируемый источник пар, а также именованные аргументы. При конфликте входящее значение заменяет старое. Сам метод изменяет объект на месте и возвращает `None`, поэтому присваивание `d = d.update(...)` уничтожит в переменной ссылку на нужный словарь, заменив её на `None`.

```python
d = {"a": 1, "b": 2}
d["a"] = 10
d["c"] = 3
result = d.update([("b", 20), ("d", 4)])
print(d)
print(result)
del d["a"]
d["a"] = 100
print(list(d))
# Ожидаемый вывод:
# {'a': 10, 'b': 20, 'c': 3, 'd': 4}
# None
# ['b', 'c', 'd', 'a']
```

Из вывода видно различие между заменой значения и повторной вставкой после удаления. Это полезно, например, когда порядок ключей используется для последовательного вывода настроек. Однако порядок не следует воспринимать как отдельную сортировку: новые ключи приходят в порядке обработки источника.

Оператор `|` объединяет два словаря в новый, не изменяя исходные. При конфликте побеждает правый операнд. Оператор `|=` обновляет левый словарь на месте. Эти операции доступны уже в Python 3.9, поэтому входят в базовую совместимость раздела. Для обычного `dict` форма `|` требует словари, а `|=` допускает также источник пар, подобно `update()`.

```python
base = {"theme": "light", "size": 12}
user = {"size": 16, "lang": "ru"}
merged = base | user
print(merged)
print(base)
base |= [("size", 14), ("debug", False)]
print(base)
# Ожидаемый вывод:
# {'theme': 'light', 'size': 16, 'lang': 'ru'}
# {'theme': 'light', 'size': 12}
# {'theme': 'light', 'size': 14, 'debug': False}
```

Объединение удобно для настроек: сначала базовые параметры, затем пользовательские переопределения. Но это поверхностная операция. Если оба словаря содержат вложенные словари под одним ключом, вложенные настройки не объединяются рекурсивно: правое значение целиком заменяет левое. Ссылки на остальные вложенные изменяемые объекты также не превращаются в независимые копии.

**Типовая ошибка:** ждать от `update()` нового словаря либо от `|` глубокого слияния вложенных структур. **Вопрос коллоквиума:** чем отличаются `a | b` и `a |= b`? Первое создаёт новый словарь, второе изменяет существующий левый объект, что заметно и через другие ссылки на него.

Полезно заранее решить, должны ли другие части программы увидеть обновление. Если один словарь настроек разделяют несколько объектов, изменение через присваивание по ключу, `update()` или `|=` будет общим для всех ссылок. Если требуется подготовить независимую верхнюю таблицу настроек для отдельной операции, удобнее создать результат через `|`. Но независимость верхнего словаря не распространяется автоматически на вложенные списки и словари. Такое различие между новой оболочкой и общими вложенными объектами повторяется во многих операциях копирования и объединения контейнеров.

## 64. Удаление элементов словаря: `del`, `pop()`, `popitem()`, `clear()`. Выбор способа

Удаление выбирают по тому, известен ли ключ, нужно ли получить удалённое значение и допустимо ли отсутствие записи. Инструкция `del d[key]` удаляет пару по ключу и не возвращает её значение. Если ключ отсутствует, возникает `KeyError`. Метод `pop(key)` тоже удаляет пару, но возвращает её значение. У него можно передать запасной результат: `pop(key, default)` тогда не вызывает ошибку для отсутствующего ключа.

Важно не путать запасной результат с удаляемым значением. Если ключ существует и содержит `None`, `pop()` вернёт именно `None`, даже если указан другой default. Сам запасной результат используется только при отсутствии. Если требуется строго контролировать наличие записи, отсутствие лучше не скрывать: используйте `del` либо `pop()` без default.

```python
d = {"a": 10, "b": 20, "c": 30}
del d["a"]
removed = d.pop("b")
print(removed)
print(d.pop("missing", "не найдено"))
print(d)
try:
    del d["missing"]
except KeyError:
    print("Удалять нечего")
# Ожидаемый вывод:
# 20
# не найдено
# {'c': 30}
# Удалять нечего
```

Метод `popitem()` не принимает ключ. В современном Python он удаляет и возвращает последнюю вставленную пару как кортеж. Это правило LIFO: последним пришёл — первым ушёл. Для словаря это гарантированное поведение, в отличие от `set.pop()`, который выбирает произвольный элемент. Если словарь пуст, `popitem()` возбуждает `KeyError`.

```python
d = {"first": 1, "second": 2}
d["first"] = 100
print(d.popitem())
print(d)
alias = d
d.clear()
print(d)
print(alias)
try:
    d.popitem()
except KeyError:
    print("Словарь пуст")
# Ожидаемый вывод:
# ('second', 2)
# {'first': 100}
# {}
# {}
# Словарь пуст
```

Обновление `first` не делает его последней вставленной записью, поэтому извлекается `second`. `clear()` удаляет все пары из существующего объекта и возвращает `None`. Переменная `alias` ссылается на тот же словарь, поэтому тоже видит пустое состояние. Присваивание `d = {}` имело бы другой смысл: переменная `d` получила бы новый объект, а прежний словарь сохранился бы через `alias`.

Практический выбор прост: `del` — удалить обязательную запись; `pop` — удалить и использовать значение; `popitem` — последовательно разбирать словарь с конца порядка вставки; `clear` — очистить всё, сохранив сам объект. Удаление не обязательно уничтожает объект-значение: если на него остались другие ссылки, он продолжает существовать.

**Типовая ошибка:** считать `popitem()` случайным выбором либо путать очистку объекта с переназначением переменной. **Вопрос коллоквиума:** почему `clear()` видно через другую ссылку? Потому что изменён общий объект, а не только имя, которым его обозначили.

<a id="topic-65"></a>

## 65. Оператор `in` для словарей. Производительность поиска в словаре и в списке

Выражение `x in d` проверяет наличие **ключа**, а не значения и не произвольной части пары. Это один из самых важных смысловых ориентиров при чтении кода со словарями. Для поиска среди значений пишут `x in d.values()`, а для проверки пары — `(key, value) in d.items()`. Отрицательная форма `not in` выражает отсутствие и обычно читается естественнее, чем отрицание всего выражения через `not`.

Проверка ключа использует хеш-таблицу. При обычных предположениях о хешировании средняя стоимость поиска, вставки и удаления близка к O(1), то есть не растёт линейно с числом записей. Это не обещание одинакового числа наносекунд и не абсолютная гарантия для всех входных данных: вычисление хеша и сравнение самих объектов тоже имеют стоимость.

```python
codes = {"ru": "Россия", "fr": "Франция"}
print("ru" in codes)
print("Россия" in codes)
print("Россия" in codes.values())
print(("ru", "Россия") in codes.items())
print("de" not in codes)
# Ожидаемый вывод:
# True
# False
# True
# True
# True
```

Список обычно ищет последовательно: сравнивает искомое значение с первым элементом, затем со вторым и так далее. Если подходящий элемент стоит первым, достаточно одной проверки. Если его нет или он стоит в конце, потребуется пройти почти весь список. Поэтому для списка поиск имеет O(n) в худшем случае, а при обычном распределении успешных запросов — тоже линейную среднюю стоимость.

```python
names = ["Анна", "Борис", "Вера", "Анна"]
index = dict.fromkeys(names)
for query in ["Вера", "Глеб"]:
    print(query, query in names, query in index)
print(len(names), len(index))
# Ожидаемый вывод:
# Вера True True
# Глеб False False
# 4 3
```

Построение индекса само требует времени и дополнительной памяти, а повторяющиеся имена становятся одним ключом. Для единственного поиска в небольшом списке создавать словарь может быть бессмысленно. Для большого числа запросов индекс часто окупается. Если значения вообще не нужны, для проверки принадлежности обычно естественнее множество.

В худшем случае, например при большом числе коллизий, поиск в словаре способен деградировать до O(n). Средняя O(1) — характеристика модели и типичных условий, а не запрет на плохой случай. Поиск в `values()` не получает преимущества ключевого индекса и обычно требует последовательного просмотра значений. Не следует доказывать асимптотику одним случайным замером: время зависит от размера, данных, реализации и условий запуска.

**Типовая ошибка:** писать `name in d`, желая найти имя среди значений. **Вопрос коллоквиума:** почему словарь обычно быстрее списка при повторных проверках ключей? Хеширование сокращает область поиска, тогда как список не имеет подобного индекса.

Оценки сложности всегда сопровождают указанием того, что считается элементарной операцией. Для небольших целых чисел вычисление хеша и сравнение обычно рассматривают как постоянные действия. Если ключом служит большой составной объект или объект с пользовательскими методами, собственная работа этих методов может быть существенной. Кроме того, словарь платит дополнительной памятью за организацию быстрого доступа. Поэтому правильный ответ на вопрос о производительности включает и преимущество средней стоимости поиска, и ограничения этой оценки, и расходы на подготовку структуры, а не только короткое утверждение «словарь быстрее».

## 66. Множество: определение, характеристики, области применения

**Множество**, или `set`, — изменяемая коллекция уникальных хешируемых элементов. В отличие от словаря здесь нет отдельного значения, связанного с ключом: хранится сам факт присутствия элемента. Повторное добавление равного элемента не увеличивает размер. Проверка равенства и хеширование согласованы так же, как для ключей словаря, поэтому `True`, `1` и `1.0` не образуют три независимых элемента.

Множество не является последовательностью. У него нет заданного порядка вставки как у словаря и нет позиционного индексирования. Оно может печататься в некотором порядке, но использовать этот порядок как часть алгоритма нельзя. Даже если в нескольких запусках результат выглядит одинаково, это не становится договором языка. Для предсказуемого вывода однородных сравнимых элементов удобно применять `sorted()`.

```python
colors = {"синий", "красный", "синий"}
print(len(colors))
print(sorted(colors))
print("синий" in colors)
print(len({True, 1, 1.0}))
# Ожидаемый вывод:
# 2
# ['красный', 'синий']
# True
# 1
```

Первый повтор исчезает, потому что множество хранит уникальные значения, а не историю их появления. Такая дедупликация полезна, если порядок и количество повторов не нужны. Но когда требуется сохранить частоты, множество недостаточно: нужен, например, словарь счётчиков. Когда требуется исходный порядок первых появлений, можно воспользоваться ключами словаря, а не надеяться на порядок `set`.

```python
visitors = ["Анна", "Борис", "Анна", "Вера", "Борис"]
unique = set(visitors)
print(len(visitors))
print(len(unique))
print(sorted(unique))
required = {"логин", "пароль"}
received = {"логин", "почта"}
print(sorted(required - received))
# Ожидаемый вывод:
# 5
# 3
# ['Анна', 'Борис', 'Вера']
# ['пароль']
```

Здесь множество решает две разные задачи: подсчитывает число различных посетителей и находит недостающие поля формы. Во второй задаче математическая операция разности читается почти как формулировка требования: взять обязательные поля, отсутствующие среди полученных. Аналогично можно находить общие интересы, совпадающие идентификаторы и новые записи.

Операции добавления, удаления и проверки принадлежности обычно имеют среднюю O(1), но возможна худшая O(n) при неблагоприятных коллизиях. Сам `set` нехешируем, поэтому его нельзя сделать ключом словаря или элементом другого обычного множества. Для неизменяемой группы элементов существует `frozenset`.

**Типовая ошибка:** использовать множество как список без повторов, одновременно ожидая сохранения позиций. **Вопрос коллоквиума:** что теряется при преобразовании списка в множество? Повторы, сведения об их количестве и исходный последовательный порядок; сами уникальные элементы остаются.

## 67. Создание множеств: литерал, пустое множество, `set()`, включения

Непустое множество можно записать литералом с фигурными скобками и элементами через запятую: `{1, 2, 3}`. Двоеточий в такой записи нет. Пустое множество создают как `set()`, потому что `{}` уже означает пустой словарь. Это небольшое синтаксическое исключение важно запомнить: после `values = {}` метод `values.add(...)` работать не будет, поскольку объект оказался словарём.

Конструктор `set(iterable)` перебирает источник и добавляет его элементы, удаляя повторы по правилам равенства и хеширования. Он принимает список, кортеж, строку, генератор и другие итерируемые объекты. Строка даёт отдельные символы, а словарь при обычном переборе даёт ключи. Поэтому смысл преобразования определяется тем, что именно выдаёт источник при итерации.

```python
empty_dict = {}
empty_set = set()
letters = set("мама")
keys = set({"a": 10, "b": 20})
print(type(empty_dict).__name__)
print(type(empty_set).__name__)
print(sorted(letters))
print(sorted(keys))
# Ожидаемый вывод:
# dict
# set
# ['а', 'м']
# ['a', 'b']
```

Строка `мама` содержит четыре символа, но разных букв только две. Словарь в последнем выражении не отдаёт ни значения `10` и `20`, ни пары: без явного вызова метода он перебирается по ключам. Для множества значений потребовалось бы передать `d.values()`, причём сами значения должны быть хешируемыми.

**Множественное включение** имеет форму `{выражение for элемент in источник if условие}`. Оно вычисляет выражение для отобранных элементов и собирает уникальные результаты. Повторы могут возникнуть не только в источнике, но и после преобразования: разные входные значения способны дать один итоговый элемент.

```python
remainders = {n % 3 for n in range(8)}
even_squares = {n * n for n in range(6) if n % 2 == 0}
print(sorted(remainders))
print(sorted(even_squares))
try:
    points = set([[1, 2], [3, 4]])
except TypeError:
    print("Нужны хешируемые элементы")
points = {(1, 2), (3, 4)}
print(sorted(points))
# Ожидаемый вывод:
# [0, 1, 2]
# [0, 4, 16]
# Нужны хешируемые элементы
# [(1, 2), (3, 4)]
```

Восемь исходных чисел дают всего три возможных остатка. Пары координат в форме списков непригодны для множества, но кортежи из целых чисел подходят. Само преобразование внешнего списка через `set()` не превращает вложенные списки в хешируемые объекты: элементы не переписываются автоматически.

**Типовая ошибка:** записывать `{}` для пустого множества или думать, что `set("кот")` создаёт множество с одной строкой. Для одного строкового элемента нужен литерал `{"кот"}`. **Вопрос коллоквиума:** почему число элементов включения иногда меньше числа проходов цикла? Потому что равные результаты сливаются в один элемент множества.

Включение вычисляет выражение результата до того, как множество решит, встречался ли равный элемент раньше. Следовательно, повторные результаты всё равно могут потребовать повторных вычислений. Если само вычисление дорогое, удаление дубликатов на выходе не обязательно экономит эту работу. Также включение следует применять для построения значений, а не для скрытых побочных действий. Новичку полезно сначала мысленно развернуть его в обычный цикл: создать пустое множество, перебрать источник, проверить условие и добавить вычисленный элемент. Такая модель помогает правильно прочитать даже вложенное выражение.

## 68. Добавление элементов в множество и проверка принадлежности: `add()`, `update()`, `in`

Метод `add(element)` добавляет **один** хешируемый элемент. Если равный элемент уже есть, множество остаётся прежним. Это делает добавление идемпотентным по содержимому: повторение одного и того же добавления не накапливает копии. Метод изменяет существующее множество и возвращает `None`, поэтому его результат обычно не присваивают переменной, в которой хранят множество.

Метод `update(iterable, ...)` добавляет элементы из одного или нескольких итерируемых источников. Главное различие с `add()` — не количество символов в записи, а уровень обработки: `add()` рассматривает аргумент как один объект, `update()` перебирает аргумент и добавляет то, что он выдаёт. Каждый реально добавляемый элемент должен быть хешируемым.

```python
names = {"Анна"}
print(names.add("Борис"))
names.add("Анна")
names.update(["Вера", "Борис"], ("Глеб",))
print(sorted(names))
print("Вера" in names)
print("Дина" not in names)
# Ожидаемый вывод:
# None
# ['Анна', 'Борис', 'Вера', 'Глеб']
# True
# True
```

При обновлении повтор `Борис` не увеличивает размер. Проверка `in` не меняет множество и возвращает логическое значение. Как и у словарей, средняя стоимость такой проверки обычно O(1), а в худшем случае возможна O(n). Это не зависит от того, записан ли оператор в условии `if` или передан в `print`: смысл операции одинаков.

```python
whole = set()
whole.add("кот")
letters = set()
letters.update("кот")
print(sorted(whole))
print(sorted(letters))
try:
    whole.add([1, 2])
except TypeError:
    print("Список нельзя добавить как элемент")
whole.update([1, 2])
print(1 in whole, 2 in whole)
# Ожидаемый вывод:
# ['кот']
# ['к', 'о', 'т']
# Список нельзя добавить как элемент
# True True
```

В первом случае строка стала одним элементом, во втором — источником отдельных букв. Список `[1, 2]` нельзя добавить целиком, но можно перебрать и добавить содержащиеся в нём целые числа. Множество `whole` после этого содержит объекты разных типов; это допустимо, однако сортировать вместе строки и числа стандартным сравнением нельзя. Поэтому последний вывод проверяет принадлежность, не пытаясь сортировать неоднородное множество.

Если требуется добавить пару координат как единое значение, можно передать кортеж в `add()`. Если этот же кортеж передать в `update()`, добавятся отдельные координаты. Выбор метода должен соответствовать модели данных, а не только отсутствию исключения.

**Типовая ошибка:** заменять `add()` на `update()` без учёта перебора аргумента либо писать `s = s.add(x)`. **Вопрос коллоквиума:** почему список разрешён как аргумент `update()`, но не как добавляемый элемент? Источник обязан быть итерируемым, а каждый сохраняемый элемент — хешируемым; это разные требования.

## 69. Удаление элементов из множества: `remove()`, `discard()`, `pop()`, `clear()`. Выбор способа

Метод `remove(element)` удаляет указанный элемент и возбуждает `KeyError`, если его нет. Метод `discard(element)` тоже удаляет указанный элемент, но отсутствие считает нормальной ситуацией и не вызывает такое исключение. Оба метода изменяют множество на месте и возвращают `None`. Их выбирают не по скорости чтения имени, а по смыслу требования: отсутствие должно считаться ошибкой или допускается.

Такое различие полезно в реальной программе. Если активный пользователь обязан находиться в наборе подключённых пользователей, `remove()` помогает заметить нарушение логики. Если требуется просто обеспечить отсутствие временной метки независимо от прежнего состояния, `discard()` делает намерение яснее и избавляет от отдельной проверки принадлежности.

```python
active = {"Анна", "Борис"}
active.remove("Анна")
active.discard("Вера")
print(sorted(active))
try:
    active.remove("Вера")
except KeyError:
    print("Элемент отсутствует")
print(active.discard("Вера"))
# Ожидаемый вывод:
# ['Борис']
# Элемент отсутствует
# None
```

Метод `pop()` удаляет и возвращает **произвольный** элемент. Это не обещание случайного выбора с равномерным распределением и не извлечение «первого» по вставке. У множества вообще нет такого публичного порядка. Поэтому пример не должен обещать конкретное извлечённое значение. Проверять можно инварианты: элемент принадлежал исходному набору, исчез из оставшегося, а размер уменьшился на единицу.

```python
s = {10, 20, 30}
before = s.copy()
item = s.pop()
print(item in before)
print(item not in s)
print(len(s))
print(s | {item} == before)
s.clear()
print(len(s))
try:
    s.pop()
except KeyError:
    print("Множество пусто")
# Ожидаемый вывод:
# True
# True
# 2
# True
# 0
# Множество пусто
```

`copy()` создаёт отдельное множество с прежним составом. Оно позволяет проверить результат без предположения о выбранном элементе. Объединение оставшегося множества с извлечённым элементом восстанавливает исходное содержимое. `clear()` затем удаляет всё, сохраняя сам объект множества. На пустом множестве `pop()` возбуждает `KeyError`, потому что возвращать нечего.

Если нужно извлечь минимальный элемент по значению, следует явно найти его через `min(s)` и затем удалить, предварительно предусмотрев пустой набор. Подмена этой задачи вызовом `pop()` некорректна, даже если на маленьких числах наблюдаемый результат кажется подходящим.

**Типовая ошибка:** ожидать от `set.pop()` конкретного значения или называть его генератором случайного выбора. **Вопрос коллоквиума:** чем `remove()` отличается от `discard()`? Поведением при отсутствии элемента, а не тем, сколько элементов удаляется: в обоих случаях речь об одном указанном элементе.

## 70. Операции теории множеств: объединение, пересечение, разность, симметрическая разность. Операторная и методная формы, их отличия

**Объединение** `A | B` содержит элементы, находящиеся хотя бы в одном из множеств. **Пересечение** `A & B` содержит общие элементы. **Разность** `A - B` оставляет элементы `A`, которых нет в `B`. **Симметрическая разность** `A ^ B` содержит элементы, находящиеся ровно в одном из двух множеств. Эти четыре операции создают новый результат и сами по себе не изменяют исходные множества.

Объединение, пересечение и симметрическая разность симметричны относительно перестановки двух операндов. Разность направлена: обычно `A - B` и `B - A` различаются. Удобно переводить выражение на обычный язык. Например, «посетили лекцию, но не практику» — это разность, а «посетили только одно из двух занятий» — симметрическая разность.

```python
a = {1, 2, 3}
b = {3, 4}
print(sorted(a | b))
print(sorted(a & b))
print(sorted(a - b))
print(sorted(b - a))
print(sorted(a ^ b))
print(sorted(a))
# Ожидаемый вывод:
# [1, 2, 3, 4]
# [3]
# [1, 2]
# [4]
# [1, 2, 4]
# [1, 2, 3]
```

Методные аналоги — `union()`, `intersection()`, `difference()` и `symmetric_difference()`. Важное различие: методы принимают произвольные итерируемые источники, тогда как операторы требуют множественные операнды `set` или `frozenset`. Поэтому `a.intersection([2, 3])` допустимо, а `a & [2, 3]` — нет. Источник всё равно должен содержать подходящие для множества элементы.

```python
a = {1, 2, 3}
print(sorted(a.union([3, 4])))
print(sorted(a.intersection([2, 3, 5])))
print(sorted(a.difference([1, 3])))
print(sorted(a.symmetric_difference([3, 4])))
try:
    result = a & [2, 3]
except TypeError:
    print("Оператору нужен множественный операнд")
a.intersection_update([2, 3, 5])
print(sorted(a))
a |= {4}
print(sorted(a))
# Ожидаемый вывод:
# [1, 2, 3, 4]
# [2, 3]
# [2]
# [1, 2, 4]
# Оператору нужен множественный операнд
# [2, 3]
# [2, 3, 4]
```

Для изменения на месте существуют `update()`, `intersection_update()`, `difference_update()`, `symmetric_difference_update()` и операторы `|=`, `&=`, `-=`, `^=`. Обновляющие методы возвращают `None`. Для обычного `set` обновляющие операторы также требуют множественные операнды; гибкость при работе с произвольным iterable дают методы. Методы объединения, пересечения и разности могут принимать несколько источников, а `symmetric_difference()` принимает один.

По сложности операции нельзя безоговорочно объявлять постоянными: нужно обработать элементы. В типичных условиях пересечение двух множеств ориентируется на размер меньшего, объединение — на суммарный размер. Коллизии и стоимость хеша могут ухудшать реальные оценки.

**Типовая ошибка:** путать разность с симметрической разностью или считать методную и операторную формы полностью одинаковыми по принимаемым типам. **Вопрос коллоквиума:** как найти общие элементы множества и списка без ручного преобразования списка? Вызвать `intersection()` с этим списком.

В сложных выражениях лучше явно расставлять скобки, чтобы математическое намерение не терялось среди правил приоритета. Например, задачу «объединить две группы и затем исключить заблокированных» следует записывать с видимым выделением объединения. Это особенно полезно, когда рядом находятся разность и пересечение: внешне похожие формулы могут описывать разные выборки. При объяснении результата на коллоквиуме удобно назвать судьбу каждого типа элементов: присутствующих только слева, только справа и в обоих наборах. Такой разбор показывает понимание операции лучше, чем механическое перечисление названий методов.

## 71. Подмножество и надмножество: операторы и методы, строгие и нестрогие сравнения, частичный порядок

Множество `A` является **подмножеством** `B`, если каждый элемент `A` принадлежит `B`. Запись `A <= B` допускает равенство множеств. Запись `A < B` означает строгое подмножество: включение выполняется, но множества не равны. Для надмножества направления обратные: `A >= B` и `A > B`. Символы напоминают сравнение чисел, но здесь речь о включении элементов, а не о размере или алфавитном порядке.

Методы `issubset()` и `issuperset()` проверяют нестрогие отношения. Они принимают итерируемые объекты, поэтому аргументом может быть список или строка. Соответствующие операторы требуют множественные операнды. Отдельного метода строгого включения нет: можно совместить проверку включения с неравенством либо использовать оператор после подходящего преобразования аргумента.

```python
a = {1, 2}
b = {1, 2, 3}
print(a <= b)
print(a < b)
print(a <= a)
print(a < a)
print(b >= a)
print(a.issubset([1, 2, 3]))
print(b.issuperset([2, 3]))
# Ожидаемый вывод:
# True
# True
# True
# False
# True
# True
# True
```

Нестрогое включение рефлексивно: любое множество является подмножеством самого себя. Строгое включение это исключает. Пустое множество является подмножеством любого множества, потому что в нём нет элемента, нарушающего условие. Это не специальная поблажка Python, а обычное математическое определение включения.

**Частичный порядок** означает, что некоторые пары множеств несравнимы по включению. У чисел обычно можно определить, какое меньше, больше или равно другому. У множеств возможна четвёртая ситуация: они различны, но ни одно не содержит другое. Поэтому сравнение размеров не заменяет сравнение состава.

```python
a = {1, 2}
b = {2, 3}
print(a == b)
print(a < b)
print(a > b)
print(a <= b)
print(b <= a)
print(set() <= a)
print(a.isdisjoint({3, 4}))
print(a.isdisjoint(b))
# Ожидаемый вывод:
# False
# False
# False
# False
# False
# True
# True
# False
```

У `a` есть элемент `1`, отсутствующий в `b`, а у `b` есть `3`, отсутствующий в `a`. Поэтому включение не выполняется ни в одну сторону, хотя размеры равны. Метод `isdisjoint()` проверяет другое свойство — отсутствие общих элементов. Несравнимость не означает непересечение: наши `a` и `b` несравнимы, но имеют общий элемент `2`.

Практический пример включения — проверка разрешений: требуемые права должны быть подмножеством имеющихся. Для сортировки набора множеств по количеству элементов нужно явно использовать ключ `len`, а не ожидать от сравнения включения полного линейного порядка.

**Типовая ошибка:** читать `a < b` как «в `a` меньше элементов» либо считать, что ложность `<`, `>` и `==` одновременно невозможна. **Вопрос коллоквиума:** почему порядок частичный? Потому что отношение включения не делает сравнимыми все пары множеств.

Для проверки прав пользователя строгое включение обычно не подходит: если имеющиеся права в точности совпадают с требуемыми, доступ всё равно должен быть разрешён. Поэтому в подобных задачах естественно нестрогое отношение. Строгое включение полезно, когда нужно установить наличие хотя бы одного дополнительного элемента сверх обязательных. Прежде чем выбирать знак сравнения, сформулируйте словами, должно ли равенство считаться успешным случаем. Затем отдельно проверьте пустые наборы: это простой способ обнаружить неверно выбранное направление включения или случайно использованную строгость условия.

## 72. Замороженные множества (`frozenset`): отличия от `set`, применение, операции

**Замороженное множество**, или `frozenset`, хранит уникальные хешируемые элементы, как `set`, но не позволяет изменять свой состав. Его создают конструктором `frozenset(iterable)`; пустой вариант — `frozenset()`. Отдельного литерала нет. Неизменяемость означает отсутствие методов добавления и удаления, а не запрет вычислять новые множества из старого.

Главное практическое отличие — сам `frozenset` хешируем. Поэтому его можно использовать как ключ словаря и как элемент другого множества. Обычный `set` для этих ролей не подходит. Это удобно, когда сущность определяется неупорядоченным набором участников: например, пара городов без направления маршрута, группа прав доступа или комбинация признаков.

```python
route = frozenset(["Казань", "Самара"])
prices = {route: 900}
reverse = frozenset(["Самара", "Казань"])
print(route == reverse)
print(hash(route) == hash(reverse))
print(prices[reverse])
groups = {frozenset({1, 2}), frozenset({2, 1})}
print(len(groups))
# Ожидаемый вывод:
# True
# True
# 900
# 1
```

Порядок входных городов не влияет на равенство ключей. Равные замороженные множества имеют одинаковые хеши, поэтому поиск по заново созданному равному ключу работает. Конкретный хеш не печатается: он не обязан совпадать между отдельными запусками. Хешируемость также не означает уникальности хеша или криптографической защиты.

`frozenset` поддерживает чтение, принадлежность, длину, сравнения включения, объединение, пересечение, разность и симметрическую разность. Эти операции возвращают новый результат. Для бинарных операций со смешанными `set` и `frozenset` тип результата определяется левым операндом. Поэтому содержимое может быть одинаковым, а изменяемость результата — различаться.

```python
frozen = frozenset({1, 2})
regular = {2, 3}
left = frozen | regular
right = regular | frozen
print(sorted(left))
print(type(left).__name__)
print(type(right).__name__)
try:
    frozen.add(4)
except AttributeError:
    print("Метода add нет")
alias = frozen
frozen |= {4}
print(sorted(frozen))
print(sorted(alias))
# Ожидаемый вывод:
# [1, 2, 3]
# frozenset
# set
# Метода add нет
# [1, 2, 4]
# [1, 2]
```

Последние строки показывают тонкость составного присваивания. Запись `frozen |= {4}` допустима, но не меняет старое замороженное множество: вычисляется новый результат, и имя `frozen` начинает ссылаться на него. Переменная `alias` по-прежнему указывает на исходный объект. Таким образом, изменение привязки имени не противоречит неизменяемости объекта.

Элементы внутри `frozenset` тоже должны быть хешируемыми: упаковка списка в замороженное множество не делает список подходящим элементом. Если требуется представить множество множеств, внутренние группы обычно превращают в `frozenset`, а внешний контейнер выбирают по необходимости дальнейших изменений.

**Типовая ошибка:** считать, что неизменяемый объект нельзя объединять с другим, либо что `|=` непременно меняет объект на месте для любого типа. **Вопрос коллоквиума:** зачем нужен `frozenset`, если уже есть `set`? Для неизменяемых неупорядоченных наборов, особенно когда сам набор должен стать хешируемым ключом или элементом другого множества.
